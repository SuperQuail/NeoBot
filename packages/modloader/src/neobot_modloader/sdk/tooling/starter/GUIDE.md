# 编写插件使用说明

先修改 `__init__.py` 中已有的 `plugin.guide(...)`。它已经覆盖打开表单、填写、核对、模拟保存、生效说明和真实命令样例，不必从空白设计播放流程。

## 当前工程的目标

| 目标 | 用途 |
| --- | --- |
| `config` | 展示完整配置表单或模拟保存位置 |
| `config.greeting` | 高亮“回复内容”字段；命令样例也引用这个相关字段 |

新增内容后，目标按下列规则扩展：

| 声明 | 教程目标 |
| --- | --- |
| `Config` 新增 `interval` 字段 | `config.interval` |
| 嵌套配置 `delivery.enabled` | `config.delivery.enabled` |
| `plugin.action("status", ...)` | `action.status` |
| `plugin.resource("items", ...)` | `resource.items` |
| 页面 `tasks` 注册锚点 `new` | `view.tasks.new` |

以导出的 `plugin.contract.json` 为准。目标必须真实存在；教程不会根据动作声明生成真实业务按钮，也不会注册聊天命令。

## 改写已有步骤

1. `chapter` 写使用者要完成的事情，例如“填写检查间隔”；`text` 写位置、输入和预期结果。
2. `target` 选择上面的稳定目标，字段显示名称改了也不必改变 ID。
3. 配置步骤的 `form` 可用 `start/edit/validate/save/saved`。`validate` 只演示样例数值范围，真实保存仍由服务端完整校验。
4. 每步 `example` 填写完整独立快照，不能只写与上一步的差异；缺省值只取公开默认值或空值，凭据留空。
5. 聊天步骤用 `command={"text": "/命令 参数", "context": "在哪个聊天、需要什么权限", "reply": "合成回复样例"}`，不能与 `form` 混用。命令名仍应提示用户从 `/help` 核对。
6. 自定义页面的 `onGuideStep` 同样要重建全部样例状态；`demo.actions` 显式提供需要的动作结果，缺少样例的动作会失败。

完成后执行 README 的 `export` 和验收，再打开隔离面板，逐项检查：

- 从第一步能看懂入口、所需条件和预期结果。
- 打开“目录与全文”能找到各章、说明和命令。
- 后退、跳章、重播与切换说明时，样例状态正确。
- 说明中不出现真实配置或用户数据，不执行真实写入。
- 返回配置后仍保留原草稿；明确说明哪些设置需要重载或重启。

增加数值约束时，可添加一个不合法的数值快照，再增加修正步骤，让使用者看到错误和恢复过程。复杂页面的完整示例位于 NeoBot 的 `streaming_parser` 插件；先采用这里的配置教程，确有业务需要时再扩展。
