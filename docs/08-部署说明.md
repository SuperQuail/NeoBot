# 08 部署说明

本文面向**部署使用者**：从零安装 NeoBot、完成最小配置，并在 OneBot 端（以 [NapCat](https://github.com/NapNeko/NapCatQQ) 为例）配置**反向 WebSocket**，把 QQ 接进来。

> 开发环境搭建与代码贡献流程见 [06-开发指南](./06-开发指南.md)；全部配置项见 [05-配置参考](./05-配置参考.md)。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| Python | 3.13 或更高（用 uv 安装时会自动准备） |
| 操作系统 | Windows / Linux / macOS |
| OneBot 实现 | 任意 OneBot v11 实现；本文以 [NapCat](https://github.com/NapNeko/NapCatQQ) 为例 |
| 模型 API | 至少一个平台密钥（DeepSeek / OpenAI / Anthropic / 硅基流动等） |

安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)（推荐，用于创建独立环境并管理依赖）：

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```bash
# Linux / macOS
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## 2. 安装 NeoBot

### 方式 A：uv 安装（推荐）

用 uv 建一个独立环境再装核心包，避免污染系统 Python：

```bash
uv venv --python 3.13

# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

# 只装核心包，其余 neobot-* 组件会作为依赖自动安装
uv pip install neobot-app

neobot --help
```

也可以直接作为全局命令安装（不进入虚拟环境）：

```bash
uv tool install neobot-app
neobot --help
```

### 方式 B：pip 安装核心包

只用 pip 时**装核心包 `neobot-app` 即可**，`neobot-adapter` / `neobot-chat` / `neobot-contracts` / `neobot-memory` / `neobot-modloader` / `neobot-storage` 会自动作为依赖装上：

```bash
python -m venv neobot-env

# Windows
neobot-env\Scripts\activate
# Linux / macOS
source neobot-env/bin/activate

pip install neobot-app
neobot --help
```

> PyPI 上的发行版可能略落后于 GitHub 源码；想用最新功能请用方式 C。

### 方式 C：GitHub 源码（uv workspace，最新版）

```bash
git clone https://github.com/SuperQuail/NeoBot.git
cd NeoBot

# 安装 app + packages/* 全部工作区依赖
uv sync --all-packages

# 运行
uv run neobot
```

## 3. 首次启动与最小配置

第一次运行 `neobot` 会在**数据目录**里自动生成 `config.toml` 与 `.env`，然后提示你补全配置。

### 3.1 数据目录

| 安装方式 | 默认数据目录 |
|---|---|
| 源码（方式 C） | `<仓库根目录>/app/data` |
| uv / pip 安装（方式 A、B） | `<运行 neobot 时的当前目录>/app/data` |

生产部署建议用环境变量固定数据目录，避免换目录启动后"配置丢失"：

```powershell
# Windows PowerShell（当前会话）
$env:NEOBOT_DATA_DIR = "D:\NeoBotData"

# 永久写入用户环境变量
setx NEOBOT_DATA_DIR "D:\NeoBotData"
```

```bash
# Linux / macOS
export NEOBOT_DATA_DIR=/opt/neobot/data
```

数据目录主要内容：

| 路径 | 说明 |
|---|---|
| `config.toml` | 主配置（机器人、聊天、模型、Agent、适配器等） |
| `.env` | 平台密钥等敏感信息 |
| `logs/` | 运行日志 |
| `plugins_data/` | 插件数据目录；网页面板的访问令牌写在 `plugins_data/dashboard/access_token.txt` |
| `config_backup/` | 配置自动备份 |

### 3.2 填写 `.env`

按平台填写地址与密钥，键名规则是 `<平台名>_URL` / `<平台名>_APIKey`，平台名与 `config.toml` 中模型注册项的 `provider` 一致。例如：

```dotenv
# DeepSeek
DeepSeek_URL=https://api.deepseek.com
DeepSeek_APIKey=sk-xxxxxxxxxxxxxxxx

# 硅基流动（视觉模型 / TTS 常用）
硅基流动_URL=https://api.siliconflow.cn/v1
硅基流动_APIKey=sk-xxxxxxxxxxxxxxxx
```

缺少必需项时启动会直接失败并列出缺失的变量名，按提示补齐即可。

### 3.3 修改 `config.toml`

最小改动：

```toml
[bot]
account = 123456789        # 机器人 QQ 号
nick_name = "Neo Bot"      # 机器人昵称

[adapter]
mode = "onebot"            # 默认值；local 为本地调试适配器
reverse_ws_host = ""       # 留空 => 0.0.0.0（监听所有网卡）
reverse_ws_port = 0        # 0 => 8080
```

也就是说：**NeoBot 默认在本机 `0.0.0.0:8080` 上开启 WebSocket 服务端，等待 OneBot 框架连过来**（即"反向 WebSocket"）。端口也可用环境变量覆盖：`NEO_BOT_ADAPTER_HOST` / `NEO_BOT_ADAPTER_PORT`。

模型相关配置（`[models.*]` / `[agent_model]`）一般保持默认即可；主模型不可用或无法处理图片时，NeoBot 会自动回退到 `vision_model`。

## 4. 在 NapCat 配置反向 WebSocket

NapCat 仓库：<https://github.com/NapNeko/NapCatQQ>
NapCat 文档：<https://napneko.github.io/>（WebUI 配置见 <https://napneko.github.io/config/basic>）

### 4.1 先启动 NeoBot

```bash
neobot            # uv / pip 安装
uv run neobot     # 源码方式
```

启动日志里应能看到：

```text
反向 WebSocket 服务运行于 ws://0.0.0.0:8080
```

> NeoBot 启动后会等待 OneBot 连接，**30 秒内没有连接会退出**并提示"连接超时"。所以先把 NeoBot 跑起来，再去 NapCat 配反向 WS 即可；配好后重启 NeoBot 或等它自动重连。

### 4.2 NapCat 侧配置

1. 安装并启动 NapCat，扫码登录机器人 QQ。
2. 打开 NapCat WebUI：`http://127.0.0.1:6099/webui`（登录 token 在启动日志的 `WebUi User Panel Url` 里，或查看 `webui.json`）。
3. 进入 **网络配置 → 新建**，网络类型选择 **WebSocket 客户端**（NapCat 文档里也称为"反向 WS"）。
4. URL 填 NeoBot 的地址与端口：

   | 部署情况 | 填写的 URL |
   |---|---|
   | NapCat 与 NeoBot 同机 | `ws://127.0.0.1:8080/onebot` |
   | 不同机器 | `ws://<NeoBot 所在主机 IP>:8080/onebot` |

   > 路径 `/onebot` 是 OneBot 惯例写法，NeoBot 不校验路径，填别的路径也能连上。
5. Token **留空**（NeoBot 当前不校验反向 WS 的 token）；若需跨公网，请自行用防火墙/内网/隧道限制来源，不要把 8080 直接暴露到公网。
6. 勾选「保存时启用」，保存。
7. 回到 NeoBot 日志，出现下面这行即接入成功：

   ```text
   框架已连接
   ```

### 4.3 验证

- 用另一个 QQ 私聊机器人，或把机器人拉进群后 @ 它，应能收到回复。
- 网页面板：本机 `http://127.0.0.1:9981/`，跨机 `http://<服务器IP>:9981/`（默认对网络开放）。登录时粘贴**访问令牌**：取 `config.toml` 的 `[dashboard].access_token`，留空则由 NeoBot 自动生成并写入数据目录 `plugins_data/dashboard/access_token.txt`，同时打印在启动日志里。
- 只想本机访问可把 `[dashboard].host` 改为 `127.0.0.1`；端口被占用时面板最多向后尝试 10 个端口，实际端口见启动日志告警。

## 5. 反向连接排错

| 现象 | 原因与处理 |
|---|---|
| NeoBot 提示"连接超时，请确保 OneBot 框架已启动并配置了反向 WebSocket 连接" | NapCat 未启用「WebSocket 客户端」；URL/端口写错；或跨机时防火墙未放行 8080 |
| NapCat 里连接一直失败/断开 | 确认 NeoBot 正在运行（它是 WS 服务端）；确认端口与 `reverse_ws_port` / `NEO_BOT_ADAPTER_PORT` 一致 |
| 端口被占用 | 改 `reverse_ws_port`（或环境变量），NapCat 的 URL 同步修改 |
| 能连上但不回复 | 看启动日志是否有「当前主回复模型不可用」，检查 `.env` 的 `_URL` / `_APIKey` |
| 外网访问网页面板失败 | 放行系统/云防火墙中的实际面板端口（占用时最多向后尝试 10 个，见启动日志告警）；Windows 可执行 `neobot firewall-open`（需管理员） |

## 6. CLI 速查

```bash
neobot                      # 启动机器人（首次运行会生成配置）
neobot init                 # 重新扫描模型库等可再生资源索引，不启动 Bot
neobot install-browser      # 下载内嵌 Chromium（浏览器工具需要）
neobot open_web [URL]       # 启动有头浏览器做手动登录，会话持久化供后续复用
neobot sandbox_CP           # 单独执行一次沙箱清理
neobot firewall-open        # 放行网页面板端口（Windows，需管理员，默认含 9981）
```

源码方式把 `neobot` 换成 `uv run neobot` 即可。

## 7. 升级

```bash
# uv / pip 安装
uv pip install -U neobot-app
# 或
pip install -U neobot-app

# 源码方式
git pull
uv sync --all-packages
```

配置会在启动时自动迁移并备份到数据目录的 `config_backup/`。升级前建议先备份整个数据目录。
