# 06 开发指南

本文面向想要为 NeoBot 贡献代码的开发者。贡献流程见 [CONTRIBUTING.md](../CONTRIBUTING.md)，插件开发见 [07-插件开发](./07-插件开发.md)。

## 环境准备

### 前置要求

- Python 3.13 或更高版本
- [uv](https://docs.astral.sh/uv/getting-started/installation/)（项目使用 uv workspace 管理依赖）

### 克隆与安装

```bash
git clone https://github.com/SuperQuail/NeoBot.git
cd NeoBot

# 安装全部工作区依赖（app + packages/*）
uv sync --all-packages
```

## 目录速览

| 目录 | 说明 |
|---|---|
| app/src/neobot_app/ | 主应用（可执行体）：bootstrap、runtime、reply、skills 等 23 个模块 |
| app/src/neobot_app/builtin_plugins/ | 官方内置插件（`dashboard` 网页面板） |
| app/tests/ | 应用测试（按模块镜像组织：modules/<模块>/test_*.py） |
| packages/adapter/ | OneBot/本地协议适配层 |
| packages/chat/ | LLM Provider、Agent 执行图、工具系统 |
| packages/contracts/ | 跨模块领域模型 + Ports 接口 |
| packages/memory/ | 记忆服务 |
| packages/modloader/ | 插件系统 |
| packages/storage/ | SQLAlchemy 存储层 + Alembic 迁移 |
| scripts/ | 开发辅助脚本 |

## 运行

### 本地运行（无需 QQ）

使用本地适配器（mode = "local"）可以不经 OneBot 框架直接启动，便于开发调试：

```bash
uv run neobot
```

本地适配器监听 HTTP/WebSocket 端口（默认 8090），可用测试脚本模拟消息收发。

### 调试模式

```toml
[debug]
enabled = true
```

开启后可通过网页面板（http://127.0.0.1:9981，用面板密码登录）查看运行概览、后台任务与实时日志。

## 测试

```bash
# 运行全部测试
uv run pytest

# 仅运行应用测试
uv run pytest app/tests

# 仅运行插件系统测试
uv run pytest packages/modloader/tests
```

### 密钥扫描（提交前必过）

仓库禁止提交任何真实密钥，`scripts/check_secrets.py` 会扫描受跟踪文件与提交历史：

```bash
python scripts/check_secrets.py            # 工作区
python scripts/check_secrets.py --staged   # 暂存区（pre-commit 用）
python scripts/check_secrets.py --history  # 全部提交历史
```

- 已启用提交钩子：`git config core.hooksPath .githooks`（克隆后执行一次），
  命中疑似密钥会直接阻止提交；
- 测试夹具/文档占位符需要显式登记到仓库根目录 `.secretsignore`（精确匹配）；
- `app/tests/modules/security/test_repo_secrets.py` 会在测试中复跑同一套规则。
- 密钥统一放 `.env`（不会被提交）或环境变量；确需示例时使用 `sk-xxxxxxxx` 这类占位符。

### 测试标记（markers）

pyproject.toml 中定义了以下标记：

| 标记 | 说明 |
|---|---|
| browser | 需要真实浏览器环境的测试（CI 默认不运行） |
| network | 需要网络访问的测试 |
| slow | 执行时间较长的测试 |
| llm | 需要真实 LLM API 的测试 |

运行特定标记的测试：

```bash
uv run pytest -m "not browser and not network and not slow and not llm"  # 默认快速集
uv run pytest -m "browser"  # 浏览器测试
```

### 测试约定

- pytest.ini_options 配置：asyncio_mode = "auto"（无需手动标记 async 测试）、pythonpath = ["app/src", "packages/contracts/src"]
- 应用测试位于 app/tests/modules/<模块名>/，与 app/src/neobot_app/<模块名>/ 一一对应

## 代码规范

```bash
# 代码风格与静态检查（ruff）
uv run ruff check .
uv run ruff format --check .

# 类型检查（mypy）
uv run mypy app/src packages
```

- 代码风格遵循 [ruff](https://docs.astral.sh/ruff/) 默认规则
- 提交信息遵循[约定式提交](https://www.conventionalcommits.org/zh-hans/v1.0.0/)（feat:、fix:、docs:、refactor:、test:、chore:）

## 网页面板前端（含 3D 舰桥）

面板前端源码在 `app/src/neobot_app/builtin_plugins/dashboard/frontend/`，产物 `web/` **随包入库**，
因此只有改前端才需要 Node.js（CI 的 `frontend` job 会跑一遍并校验产物与源码一致）。

```bash
cd app/src/neobot_app/builtin_plugins/dashboard/frontend
pnpm install
pnpm run dev        # 开发服务器（5173），/api、/image 代理到 9981
pnpm run verify     # lint + typecheck + test + build 一次跑完
pnpm run build      # 必须执行：产物输出到 ../web 并需要一起提交
```

- 改了 `src/**` 却没重新 `pnpm run build`，CI 会因为 `web/` 与源码不一致而失败
- 3D 舰载控制台（`src/bridge/`）用 three.js 实现，**不进经典面板的首屏包**：`App.tsx` 里
  `lazy(() => import('./bridge/bridge'))`，Vite 的 `manualChunks` 把 three.js 单独拆块
- 舰桥的坐标契约在 `src/bridge/core/layout.ts`：舱室/走廊/舱门尺寸由几何与碰撞体共用，
  改坐标后跑 `pnpm run test`（`src/test/bridge.test.tsx` 会校验终端与物资都落在可通行区域内）
- 服务端侧：`dashboard/server.py` 把 `/bridge/**` 映射到 `web/`，并在 `/bridge` 前缀下
  再注册一份 API 路由；后端联调可用 `python scripts/bridge_smoke.py` 做端到端冒烟
- 分支命名：feat/xxx、fix/xxx、docs/xxx、refactor/xxx 等

## 开发一个功能（推荐流程）

1. **从 main 创建分支**：git checkout -b feat/your-feature
2. **定位模块**：确定改动属于哪个层（app 业务逻辑 / packages 子包 / contracts 接口）
3. **遵守依赖方向**：app 依赖 packages，packages 之间通过 neobot-contracts 的 Ports 解耦；新增跨模块能力优先在 contracts 定义接口，在各子包实现
4. **配置项**：新增配置在 [config/schemas/bot.py](../app/src/neobot_app/config/schemas/bot.py) 定义 dataclass，字段带 metadata={"description": ...}（网页面板的配置表单与文档会用到）
5. **Skill/工具**：新能力建议实现为 Skill（app/src/neobot_app/skills/），遵循 SkillModule 协议
6. **测试**：在 app/tests/modules/ 对应目录添加测试，避免依赖真实网络/LLM（使用 browser/llm 标记隔离）
7. **同步文档**：新增/变更功能时更新 docs/04-功能文档/ 对应文件与 docs/05-配置参考.md
8. **提交并推送**，创建 PR（见 CONTRIBUTING.md）

## 构建与发布

- 打包使用 PyInstaller（scripts/publish.ps1 提供发布脚本）
- 版本号遵循语义化版本；发布时执行 [scripts/versions.py](../scripts/versions.py) 统一更新版本

## 常见调试技巧

- 使用 `neobot open_web` 手动登录浏览器，会话持久化供无头复用
- 网页面板（官方插件 dashboard）可查看运行概览、系统状态、后台任务与实时日志，便于问题排查
- [scripts/prompt_builder.py](../scripts/prompt_builder.py) 可预览提示词构建结果
- [scripts/tools_editor.py](../scripts/tools_editor.py) 可视化编辑工具定义
