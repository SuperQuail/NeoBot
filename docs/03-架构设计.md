# 03 架构设计

## 总体分层

NeoBot 采用「应用层 + 可复用子包」的 monorepo 结构（uv workspace），子包之间通过 `neobot-contracts` 定义的 **Ports（接口）** 解耦：

```text
┌──────────────────────────────────────────────────────────────┐
│                         app (neobot_app)                      │
│  bootstrap 装配 → runtime 管线 → reply 编排 → skills/agents   │
└───────┬──────────────────────┬───────────────────────┬────────┘
        │                      │                       │
        ▼                      ▼                       ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-adapter│   │  neobot-chat     │   │ neobot-modloader │
│ OneBot/本地    │   │  Provider/Graph  │   │ 插件系统         │
└───────┬───────┘   └───────┬──────────┘   └─────────┬────────┘
        │                   │                        │
        ▼                   ▼                        ▼
┌──────────────────────────────────────────────────────────────┐
│                 neobot-contracts (模型 + Ports)               │
└───────┬───────────────────────┬──────────────────────┬────────┘
        │                       │                      │
        ▼                       ▼                      ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-memory │   │ neobot-storage   │   │ 外部服务          │
│ 记忆/档案      │   │ SQLAlchemy/Alembic│   │ LLM/浏览器/搜索  │
└───────────────┘   └──────────────────┘   └──────────────────┘
```

## 启动流程（bootstrap）

[`app/src/neobot_app/cli.py`](../app/src/neobot_app/cli.py) 入口 → [`bootstrap/create_application()`](../app/src/neobot_app/bootstrap/__init__.py) 依次完成：

1. **配置加载**（[`bootstrap/_config.py`](../app/src/neobot_app/bootstrap/_config.py)）：读取 `data/config.toml` + `.env`，自动迁移与备份
2. **Provider 构建**（[`bootstrap/_providers.py`](../app/src/neobot_app/bootstrap/_providers.py)）：按模型注册表构建各 LLM Provider（主模型 + Agent 模型 + 视觉/TTS/生图）
3. **服务装配**（[`bootstrap/_services.py`](../app/src/neobot_app/bootstrap/_services.py)）：存储引擎、记忆服务、意愿服务、图片解析、表情包、TTS、绘图管理器、定时任务管理器、通知中心等
4. **Skill 装配**（[`bootstrap/_skills.py`](../app/src/neobot_app/bootstrap/_skills.py)）：调用 [`skills/build_all_skills()`](../app/src/neobot_app/skills/__init__.py) 注册全部内置 Skill
5. **管线构建**（[`bootstrap/_pipeline.py`](../app/src/neobot_app/bootstrap/_pipeline.py)）：插件主机（`PluginHostFacade` + 钩子总线）、回复编排器（`ReplyOrchestrator`）、事件网关与管线（`EventGateway` → `EventPipeline` → `InboundPipeline`）
6. **运行**（[`runtime/application.py`](../app/src/neobot_app/runtime/application.py)）：`run_forever()` 启动适配器、等待 OneBot 连接；收到重启请求（`restart_requested`）后先优雅关闭组件，由 CLI 在 `asyncio.run()` 完成后台任务、异步生成器和默认线程池清理并关闭事件循环后执行进程级重启。新进程继承原启动参数、工作目录及环境，重新读取配置和代码，不复用旧解释器的单例或缓存；磁盘历史数据保留，不新增重试或强杀超时。

## 自包含 HTML 卡片与渲染

- **通用渲染器** [`runtime/html_card.py`](../app/src/neobot_app/runtime/html_card.py)：
  `render_card_html(title, subtitle, blocks, footer, theme, width)` 生成**自包含** HTML
  （内联 CSS、无 JS、无外链），`render_card_image(html, *, timeout, screenshots, fonts=None)`
  走既有 `ScreenshotService` 截图；截图能力不可用或渲染失败时返回 `None`，
  **由调用方降级而不抛异常**。卡片是**运行时**用 Chromium 渲染的，没有任何前端构建步骤：
  主题 = CSS 变量 + 一段主题 CSS + 内联 SVG 装饰，部署侧只要有浏览器即可。

### 主题系统

- **内置主题**：`default`（深夜冷色玻璃）、`bottle`（深海渐变 + 波浪 / 气泡 + 衬线正文）、
  `game`（街机像素：紫底像素网格 + 硬边阴影 + 等宽字体）、`fortune`（宣纸 + 回纹 + 朱红 +
  宋体 / 楷体 + 竹签与印章插图）。每套主题声明自己的**字体栈**、**背景装饰**、
  **标题徽章**与**调色板**，未声明的视觉变量由 `default` 兜底，因此新主题只需给核心颜色。
- **未知主题回落 `default` 并记 warning**；`THEMES` / `resolve_theme` / `theme_variables`
  的既有语义保持不变（`THEMES` 是「主题 id → CSS 变量」的实时映射）。
- **主题注册 API**（插件可注册自己的主题，例如小游戏插件的 `minecraft`）：

  ```python
  from neobot_app.runtime.html_card import EmbeddedFont, register_theme, svg_data_uri

  register_theme(
      "minecraft",
      variables={"--card-bg": "#1d1d21", "--accent": "#7cc576", "--radius": "4px", ...},
      font_stack=['"Monocraft"', '"FusionPixel"', "monospace"],   # CSS 字体族名栈
      embed_fonts=[                                               # 要内联的字体文件
          EmbeddedFont("Monocraft", "assets/fonts/Monocraft-Regular.ttf"),
          EmbeddedFont("FusionPixel", "assets/fonts/FusionPixel8px-zh_hans.woff2", format="woff2"),
      ],
      font_base_dir=Path(__file__).parent,                        # 相对路径的基准目录
      background=svg_data_uri("<svg>…</svg>"),                    # 或纯 CSS 渐变
      ornament='<svg class="nb-mc">…</svg>',                      # 卡片底纹 / 插图（内联 SVG）
      emblem='<svg>…</svg>',                                      # 标题右侧徽章
      svg_assets={"dirt": "<svg>…</svg>"},                        # → CSS 变量 --svg-dirt
      css=".block--kv { border-width: 3px; }",
  )
  ```

  另提供 `unregister_theme`（内置主题不可注销）、`registered_themes`、`get_theme` /
  `theme_spec`、`theme_css`、`theme_svg`；`register_theme(..., fonts=[...])`
  传字体文件列表时也会被识别为 `embed_fonts`。
- **字体绑定**：`font_stack` 写进 `--card-font`（多字体逐字形回退，拉丁像素字体 + 中日韩像素
  字体可以并排声明）；`embed_fonts` 会随卡片 HTML 带一份**内嵌字体清单**，
  渲染时由 `render_card_image` 读回并转成 `neobot_contracts.ports.screenshot.FontFace`，
  经 `RenderOptions.fonts` 以 data URI 内联进临时页 —— 用户不需要安装任何字体。
  带内嵌字体时 `wait_for_fonts=True`（等字形真正就绪），没有内嵌字体时保持 `False` 不额外等待；
  字体文件缺失只记 warning 并回落系统字体，**绝不让渲染失败**；截图链路对个别大体积
  woff2 的字体校验存在概率性失败，此时渲染器自动降级为「不等校验直接渲染」（字体仍内联并生效），
  保证出图优先于校验。
- **自包含约束**（注册时即校验，违反直接抛 `ThemeRegistrationError`）：主题的变量 /
  字体栈 / CSS / SVG 片段里不允许出现 `http(s)://`、`@import`、`<script`、事件处理器、
  `<image>` / `<foreignObject>` 等；要放位图 / 图案请用 `svg_data_uri(...)`，
  它会把 SVG（含 `xmlns` 里的协议分隔符）一并百分号编码，解码后仍是标准 SVG 命名空间，
  因此卡片 HTML 里不会出现任何外链字面量。渲染器的内置主题与插件主题走**同一条注册与校验路径**。
  `background` 支持多个背景层（逗号分隔）；`--card-bg-repeat` / `--card-bg-size` 控制是否平铺与
  单块尺寸（默认平铺），交互式的背景装饰请放在主题 `css` 里而不要写进 `variables`，
  否则会作为缺省值泄漏给其它主题。
- **块 DSL**：`heading` / `kv` / `rows`（支持 `widths` 列宽与 `variant` 变体类）/
  `stats`（指标卡片墙，值可带 `ok` / `warn` / `danger` 色调）/ `grid`（多栏分组，
  单元格内可再嵌块）/ `note` / `pager`（页码条）/ `slot` 与 `marker`（可信片段插槽）。
  块与单元格都可声明 `tone`（`accent` / `ok` / `warn` / `danger` / `muted`）做状态强调。
- **可信片段注入**：`slot` 渲染成占位符，`inject_slot(html, name, fragment)` 把片段插进去；
  `marker`（以及既有的「note 文本里放 `@@MG_XXX@@`」写法）由 `inject_marker(...)` 处理。
  插槽 / 标记名受严格字符集校验，注入的片段由调用方保证**不含任何用户输入**；
  用户可控文本永远先 escape → Markdown → URL 清洗，**绝不进标签或属性**。
- **调用方**：`/status` 的看板卡片（`builtin_plugins/dashboard/status_card.py`）与 `/help` 的命令卡片
  （`runtime/help_card.py`）共用它；小游戏卡片同样复用它。
- **降级链**：`/help` 与 `/status` 都是「HTML 卡片 → 既有 markdown→图片（仅 /help）→ 纯文本」，
  任一级失败都不得让命令报错；截图与 markdown→图片共享同一把 `operation_lock`（串行排队），
  因此每次渲染都设超时。

## /help 预渲染缓存

- [`runtime/help_cache.py`](../app/src/neobot_app/runtime/help_cache.py) 把 `/help` 列表卡片预渲染落盘到
  `<DATA_DIR>/cache/help/`，键为 `help-{权限维度}-p{页码}-s{页大小}-{命令集指纹}.png`，
  另有 `index.json` 记录当前指纹 / 各维度页数 / 生成时间 / 渲染器版本。
- **按权限维度分份**：低权限用户读的是自己维度的文件，**不可能**拿到高权限命令的图 —— 这是该设计
  最关键的安全点。
- **失效**：命令集指纹（`name` / `usage` / `description` / `permission` 四元组的 sha256 前 16 位）
  变化即整体失效，插件加载 / 卸载 / 热重载后自然重渲染；容量上限 60 个文件，超出按生成时间淘汰。
- **触发**：进程启动与软重启后由组合根挂的**后台异步**协程预渲染（失败只记 warning，
  **绝不影响启动**）；未命中时 `/help` 即时渲染并写回；`/help --refresh`（次级管理员及以上）
  手动重建。删掉该目录即回到「每次即时渲染」。

## 用户头像存储（AvatarStore）

- **宿主服务** `avatar_store`（[`runtime/avatar_store.py`](../app/src/neobot_app/runtime/avatar_store.py) 的 `AvatarStore`）：
  在组合根里紧随存储之后装配，并登记进宿主服务注册表，面板与插件通过 `ctx.plugin_host.services` 取用。
  它随软重启复用（核心对象），内存缓存与在途下载不重建。
- **落盘**：`<DATA_DIR>/avatars/<QQ号>.png`（QQ 头像接口的 640px 原图）。头像路径 / 获取时间 /
  失败次数三列加在 `user_data` 上（迁移 `0027_add_user_avatar_storage.py`）：与用户资料同表是因为
  「有 user_data 行 = 认识该用户」，天然覆盖聊过天的人，也避免两处数据不一致。
- **触发点**：[`runtime/event_pipeline.py`](../app/src/neobot_app/runtime/event_pipeline.py) 在用户**再次出现在
  聊天流**时（`_maybe_refresh_avatar`）只做过期判定；下载由 `AvatarStore` 派生的后台任务执行
  （同一用户单飞 + 全局并发上限 + 失败冷却 + 失败不覆盖旧头像），不阻塞消息处理。
- **对外接口**：`get_path` / `get_data_uri`（`data:image/png;base64,…`，内部 128 条进程内 LRU）/
  `maybe_refresh` / `stats`。语义与配置见 [04-功能文档/记忆系统](./04-功能文档/记忆系统.md) 与
  [05-配置参考](./05-配置参考.md) 的 `[avatars]` 段。

## Agent 执行模型

- 主对话 Agent 在提示词约束下运行一个**工具调用循环**（`agent_max_iterations` 上限，默认 200）：
  1. 模型返回文本或工具调用
  2. 工具调用经 SkillManager/工具注册表分发执行
  3. 结果回填上下文，模型继续，直到生成最终回复或调用取消工具（cancel）
- 子 Agent（解题/记忆/聊天互动/创作等）是**独立的 LLM 会话**，主 Agent 通过 `delegate` 工具委托；子 Agent 可要求更多信息（通过 `wait` 工具等待新消息）。
- 所有 Agent 的模型通过 **AgentModelRouting** 的编号（0-3）映射到模型注册表。

## 配置热重载

`bootstrap/_pipeline.py` 注册 `config.reload` 管理命令：重新加载配置文件并广播 `config.changed` 生命周期事件。

**生效编排走注册制**（`runtime/hot_reload_registry.py`）：需要按新配置重建的组件实现 `ConfigConsumer`（声明关心的配置前缀 + 自己负责 `apply_config`），由组合根注册；重载时注册表只调用「声明关心的前缀确实变了」的组件，单个组件失败不影响其余组件。因此**新增一个可热重载子系统 = 新增一次注册**，重载编排代码不动（开闭原则）。

- 已接入：`AdapterSupervisor`（`[adapter]` 监听设置 → 原地重启反向 WS 服务，失败回滚原设置）、`ProviderReloadConsumer`（`[models]` / 平台密钥 → 重建 provider 并原地替换，新 provider 不可用时保留原 provider）。
- 已接入（spec(4) Part A）：`[billing]` 由 `BillingService` **每次现取**，装配处登记 `HotReloadRule("billing", True, …)`（`bootstrap/__init__.py`），改 `enabled` / `timeout_ms` 等立即生效；计价脚本本身另有 `st_mtime_ns + st_size` 文件级重载（`statistics/billing.py`），两者都不需要重启进程。挂在 `[models]` 下的 `billing_script` / `billing_config` 仍按「面板保存并重载」路径生效。
- 生效方式声明也是自注册的：组件通过 `hot_reload_policies` 提交 `HotReloadRule`，`config/hot_reload.py` 的 `RULES` 退化为**基线表**（未登记路径仍按「需重启」保守处理），分类表本身不认识任何具体组件。
- 仍需进程重启：面板自身监听地址/端口（重开 HTTP 服务会中断当前连接）、插件目录等核心构建期组件；TTS 等 bot 侧「需重启」项可点「软重启运行」按当前配置重建（见 [04-功能文档/网页面板](./04-功能文档/网页面板.md)）。
- 软重启只重建 bot 侧对象，而插件运行时是核心对象：每次重建后由组合根调用 `PluginRuntime.bind_generation(...)` 显式切换本次的 Agent/Skill 注册表与截图端口代际，插件已注册的 Agent/Skill 随之迁入新注册表（旧注册表不再被排空/关闭）。插件侧通过解析器读取当前代际，不允许在构造期捕获上一代实例。

**启动韧性**：`runtime/connection_readiness.py` 把「框架是否已连上」降级为**运行状态**而非启动成败 —— 反向 WS 服务启动后框架随时可以连入，未连接不应触发 `application.start()` 的回滚（否则会连带拆掉网页面板这个修复入口）。配置侧同理：`config/availability.py` 用策略决定「模型缺 Key 是致命还是降级」，默认 `DegradeEverythingPolicy` 只降级，让进程与面板先起来。

**依赖方向**：核心层（`runtime` / `bootstrap`）不得 import 具体内置插件实现，`runtime` 不得 import `bootstrap`；由 `app/tests/modules/security/test_architecture_boundaries.py` 机械扫描守住。

## 插件系统

NeoBot 通过 `neobot-modloader` 从文件系统目录加载 Python 插件，分为两类：**官方插件**（随本体分发，位于 `app/src/neobot_app/builtin_plugins/`，可启停/重载但不能安装/更新/卸载，`config.plugins.enabled = false` 不影响它们）与**第三方插件**（安装到数据目录 `plugins/`，可安装/更新/卸载/启停/重载；同名时官方插件优先）。启停状态持久化在数据目录 `plugin_state.json`。

插件显式导出 `plugin = Plugin("name")`，可注册：

- **命令/消息处理器**（`@plugin.on.command` / `@plugin.on.message`）
- **工具**（`@plugin.on.tool`，以 function-calling 形式注入）
- **子 Agent**（`@plugin.on.agent`）
- **Markdown Skill**（`skills/` 目录下的 `SKILL.md`）
- **钩子**（生命周期事件订阅）与 **插件数据库**（自带迁移）

运行时管理通过 `PluginControlFacade`（`load_path` / `unload` / `reload` / `start` / `stop` / `set_enabled` / `install` / `uninstall` / `check_update(s)` / `snapshot`）暴露给网页面板；插件读取本体服务则通过宿主服务注册表 `ctx.plugin_host.services`（`get` / `require` / `names` / `describe`）。

详见 [07-插件开发](./07-插件开发.md) 与 [packages/modloader/README.md](../packages/modloader/README.md)。
