# 03 架构设计

## 总体分层

NeoBot 采用「应用层 + 可复用子包」的 monorepo 结构（uv workspace），子包之间通过 `neobot-contracts` 定义的 **Ports（接口）** 解耦：

```text
┌──────────────────────────────────────────────────────────────┐
│                         app (neobot_app)                      │
│  bootstrap 装配 → runtime 管线 → reply 编排 → skills/agents   │
└───────┬──────────────────────┬───────────────────────┬────────┘
        │                      │                       │
        ▼                      ▼                       ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-adapter│   │  neobot-chat     │   │ neobot-modloader │
│ OneBot/本地    │   │  Provider/Graph  │   │ 插件系统         │
└───────┬───────┘   └───────┬──────────┘   └─────────┬────────┘
        │                   │                        │
        ▼                   ▼                        ▼
┌──────────────────────────────────────────────────────────────┐
│                 neobot-contracts (模型 + Ports)               │
└───────┬───────────────────────┬──────────────────────┬────────┘
        │                       │                      │
        ▼                       ▼                      ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-memory │   │ neobot-storage   │   │ 外部服务          │
│ 记忆/档案      │   │ SQLAlchemy/Alembic│   │ LLM/浏览器/搜索  │
└───────────────┘   └──────────────────┘   └──────────────────┘
```

| `neobot-adapter` | 协议适配：OneBot 11（WebSocket 反向连接）、本地 HTTP/WebSocket、事件分发、消息模型 | [onebot/](../packages/adapter/src/neobot_adapter/onebot/)、[local/](../packages/adapter/src/neobot_adapter/local/)、[eventing.py](../packages/adapter/src/neobot_adapter/eventing.py) |
| `neobot-chat` | LLM 对话内核：Provider（DeepSeek/OpenAI/Anthropic）、Agent 工具循环、工具注册、Skill 注入、插件可用的 Workflow 图 API | [providers/](../packages/chat/src/neobot_chat/providers/)、[runtime/agent.py](../packages/chat/src/neobot_chat/runtime/agent.py)、[tools/](../packages/chat/src/neobot_chat/tools/)、[skills/](../packages/chat/src/neobot_chat/skills/) |
| `neobot-contracts` | 跨模块领域模型（消息、记忆、定时任务、触发器）与 Ports 接口（输出、存储、沙箱、截图等） | [models/](../packages/contracts/src/neobot_contracts/models/)、[ports/](../packages/contracts/src/neobot_contracts/ports/) |

| `neobot-storage` | SQLAlchemy 2.0 async 存储 + 工作单元（UoW）+ Alembic 迁移 | [engine.py](../packages/storage/src/neobot_storage/engine.py)、[uow.py](../packages/storage/src/neobot_storage/uow.py)、[alembic/](../packages/storage/src/neobot_storage/alembic/) |

## 依赖注入与 Ports

`neobot-contracts/ports/` 定义了应用依赖的抽象接口（协议类），例如：

- [output.py](../packages/contracts/src/neobot_contracts/ports/output.py) — 运行时输出（日志/事件）
- [repository.py](../packages/contracts/src/neobot_contracts/ports/repository.py) / [unit_of_work.py](../packages/contracts/src/neobot_contracts/ports/unit_of_work.py) — 存储访问
- [memory.py](../packages/contracts/src/neobot_contracts/ports/memory.py)（规划中，无实现与调用方）/ [archive_memory_access.py](../packages/contracts/src/neobot_contracts/ports/archive_memory_access.py) — 记忆访问
- [sandbox.py](../packages/contracts/src/neobot_contracts/ports/sandbox.py) — 沙箱文件操作
- [provider.py](../packages/contracts/src/neobot_contracts/ports/provider.py) — LLM Provider
- [media_sender.py](../packages/contracts/src/neobot_contracts/ports/media_sender.py) — 媒体发送
- [screenshot.py](../packages/contracts/src/neobot_contracts/ports/screenshot.py) / [creator_image_access.py](../packages/contracts/src/neobot_contracts/ports/creator_image_access.py) / [emoji_access.py](../packages/contracts/src/neobot_contracts/ports/emoji_access.py) — 各类能力

实现位于各子包（如 `neobot-storage` 实现 repository 与 unit_of_work 端口）。应用在 `bootstrap/` 阶段完成装配（依赖注入），使各层可以独立测试与替换。

## 启动流程（bootstrap）

[`app/src/neobot_app/cli.py`](../app/src/neobot_app/cli.py) 入口 → [`bootstrap/create_application()`](../app/src/neobot_app/bootstrap/__init__.py) 依次完成：

1. **配置加载**（[`bootstrap/_config.py`](../app/src/neobot_app/bootstrap/_config.py)）：读取 `data/config.toml` + `.env`，自动迁移与备份
2. **Provider 构建**（[`bootstrap/_providers.py`](../app/src/neobot_app/bootstrap/_providers.py)）：按模型注册表构建各 LLM Provider（主模型 + Agent 模型 + 视觉/TTS/生图）
3. **服务装配**（[`bootstrap/_services.py`](../app/src/neobot_app/bootstrap/_services.py)）：存储引擎、记忆服务、意愿服务、图片解析、表情包、TTS、绘图管理器、定时任务管理器、通知中心等
4. **Skill 装配**（[`bootstrap/_skills.py`](../app/src/neobot_app/bootstrap/_skills.py)）：调用 [`skills/build_all_skills()`](../app/src/neobot_app/skills/__init__.py) 注册全部内置 Skill
5. **管线构建**（[`bootstrap/_pipeline.py`](../app/src/neobot_app/bootstrap/_pipeline.py)）：插件主机（`PluginHostFacade` + 钩子总线）、回复编排器（`ReplyOrchestrator`）、事件网关与管线（`EventGateway` → `EventPipeline` → `InboundPipeline`）
6. **运行**（[`runtime/application.py`](../app/src/neobot_app/runtime/application.py)）：`run_forever()` 启动适配器、等待 OneBot 连接；收到重启请求（`restart_requested`）后先优雅关闭组件，由 CLI 在 `asyncio.run()` 完成后台任务、异步生成器和默认线程池清理并关闭事件循环后执行进程级重启。新进程继承原启动参数、工作目录及环境，重新读取配置和代码，不复用旧解释器的单例或缓存；磁盘历史数据保留，不新增重试或强杀超时。

## 消息处理流水线

```text
OneBot 框架 (NapCat)
      │ WebSocket 反向连接
      ▼
neobot-adapter (OneBotAdapter)
      │ 事件分发 (EventDispatcher)
      ▼
runtime/gateway.py (EventGateway)
      │
      ▼
runtime/event_pipeline.py (EventPipeline)
      │ 按事件类型路由
      ├── 消息事件 → EventPipeline.handle_*_message_event（入队群/私聊消息队列）
      │                └─ InboundPipeline（仅规范化 + 记日志，不持有队列）
      ├── 通知事件 → NoticeHandler
      ├── 生命周期事件 → LifecycleHandler
      └── OneBot 请求 → OneBotRequestHandler
      │
      ▼
reply/orchestrator.py (ReplyOrchestrator)
      │ 1. 意愿判断（willing 服务，决定是否回复）
      │ 2. 提示词构建（prompt/builder.py：system 模板 + 上下文 user 块 + 角色消息）
      │ 3. 调用主模型（agent 模式：迭代执行工具调用循环）
      │ 4. 工具/Skill/子 Agent 执行
      │ 5. 后处理与切分（reply/postprocess.py）
      ▼
reply/sender.py → adapter 发送回复（短句逐条、长回复 Markdown 转图片等）
```

> 流水线各环节实现：
> - [runtime/gateway.py](../app/src/neobot_app/runtime/gateway.py)（EventGateway）→ [runtime/event_pipeline.py](../app/src/neobot_app/runtime/event_pipeline.py)（EventPipeline）→ [runtime/inbound_pipeline.py](../app/src/neobot_app/runtime/inbound_pipeline.py)（InboundPipeline）
> - 消息处理：[runtime/notice_handler.py](../app/src/neobot_app/runtime/notice_handler.py)、[runtime/lifecycle_handler.py](../app/src/neobot_app/runtime/lifecycle_handler.py)、[runtime/onebot_request_handler.py](../app/src/neobot_app/runtime/onebot_request_handler.py)
> - 回复编排：[reply/orchestrator.py](../app/src/neobot_app/reply/orchestrator.py)（ReplyOrchestrator）、[prompt/builder.py](../app/src/neobot_app/prompt/builder.py)、[reply/postprocess.py](../app/src/neobot_app/reply/postprocess.py)、[reply/sender.py](../app/src/neobot_app/reply/sender.py)

## Agent 执行模型

- 主对话 Agent 在提示词约束下运行一个**工具调用循环**（`agent_max_iterations` 上限，默认 200）：
  1. 模型返回文本或工具调用
  2. 工具调用经 SkillManager/工具注册表分发执行
  3. 结果回填上下文，模型继续，直到生成最终回复或调用取消工具（cancel）
- 子 Agent（解题/记忆/聊天互动/创作等）是**独立的 LLM 会话**，主 Agent 通过 `delegate` 工具委托；子 Agent 可要求更多信息（通过 `wait` 工具等待新消息）。
- 所有 Agent 的模型通过 **AgentModelRouting** 的编号（0-3）映射到模型注册表。

## 配置热重载

`bootstrap/_pipeline.py` 注册 `config.reload` 管理命令：重新加载配置文件并广播 `config.changed` 生命周期事件。

**生效编排走注册制**（`runtime/hot_reload_registry.py`）：需要按新配置重建的组件实现 `ConfigConsumer`（声明关心的配置前缀 + 自己负责 `apply_config`），由组合根注册；重载时注册表只调用「声明关心的前缀确实变了」的组件，单个组件失败不影响其余组件。因此**新增一个可热重载子系统 = 新增一次注册**，重载编排代码不动（开闭原则）。

- 已接入：`AdapterSupervisor`（`[adapter]` 监听设置 → 原地重启反向 WS 服务，失败回滚原设置）、`ProviderReloadConsumer`（`[models]` / 平台密钥 → 重建 provider 并原地替换，新 provider 不可用时保留原 provider）。
- 生效方式声明也是自注册的：组件通过 `hot_reload_policies` 提交 `HotReloadRule`，`config/hot_reload.py` 的 `RULES` 退化为**基线表**（未登记路径仍按「需重启」保守处理），分类表本身不认识任何具体组件。
- 仍需进程重启：面板自身监听地址/端口（重开 HTTP 服务会中断当前连接）、插件目录等核心构建期组件；TTS 等 bot 侧「需重启」项可点「软重启运行」按当前配置重建（见 [04-功能文档/网页面板](./04-功能文档/网页面板.md)）。
- 软重启只重建 bot 侧对象，而插件运行时是核心对象：每次重建后由组合根调用 `PluginRuntime.bind_generation(...)` 显式切换本次的 Agent/Skill 注册表与截图端口代际，插件已注册的 Agent/Skill 随之迁入新注册表（旧注册表不再被排空/关闭）。插件侧通过解析器读取当前代际，不允许在构造期捕获上一代实例。

**启动韧性**：`runtime/connection_readiness.py` 把「框架是否已连上」降级为**运行状态**而非启动成败 —— 反向 WS 服务启动后框架随时可以连入，未连接不应触发 `application.start()` 的回滚（否则会连带拆掉网页面板这个修复入口）。配置侧同理：`config/availability.py` 用策略决定「模型缺 Key 是致命还是降级」，默认 `DegradeEverythingPolicy` 只降级，让进程与面板先起来。

**依赖方向**：核心层（`runtime` / `bootstrap`）不得 import 具体内置插件实现，`runtime` 不得 import `bootstrap`；由 `app/tests/modules/security/test_architecture_boundaries.py` 机械扫描守住。

## 插件系统

NeoBot 通过 `neobot-modloader` 从文件系统目录加载 Python 插件，分为两类：**官方插件**（随本体分发，位于 `app/src/neobot_app/builtin_plugins/`，可启停/重载但不能安装/更新/卸载，`config.plugins.enabled = false` 不影响它们）与**第三方插件**（安装到数据目录 `plugins/`，可安装/更新/卸载/启停/重载；同名时官方插件优先）。启停状态持久化在数据目录 `plugin_state.json`。

插件显式导出 `plugin = Plugin("name")`，可注册：

- **命令/消息处理器**（`@plugin.on.command` / `@plugin.on.message`）
- **工具**（`@plugin.on.tool`，以 function-calling 形式注入）
- **子 Agent**（`@plugin.on.agent`）
- **Markdown Skill**（`skills/` 目录下的 `SKILL.md`）
- **钩子**（生命周期事件订阅）与 **插件数据库**（自带迁移）

运行时管理通过 `PluginControlFacade`（`load_path` / `unload` / `reload` / `start` / `stop` / `set_enabled` / `install` / `uninstall` / `check_update(s)` / `snapshot`）暴露给网页面板；插件读取本体服务则通过宿主服务注册表 `ctx.plugin_host.services`（`get` / `require` / `names` / `describe`）。

详见 [07-插件开发](./07-插件开发.md) 与 [packages/modloader/README.md](../packages/modloader/README.md)。
