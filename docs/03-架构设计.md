# 03 架构设计

## 总体分层

NeoBot 采用「应用层 + 可复用子包」的 monorepo 结构（uv workspace），子包之间通过 `neobot-contracts` 定义的 **Ports（接口）** 解耦：

```text
┌──────────────────────────────────────────────────────────────┐
│                         app (neobot_app)                      │
│  bootstrap 装配 → runtime 管线 → reply 编排 → skills/agents   │
└───────┬──────────────────────┬───────────────────────┬────────┘
        │                      │                       │
        ▼                      ▼                       ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-adapter│   │  neobot-chat     │   │ neobot-modloader │
│ OneBot/本地    │   │  Provider/Graph  │   │ 插件系统         │
└───────┬───────┘   └───────┬──────────┘   └─────────┬────────┘
        │                   │                        │
        ▼                   ▼                        ▼
┌──────────────────────────────────────────────────────────────┐
│                 neobot-contracts (模型 + Ports)               │
└───────┬───────────────────────┬──────────────────────┬────────┘
        │                       │                      │
        ▼                       ▼                      ▼
┌───────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ neobot-memory │   │ neobot-storage   │   │ 外部服务          │
│ 记忆/档案      │   │ SQLAlchemy/Alembic│   │ LLM/浏览器/搜索  │
└───────────────┘   └──────────────────┘   └──────────────────┘
```

### 各层职责

| 包 | 职责 | 关键模块 |
|---|---|---|
| `app` | 应用组装与业务逻辑：启动装配、配置、消息管线、回复编排、技能、控制台 | `bootstrap/`、`runtime/`、`reply/`、`skills/` |
| `neobot-adapter` | 协议适配：OneBot 11（WebSocket 反向连接）、本地 HTTP/WebSocket、事件分发、消息模型 | `onebot/`、`local/`、`eventing.py` |
| `neobot-chat` | LLM 对话内核：Provider（DeepSeek/OpenAI/Anthropic）、Agent 执行图、工具注册、Skill 注入 | `providers/`、`graph/`、`tools/`、`skills/` |
| `neobot-contracts` | 跨模块领域模型（消息、记忆、定时任务、触发器）与 Ports 接口（输出、存储、沙箱、截图等） | `models/`、`ports/` |
| `neobot-memory` | 记忆服务：档案读写、图片记忆、归档总结 | `service.py`、`archive_service.py` |
| `neobot-storage` | SQLAlchemy 2.0 async 存储 + 工作单元（UoW）+ Alembic 迁移 | `engine.py`、`uow.py`、`alembic/` |
| `neobot-modloader` | 插件加载与运行时：Plugin API、命令 DSL、钩子总线、插件数据库、依赖注入 | `plugin.py`、`hooks.py`、`loader.py` |

## 依赖注入与 Ports

`neobot-contracts/ports/` 定义了应用依赖的抽象接口（协议类），例如：

- `output.py` — 运行时输出（日志/事件）
- `repository.py` / `unit_of_work.py` — 存储访问
- `memory.py` / `archive_memory_access.py` — 记忆访问
- `sandbox.py` — 沙箱文件操作
- `provider.py` — LLM Provider
- `media_sender.py` — 媒体发送
- `screenshot.py` / `creator_image_access.py` / `emoji_access.py` — 各类能力

实现位于各子包（如 `neobot-storage` 实现 repository 与 unit_of_work 端口）。应用在 `bootstrap/` 阶段完成装配（依赖注入），使各层可以独立测试与替换。

## 启动流程（bootstrap）

`app/src/neobot_app/cli.py` 入口 → `bootstrap/create_application()` 依次完成：

1. **配置加载**（`bootstrap/_config.py`）：读取 `data/config.toml` + `.env`，自动迁移与备份
2. **Provider 构建**（`bootstrap/_providers.py`）：按模型注册表构建各 LLM Provider（主模型 + Agent 模型 + 视觉/TTS/生图）
3. **服务装配**（`bootstrap/_services.py`）：存储引擎、记忆服务、意愿服务、图片解析、表情包、TTS、绘图管理器、定时任务管理器、通知中心等
4. **Skill 装配**（`bootstrap/_skills.py`）：调用 `skills/build_all_skills()` 注册全部内置 Skill
5. **管线构建**（`bootstrap/_pipeline.py`）：插件主机（`PluginHostFacade` + 钩子总线）、回复编排器（`ReplyOrchestrator`）、事件网关与管线（`EventGateway` → `EventPipeline` → `InboundPipeline`）
6. **运行**（`runtime/application.py`）：`run_forever()` 启动适配器、等待 OneBot 连接，支持热重启（`restart_requested`）

## 消息处理流水线

```text
OneBot 框架 (NapCat)
      │ WebSocket 反向连接
      ▼
neobot-adapter (OneBotAdapter)
      │ 事件分发 (EventDispatcher)
      ▼
runtime/gateway.py (EventGateway)
      │
      ▼
runtime/event_pipeline.py (EventPipeline)
      │ 按事件类型路由
      ├── 消息事件 → InboundPipeline（消息队列：群/私聊）
      ├── 通知事件 → NoticeHandler
      ├── 生命周期事件 → LifecycleHandler
      └── OneBot 请求 → OneBotRequestHandler
      │
      ▼
reply/orchestrator.py (ReplyOrchestrator)
      │ 1. 意愿判断（willing 服务，决定是否回复）
      │ 2. 提示词构建（prompt/builder.py：模板 + 聊天记录 + 档案 + 技能说明）
      │ 3. 调用主模型（agent 模式：迭代执行工具调用循环）
      │ 4. 工具/Skill/子 Agent 执行
      │ 5. 后处理与切分（reply/postprocess.py）
      ▼
reply/sender.py → adapter 发送回复（短句逐条、长回复 Markdown 转图片等）
```

## Agent 执行模型

- 主对话 Agent 在提示词约束下运行一个**工具调用循环**（`agent_max_iterations` 上限，默认 200）：
  1. 模型返回文本或工具调用
  2. 工具调用经 SkillManager/工具注册表分发执行
  3. 结果回填上下文，模型继续，直到生成最终回复或调用取消工具（cancel）
- 子 Agent（解题/记忆/聊天互动/创作等）是**独立的 LLM 会话**，主 Agent 通过 `delegate` 工具委托；子 Agent 可要求更多信息（通过 `wait` 工具等待新消息）。
- 所有 Agent 的模型通过 **AgentModelRouting** 的编号（0-3）映射到模型注册表。

## 配置热重载

`bootstrap/_pipeline.py` 注册 `config.reload` 管理命令：重新加载配置文件并广播 `config.changed` 生命周期事件。**部分生效**：运行时按需读取的配置（提示词模板、概率系数、名单、模型注册表等）立即生效；构建期组件（运行中的 LLM Provider、关键词规则、TTS/表情包）需重启。

## 插件系统

NeoBot 通过 `neobot-modloader` 从文件系统目录加载 Python 插件。插件显式导出 `plugin = Plugin("name")`，可注册：

- **命令/消息处理器**（`@plugin.on.command` / `@plugin.on.message`）
- **工具**（`@plugin.on.tool`，以 function-calling 形式注入）
- **子 Agent**（`@plugin.on.agent`）
- **Markdown Skill**（`skills/` 目录下的 `SKILL.md`）
- **钩子**（生命周期事件订阅）与 **插件数据库**（自带迁移）

详见 [07-插件开发](./07-插件开发.md) 与 [packages/modloader/README.md](../packages/modloader/README.md)。
