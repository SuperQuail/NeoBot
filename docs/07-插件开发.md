# 07 插件开发

NeoBot 通过 **neobot-modloader** 从文件系统目录加载 Python 插件。本文是插件开发的入门指南；**完整 API 文档见 [packages/modloader/README.md](../packages/modloader/README.md)**（747 行，含全部注册方式与示例），以下仅做概览与示例。

## 官方插件与第三方插件

| | 官方插件 | 第三方插件 |
|---|---|---|
| 位置 | `app/src/neobot_app/builtin_plugins/`（随本体分发） | 数据目录 `plugins/`（`plugins.dir`，默认 `./plugins`） |
| 安装 / 更新 / 卸载 | 不支持（随本体升级） | 支持（面板或 `PluginControlFacade`） |
| 启停 / 热重载 | 支持 | 支持 |
| 运行配置 | `plugins_data/<插件名>/config.toml` | `plugins_data/<插件名>/config.toml` |
| 打包默认值 | 插件 `plugin.toml` 的 `[config]`（可留空，用代码里的默认值） | 插件 `plugin.toml` 的 `[config]` |
| 受 `plugins.enabled` 影响 | 否，始终加载 | 是，`plugins.enabled = false` 时全部跳过 |

- 同名时**官方插件优先**，第三方副本被忽略。
- **官方插件 ID 是保留字**（spec(4) R27/D24）：安装第三方插件时，若 manifest 的 `name` 命中 `builtin_plugins/` 下的官方插件名，安装**直接拒绝**，文案为「官方插件随本体更新，不能在面板内更新」。同名第三方插件需要改名后才能安装。
- 官方与第三方插件的**配置位置完全一致**：`data/plugins_data/<插件名>/config.toml`。插件目录里的 `plugin.toml` 只提供打包默认值（安装/更新会覆盖），用户与面板的改动写在插件数据目录，升级不会丢。
- 读取规则：打包默认值打底，插件数据目录里已保存的值覆盖（嵌套表逐层合并），因此插件升级新增的配置项会自动补上默认值。插件在 `on_load` 收到的 `ctx.config` 就是合并后的结果。
- **是否启用不是配置项**：启停状态是数据目录 `plugin_state.json` 里的独立记录（`{"plugins": {"<插件名>": {"enabled": false}}}`），默认启用；面板/代码里的启停只改这条记录，不碰配置，也不受插件更新影响。`plugin.toml` 顶层的 `enabled` 只是**打包默认值**（插件默认关闭时可写 `false`）。
- 插件配置可在网页面板「插件 → 配置」在线编辑：键名命中 `api_key` / `token` / `password` / `secret` 等敏感规则的字段**只写不读**（面板只显示「已设置 / 未设置」，留空表示不修改）；含密钥时该插件的源码模式会被禁用。
- 插件自己的数据库/鉴权等文件同样放在 `plugins_data/<插件名>/` 下（`ctx.data_dir`）。

## 插件结构

插件可以是单个 Python 文件（第三方插件）：

```text
plugins/
  ping.py
```

也可以是一个包（官方插件同样是包）：

```text
plugins/
  weather/
    plugin.toml
    __init__.py
```

插件模块必须导出一个 Plugin 实例（当前版本只保留这一种写法）：

```python
from neobot_modloader import Plugin

plugin = Plugin("ping")
```

> 不再支持旧的 setup(ctx)、ctx.on.*、Matcher、on_command() 等兼容 API。

## plugin.toml 字段

包形式的插件可带一个 `plugin.toml`（单文件插件不需要）：

```toml
name = "weather"
version = "1.0.0"
description = "天气查询插件"
author = "your-name"
dependencies = []            # 依赖的其它插件名
priority = 0                 # 加载优先级
min_neobot_version = ""      # 最低本体版本
python_dependencies = []     # 需要自动安装的第三方包

# 以下为可选元数据（更新检查与面板展示用）
repo = "https://github.com/you/neobot-plugin-weather"
branch = "main"
homepage = "https://example.com/weather"
license = "MIT"
tags = ["tool", "weather"]
hot_reload = true            # 插件本体是否支持面板内热重载（不重启进程）
config_hot_reload = true     # 插件配置改动是否支持不重启生效

[config]                     # 打包默认配置；运行配置在 plugins_data/<插件名>/config.toml
host = "127.0.0.1"           # 留空表示全部使用代码里的默认值
```

- `repo` / `branch` 用于面板的「检查更新 / 更新此插件」（仅第三方插件）。
- `homepage`、`license`、`tags` 仅用于展示。
- `hot_reload` / `config_hot_reload` 缺省为 `true`，也可在 `Plugin(...)` 构造参数里声明（`plugin.toml` 优先）。
  面板会把两项能力分别标记为「可热重载 / 本体需重启」与「配置可热重载 / 配置需重启」；
  声明 `hot_reload = false` 后，面板与 `PluginControlFacade.reload()` 会拒绝热重载并提示重启。
  插件自身持有监听端口、后台线程或启动期快照时应当声明为 `false`（例如官方 dashboard 插件）。
- 插件下载代理可在 `[plugins]` 配置（`proxy_mode` / `proxy_host` / `proxy_port`），
  面板「插件管理 → 代理设置」可随时切换，无需重启。

## 管理接口（PluginControlFacade）

网页面板等调用方通过 `PluginControlFacade` 管理插件，方法均返回 `PluginOperationResult`（`ok` / `name` / `state` / `error` / `requires_restart` / `path`）：

| 方法 | 说明 |
|---|---|
| `load_path(path, start=True)` | 从磁盘路径加载插件 |
| `unload(name)` | 卸载（不删除文件） |
| `reload(name, start=True)` | 重新加载 |
| `start(name)` / `stop(name)` | 启动 / 停止 |
| `set_enabled(name, enabled)` | 启停并持久化到 `plugin_state.json`（官方与第三方统一处理） |
| `install(repo, branch=None, replace=False, start=True)` | 从 Git 仓库安装（仅第三方） |
| `uninstall(name)` | 卸载并删除文件（仅第三方；面板不允许卸载自身） |
| `check_update(name)` / `check_updates()` | 检查更新 |
| `snapshot()` / `get(name)` | 插件快照列表 / 单个快照（含 `official`、`manageable`、`hot_reloadable`、`hot_reload`、`config_hot_reload`） |
| `installer_proxy()` / `set_installer_proxy(mode, host, port)` | 读取 / 切换插件下载代理（system / none / custom） |
| `config_model(name)` | 插件声明的配置模型（面板据此生成配置表单并做保存前校验） |
| `plugin_config_path(name)` | 插件配置文件路径（`plugins_data/<插件名>/config.toml`，未加载的插件同样可用） |
| `plugin_config_defaults(name)` | 插件打包默认值（`plugin.toml` 的 `[config]`） |
| `plugin_config_values(name)` | 插件当前生效的配置（默认值 + 已保存的值） |
| `register_config_consumer(name, consumer)` | 声明「本插件的配置可以在运行期原地生效」（见下节） |
| `config_consumer(name)` / `unregister_config_consumer(name)` | 读取 / 注销已登记的配置消费者 |

约束：官方插件 `manageable = False`，不能安装/更新/卸载；面板自身不能在面板内停用或重载。

## 插件配置的「原地生效」（可选）

默认情况下，插件配置改动需要重载插件或重启 NeoBot 才生效（受 `config_hot_reload` 控制）。
但对于**持有长生命周期资源**的插件（HTTP 服务、连接、内存指标），整插件重载代价很大——
面板自身就是典型：重载会关闭 HTTP 服务、切断当前保存请求、并丢掉全部内存指标。

这类插件可以用**配置消费者**声明「哪些字段保存后可以原地生效」：

```python
class MyConfigConsumer:
    name = "myplugin"
    config_paths = ("plugin.myplugin",)

    @property
    def hot_reload_policies(self):
        from neobot_app.config.hot_reload import HotReloadRule
        return (
            # 运行期安全：保存即生效
            HotReloadRule("plugin.myplugin.poll_interval_seconds", True, "循环每轮重读配置"),
            # 绑定期 / 安全类：保守处理，仍提示需要重启
            HotReloadRule("plugin.myplugin.port", False, "监听端口在启动时绑定"),
        )

    async def apply_config(self, config):
        # 用新的**生效配置**让自己生效；失败请抛出（调用方会保留旧配置并报错给面板）
        self.setting = int(config["poll_interval_seconds"])


@plugin.on_load
async def _load(ctx):
    control = getattr(ctx, "plugin_control", None)
    register = getattr(control, "register_config_consumer", None)
    if callable(register):
        register(ctx.plugin_name, MyConfigConsumer())
```

约定与语义：

| 项 | 说明 |
|---|---|
| 路径命名空间 | `plugin.<插件名>.<配置键>`；**未在 policies 里登记的键一律按「需要重启」处理**（保守，避免新字段被误判） |
| 保存行为 | 面板保存时把「运行期安全」的字段原地喂给 `apply_config`；**不重载插件本体**，HTTP 服务与内存指标不受影响 |
| 部分生效 | 一次保存里同时有可生效项与需重启项时，可生效的立即生效，并提示「另有 N 项需重启」 |
| 失败处理 | `apply_config` 抛异常 → 面板提示「已保存但立即生效失败（已保留原配置）」，插件继续按旧值运行 |
| 注销 | 插件卸载时运行时**自动**移除消费者；插件也可在 `on_shutdown` 里显式 `unregister_config_consumer` |
| 向后兼容 | **未声明消费者的插件行为完全不变**（继续提示「需要重启 NeoBot」） |

> 不要把「把 `hot_reload` 改成 `true`」当成等价手段：那等于真正卸载并重装插件，
> 会关闭并重新绑定服务、重建订阅、丢掉内存状态，还会联动停/起依赖它的插件。

## 宿主服务注册表

插件读取本体服务无需依赖装配代码，通过 `ctx.plugin_host.services` 访问：

```python
services = ctx.plugin_host.services
config = services.get("config")            # 未注册时返回 None
adapter = services.require("adapter")      # 未注册时抛 KeyError，并列出可用服务名
names = services.names()                   # 可用服务名列表
infos = services.describe()                # [{name, description, available}, ...]
```

本体在装配阶段注册的核心服务包括 `config`、`adapter`、`logger_factory`、`host_commands`、`group_queue`、`friend_queue`、`reply_orchestrator`、`emoji_service`、`tts_service`、`file_server`、`image_pool`、`drawing_manager`、`creator_image_service`、`scheduled_task_manager`、`problem_solver_manager`、`notification_hub`、`self_heal_manager`、`browser_lifecycle_manager`、`vision_detect_service`、`vision_provider`、`provider`、`command_service`、`credential_manager`、`sleep_service`、`standby_service`、`cache_calculator`、`archive_memory_service`、`prompt_store`、`chat_flow_registry`、`context_recorder` 等（以 `services.names()` 的实际结果为准）。

其中 `standby_service` 是待机服务，供插件读取待机状态或触发待机（面板待机控制与 `/standby`、`/reboot` 共用同一状态机）。

## 最小官方插件示例

官方插件就是 `app/src/neobot_app/builtin_plugins/` 下的一个子包，目录结构与普通插件包一致：

```text
app/src/neobot_app/builtin_plugins/
  hello/
    __init__.py
    plugin.toml
```

`plugin.toml`：

```toml
name = "hello"
version = "1.0.0"
description = "示例官方插件"
author = "NeoBot"
homepage = "https://github.com/SuperQuail/NeoBot"
license = "MIT"
tags = ["official", "example"]

# 运行配置在插件数据目录 plugins_data/hello/config.toml（面板可编辑），
# 本表只提供打包默认值（可留空，用代码里的默认值）。
[config]
greeting = "你好"
```

`__init__.py`：

```python
"""最小官方插件：注册一条命令与一个工具。"""

from __future__ import annotations

from neobot_modloader import Plugin, Reply

plugin = Plugin("hello", version="1.0.0", description="示例官方插件")


@plugin.on.command("hello")
async def hello() -> Reply:
    return Reply("你好！")


@plugin.on.tool("hello_echo", description="回显一段文本")
async def hello_echo(text: str) -> str:
    return text
```

要点：

- 官方插件无需登记到任何清单，放在 `builtin_plugins/` 下即会被扫描（`builtin_plugin_dirs()`）。
- 需要配置时在 `plugin.toml` 的 `[config]` 里写打包默认值，运行值由面板写入 `plugins_data/<插件名>/config.toml`，插件内通过 `ctx.config` 使用合并后的结果。
- 官方插件只能启停与重载，不能从面板安装/更新/卸载，改动随本体版本发布。

参考实现：[dashboard 网页面板](../app/src/neobot_app/builtin_plugins/dashboard/)。

## 注册命令

```python
from neobot_modloader import Plugin, Reply

plugin = Plugin("ping")

@plugin.on.command("ping")
async def ping():
    return Reply("pong")
```

### 注册进本体命令表（`ctx.app_commands`）

`@plugin.on.command` 是**模式匹配**，不参与本体的命令表、也没有权限概念。
要让命令出现在 `/help`、受统一的权限判定保护，用 `ctx.app_commands.register(...)`：

```python
from neobot_app.commands.model import PERM_SUB_ADMIN

@ctx.app_commands.register(
    "status",
    description="查看 NeoBot 运行状态",
    usage="[概况 用量 插件 错误]",
    permission=PERM_SUB_ADMIN,
)
async def _status(command_ctx):
    return "文本回复（也可自行发图后返回 None）"
```

#### 命令命名：先试原名，冲突才加来源前缀

> **破坏性变更（spec(4) R26 / D21）**：早期版本对插件命令**一律**加 `{插件名}__` 前缀，
> 现在改为「**先试原名**」。升级后既有插件注册的命令名可能由 `/foo__bar` 变为 `/bar`。

| 情况 | 结果 | 日志 |
|---|---|---|
| 无冲突 | 用**原名**（如 `/status`） | — |
| 原名（或它的别名）已被占用 | 自动改为 `{插件名}__{name}`（如 `/dashboard__status`） | WARNING：`命令因重名被重命名` |
| 原名与前缀名都被占用 | **跳过注册**，只记 WARNING；**不抛异常、不阻断插件加载** | WARNING：`原名与来源前缀名均被占用，跳过注册` |

要保持改造前的旧行为（一律加前缀）显式传 `prefixed=True`：

```python
ctx.app_commands.register(Command(name="ping", description="响应测试", handler=_ping), prefixed=True)
```

#### 来源可见性与权限

- 注册成功的命令会带上插件来源：`/help` 列表与详情对**插件命令**追加 `[来源: <插件名>]`，本体命令不带标记；
  被重命名的命令还会记录「原 `/status` → 实际 `/dashboard__status`（重名）」，在网页面板「插件 → 详情」里可见。
- 权限等级常量在 `neobot_app.commands.model`：`PERM_EVERYONE = 0`（所有人）、`PERM_SUB_ADMIN = 1`（次级管理员）、`PERM_SUPER_ADMIN = 2`（超级管理员）。
  判定由 `CommandService` 在 **handler 之前**统一完成，越权自动回「你没有权限使用 /xxx(需要权限:次级管理员)」。
  **插件不需要（也不应该）在 handler 里写权限代码。**
- 命令随插件停用 / 卸载自动摘除（`unregister_all()`），不会留下悬空命令。

## 插件配置与本体配置解耦

插件的运行配置**不在本体 `config.toml` 里**：官方插件与第三方插件都使用

```text
data/plugins_data/<插件名>/config.toml
```

- 插件自带的 `plugin.toml` 的 `[config]` 只是**打包默认值**（安装/更新会被覆盖）；
- 用户与面板的改动写在插件数据目录，插件升级不丢；
- 面板「插件 → <插件名> → 配置」显示的就是这个真实文件路径；
- **是否启用不是配置项**：启停记录在 `plugin_state.json`，面板详情页的「运行状态」行
  可以启用/停用插件，停用后配置仍可编辑。

### 给配置项写注释（面板会显示成字段说明）

在 `plugin.toml` 的 `[config]` 里给每个默认值写一行注释即可：

```toml
[config]
# 默认回答语言
language = "zh"
# 单次回复的最大字符数
max_reply_chars = 800
```

面板表单会把注释渲染成字段说明，并在首次生成 `config.toml` 时把注释写进文件；
保存时保留已有注释与顺序。有 pydantic 配置模型的插件还可以用
`Field(description=...)`，两者同时存在时模型说明优先。

## 插件依赖与前置调用

插件可以在 `plugin.toml` / `Plugin(...)` 里声明前置插件（支持版本约束）：

```toml
name = "starship"
version = "1.0.0"
dependencies = ["dashboard>=1.0.0"]
priority = -1
```

行为（详见 [packages/modloader/README.md](../packages/modloader/README.md) 的「插件依赖」）：

- 前置插件先加载（拓扑排序，同级按 priority）；
- 前置插件缺失 / 版本不满足 / 被停用 / 依赖成环时，本插件**自动禁用**，
  程序照常启动，面板插件页会显示原因与「依赖未满足」标记；
- 前置插件恢复后自动重新加载；停用 / 卸载 / 重载前置插件时联动停用依赖方；
- 版本号只比数字段，无法比较时按满足处理（不会把插件拦死）。

调用前置插件的功能用能力（capability）：

```python
# 前置插件 dashboard
@plugin.capability("web.register_extension")
async def _register_extension(payload):
    return server.register_extension(payload["name"], payload["extension"])


# 依赖方 starship
@plugin.on_load
async def _load(ctx):
    handle = ctx.require_plugin("dashboard", ">=1.0.0")
    await handle.call("web.register_extension", {"name": "starship", "extension": ext})
```

`ctx.require_plugin` 在前置插件不存在 / 未就绪 / 版本不符时抛
`PluginDependencyError`；`ctx.plugins.optional(name)` 是拿不到就返回 None 的宽松版本。

## 官方插件示例：starship（星舰游戏）

`app/src/neobot_app/builtin_plugins/starship/` 是一个完整的官方插件示例，
覆盖了本文大部分能力：

| 能力 | 用法 |
| --- | --- |
| 插件依赖 | `dependencies = ["dashboard>=1.0.0"]` |
| 前置调用 | `ctx.require_plugin("dashboard").call("web.register_extension", ...)` |
| 对外能力 | `@plugin.capability("minigame.register")` 供其它插件注册小游戏元数据 |
| 独立数据库 + 迁移 | 成绩与成就表（`starship.db`） |
| HTTP 扩展点 | 页面与 `/game/api/*` 挂在面板同一个端口下 |
| 编译产物随包分发 | `frontend/` 源码不进包，`web/` 产物随包（部署无需 Node） |

## 官方插件示例：minigame（命令 + agent 工具双通道）

`app/src/neobot_app/builtin_plugins/minigame/` 是「命令 + agent 工具双通道」的完整范例，
推荐第三方插件直接照抄这套形状。

### 1. 命令入口用 `ctx.app_commands`

```python
from neobot_modloader import Plugin

plugin = Plugin("minigame", version="1.0.0", config=MinigameConfig)


def register_commands(self, ctx):
    registrar = ctx.app_commands
    @registrar.register(
        "mg",
        description="NeoBot 小游戏：漂流瓶 / 成语接龙 / 签到与积分 / 抽签",
        usage="[游戏|stop|rank|积分|help] [参数]",
        aliases=("游戏",),
    )
    async def _mg(command_ctx):
        return await self.handle_command(command_ctx)
```

- 命令进的是**本体命令表**，因此 `/help` 会列出它、权限判定与来源标记（`[来源: minigame]`）
  都由本体完成；重名时自动变 `minigame__<名字>`。
- 停用 / 卸载时随 `ctx.app_commands.unregister_all()` 一起摘除。

### 2. agent 工具用 `@plugin.tool`，并**按功能拆成技能包**

```python
@plugin.tool("bottle_write", package="bottle", description="把一句话装进漂流瓶...")
async def _tool_bottle_write(content: str, anonymous: bool = False) -> str:
    ...

@plugin.tool_package("bottle", description="漂流瓶", instructions=game.describe())
```

- 工具最终名恒为 `{插件名}__{工具名}`；`package=` 只决定它属于哪个**可独立加载的技能包**
  （技能名 `{插件名}_{包名}`），于是一个插件可以「只激活漂流瓶工具」而不是整套工具。
- `instructions=` 是给模型看的用法说明，可用 `skills__view_instructions` 查看。
- 不写 `package=` 时全部工具聚成以插件名命名的单个技能，与历史行为一致。

### 3. 关键词入口用 `@plugin.message`，经 `ctx.agent_reply` 交回主管线

插件消息处理器**不能**自己发一句话冒充 AI，也不该直接把 AI 回复拦掉。正确做法是
把「事实 + 提示词」交回主回复管线，并声明本轮要预激活哪些技能包：

```python
@plugin.message(keywords=("漂流瓶", "签到", "抽签"), rule=_not_a_command, priority=10)
async def _keyword_entry(ctx, event: dict) -> str:
    guidance = build_guidance(event)          # 给模型看的事实与两个分支
    ctx.agent_reply(guidance, preactivate=["minigame_bottle", "minigame_base"])
    return guidance
```

- 语义与命令层的 `sync_reply` 一致：不发固定文本，结果作为背景触发**一次**模型回复；
- `preactivate` 里的技能包在**本轮**工具表构建前激活，模型当场就能调用；
- 意图是**一次性**的（随事件对象传递、被消费即清除），未登记意图时行为与历史完全一致；
- 处理器保持 `block=False` / `block_ai_reply=False`，不消费消息、不拦截 AI 回复。

### 4. 命令层的交互路径：`command_ctx.sync_reply = True`

命令参数格式错误 / 缺参数 / 用户只说自然语言时，不要回固定错误文案：

```python
async def _mg_bottle(self, command_ctx, args):
    if not content:
        command_ctx.sync_reply = True          # 结果交主管线，由模型组织回复
        return "事实：用户要发瓶但没给正文（未写库）。请先问清他想说什么。"
    ...                                        # 参数完整：直接执行 + 渲染卡片
```

### 5. 卡片渲染与头像

- 卡片统一走 `neobot_app.runtime.html_card`（多主题、自包含 HTML、无 JS / 无外链），
  渲染不可用时降级成**信息等价**的纯文本；
- 头像一律查本体头像存储（宿主服务 `avatar_store`），**不要自己联网**；
- 用户正文若要支持 Markdown，请**先 HTML 转义再渲染**，并对链接做属性级清洗。

### 6. 数据与限流

- 独立数据库：`plugin.sqlite_database("main", filename="minigame.db", migrations=[...])`，
  文件落在 `plugins_data/<插件名>/databases/`；
- `ctx.data_dir` 是插件数据目录，缓存 / 导出文件也放这里。
