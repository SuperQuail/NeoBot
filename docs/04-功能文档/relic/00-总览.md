# Relic 总览

> 模块 X · 归属 relic 插件 · 状态：设计稿（未实现）

Relic（遗物）是官方插件，为机器人提供「增强虚拟人生」：让 Bot 有跨月的虚拟日程、会关心特定用户、并能对重点用户做长期观察。
**插件默认关闭**，开启后才会占用模型与磁盘——描述文案：*为你的QQ机器人提供增强虚拟人生，但会增加一定开销*。

## 1. 目标与非目标

**目标**

1. Bot 有可查询的月度虚拟日程，并在节日为用户安排关心。
2. 对白名单私聊用户，Bot 能在合适的时间主动关心（定时任务）。
3. 对重点用户，Bot 每天做一次深度观察，结论进入用户档案，后续对话自然带上。

**非目标**

- 不做插件市场、不做第三方托管。
- 不改本体对话管线，不注入主提示词模板；日程（R-A）本轮只存不用，R-C 的「近期状态」按 03-§5 只读追加在档案正文后。
- 不做多实例分布式调度。

## 3. Agent 路由

relic **不复用对话 agent**，在 `[agent_model]` 单独注册两条路由（`app/src/neobot_app/config/schemas/bot_parts/model_registry.py:310-348`）：

| 路由键 | 用途 | 默认编号 | 说明 |
|---|---|---|---|
| `relic_planner` | 月度规划 | 1 | 每月一次，可给强推理 |
| `relic_analyst` | 陪伴分析 + 精益求精 | 3 | 高频，默认低成本非推理 |

两条路由各自 `resolve_agent_model_name` → `create_provider` 得到独立 provider，再由 relic 自建 `neobot_chat.Agent` 实例。它们**不进入** `AgentRegistry`，与主对话、记忆管线互不调用，会话历史独立。

先例：`app/src/neobot_app/bilibili/diary_tools.py:117-140`（Toolset + Agent + `asyncio.wait_for`）。

**统一约定：所有 relic agent 都是多轮工具调用，结果一律由 submit 工具提交。**

| Agent | 提交工具 | 读取工具范围 |
|---|---|---|
| `relic_planner` | `submit_monthly_plan` | 关系、近期消息、关系写入 |
| `relic_analyst`（陪伴） | `submit_companion_tasks` / `no_action` | 消息、日记素材、关系、档案 |
| `relic_analyst`（精益求精） | `submit_analysis` / `skip_analysis` | 消息、日记素材、关系、群资料、档案 |

不解析 assistant 正文，不靠提示词约定 JSON；参数校验由工具定义（JSON Schema）与工具实现共同完成，
校验失败返回错误字符串让模型自行修正重提。

## 4. 开关与白名单

三层放量，避免一开插件就全量跑模型：

| 层 | 位置 | 默认 |
|---|---|---|
| 插件启停 | `plugin.toml` `enabled=false` / 面板 | 关闭 |
| 功能开关 | relic `[config]`：`monthly_plan`、`companion`、`perfection`、`record_messages` | 前三个开、记录开 |
| 用户白名单 | `relic_whitelist`：`companion` / `perfection` 两列 | 空 |

**白名单只属于精益求精体系**（R-C 及其自动开启的陪伴分析 R-B）；月度规划（R-A）的节日任务按关系图谱与近期互动挑人，**不使用白名单**。

白名单写入只有一个可信入口：管理员命令 `/relic`（`permission=1`）；agent 工具 `relic__enable_companion` / `relic__enable_perfection` 只记录用户请求并提示管理员确认，不直接写白名单。

## 5. 成本

| 任务 | 频率 | 触发者 | 量级 |
|---|---|---|---|
| 月度规划 | 每月 1 次 | 调度循环 | 一次生成（多轮工具调用，输入由 agent 按需读取；轮次/超时上限见 01） |
| 陪伴分析 | 不足 30 条时每次检查最多 1 次；攒够 30 条在最近一次检查立即分析（最迟约 60 分钟） | 消息计数 + 定时检查 | 每次约 50 条消息 + 档案 + 关系 |
| 精益求精 | 每天每用户 1 次 | 00:00 队列 | 多轮工具调用（`max_iterations` 默认 1000；`timeout_seconds` 默认 120/180，见 01/02/03） |

四个刹车：白名单、`max_pending_tasks`、`timeout_seconds`（默认值见各模块）、每用户每日上限；`max_iterations` 默认 1000，只作防死循环兜底。
所有调用按 `agent:relic` 记账（`app/src/neobot_app/statistics/tracker.py:24-36` 白名单需加此项），面板用量页可查。

## 6. 隐私与数据

- 聊天记录**只写 relic 自己的库**（`relic_messages`），本体 `messages` 表零改动。
- 保留期默认 30 天，每日清理；插件关闭即停止记录。
- 精益求精会读取该用户出现过的其他群聊记录（只读，来自 relic 自己的记录）。
- 关系图谱写本体库（`user_relations`），供所有 agent 查询。

## 7. 术语

| 词 | 含义 |
|---|---|
| 白名单 | 被允许触发关心/深度分析的用户，表 `relic_whitelist` |
| 陪伴分析 | R-B，产出定时任务 |
| 精益求精 | R-C，产出档案结论 |
| 日记素材 | R-D，带时间区间的聊天摘要，供后续日记生成使用 |
| 近期状态 | R-C 结论段，注入在用户档案正文之后 |
