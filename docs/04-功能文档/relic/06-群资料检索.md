# 群资料检索

> 模块 M-B · 归属 **本体** · 状态：设计稿（未实现）

让 agent 能按群名/群档案找到群，理解一个群是什么性质的地方。
数据来自既有表 `group_data`，只补一个搜索工具和一个开关。

## 1. 目标与非目标

**目标**

1. 按关键词（群名、群档案）搜群，返回群号 + 群名 + 档案摘要。
2. 默认开启，可一键关闭。
3. 零新表：复用 `group_data`(`group_name`,`profile`)。

**非目标**

- 不做群成员检索（属于用户档案领域）。
- 不缓存群公告、群主等需要打 API 的资料。

## 2. 数据来源

`packages/storage/src/neobot_storage/models.py:48-55`：

| 列 | 说明 |
|---|---|
| `group_id` | 群号（主键） |
| `group_name` | 群名 |
| `profile` | 群档案（由记忆 agent 维护） |
| `is_quite` | 是否禁言/沉默标记 |

写入方：启动时拉群列表落 `group_name`（`app/src/neobot_app/database/chatstream.py`），
`profile` 由记忆 agent 的档案总结写入。

## 3. 工具

加在已有 `app/src/neobot_app/skills/group_management.py`（不新建 skill）：

| 工具 | 参数 | 返回 |
|---|---|---|
| `group_management__search_groups` | `query`、`group_id`(可选，精确查询)、`limit`(默认 5，上限 20) | 每项：`group_id`、`group_name`、`profile` 摘要（≤200 字）、`is_quite` |

匹配规则：给 `group_id` 时按群 ID 精确返回该群；否则 `query` 对 `group_name` 与 `profile` 做大小写不敏感 LIKE，命中群名优先排序，其次按 `group_id` 升序稳定排序。
空 `query` 返回群资料库中按 `group_id` 升序的若干群（不承诺活跃度，也不做额外统计）。

返回 JSON 数组，字段名固定，便于模型引用。

## 4. 配置

| 键 | 默认 | 位置 |
|---|---|---|
| `group_search_enabled` | true | `[chat]` |

关闭后工具不注册（模型看不到），而不是注册后返回错误——避免工具表噪音。

## 5. 接入与权限

- 工具是只读的，权限与其它查询类工具一致（任何会话可用）。
- 不返回群成员名单、不返回群公告。
- 结果不含敏感字段（群档案由本体写入，已受档案容量治理约束）。

## 6. 失败与边界

- 空库/无匹配：返回空数组 `[]`；调用方据空数组自行提示，不在数组里混入文本（保持返回结构固定）。
- LIKE 通配符：对 `%`、`_` 转义，防止用户输入变成通配。
- 大结果：`limit` 上限 20，单条 `profile` 截断到 200 字。
- 群号不存在但用户知道群名：搜不到就如实返回空，不臆造。

## 7. 测试与验收

- 单元：按群名匹配、按档案匹配、转义 `%`、limit 上限、空结果文案。
- 单元：开关关闭后工具不在工具表里。
- 集成：agent 一轮对话里能搜到群并引用群名。
