# 月度规划

> 模块 R-A · 归属 relic 插件 · 状态：设计稿（未实现）

每月最后 5 天起，用一个独立 agent 生成下个月的虚拟日程；若本月还缺计划则先补本月。
同时根据下月节日，判断是否给特定用户安排定时任务（按关系图谱与近期互动挑人，不使用精益求精的白名单）。

## 1. 目标与非目标

**目标**

1. 每月有一份可查询的日程（节庆、主题、备注），落 `relic_monthly_plan`。
2. 节日任务按关系图谱与近期互动挑人（**不走精益求精的白名单**），且不重复、不刷屏。
3. 检查本身要安静：不需要生成时只写 debug，生成才写 info。

**非目标**

- 本轮不把日程注入对话提示词，只存不用。
- 不做权威农历换算，节日名单先由模型生成并校验。

## 2. 触发与流程

调度循环由 `ctx.create_task` 托管（`packages/modloader/src/neobot_modloader/messaging.py:38-64`），
宿主没有 cron/tick 设施，循环体自管：

```text
每 monthly_check_interval_seconds（默认 3600）执行一次：
  1. 本月计划缺失 → 生成「本月」（补跑）
  2. 距月末 ≤ monthly_lead_days（默认 5）且下月计划缺失 → 生成「下月」
  3. 否则 → debug 日志「relic 月度规划：本月/下月已存在，跳过」
```

判定顺序固定为上面 1→2→3，一次 tick 最多生成一份，避免月初与月末同时触发。

生成条件满足时先写 info 日志（含目标年月），再调用模型；失败在下个 tick 重试，不阻塞循环。

## 3. 生成（多轮工具调用）

一次生成 = 一个带工具的 `neobot_chat.Agent`（`relic_planner` 路由）。**结果只认工具调用，不解析 assistant 正文，也不靠提示词约束 JSON。**

| 工具 | 用途 |
|---|---|
| `relation__list_relations` | 读 Bot 直连关系，确定节日问候对象 |
| `relic__search_messages` | 查近期私聊过的人（节日候选） |
| `relation__save_relation` | 聊出新的亲属/朋友关系时顺手记录 |
| `submit_monthly_plan` | **提交最终计划**，参数即结构 |

`submit_monthly_plan` 参数（工具定义即 JSON Schema）：

| 参数 | 类型 | 约束 |
|---|---|---|
| `month` | string | `YYYY-MM`，必须等于目标月 |
| `festivals` | array | 每项 `{id, name, date, suggestion}`，`date` 落在该月 |
| `days` | array | 每项 `{date, theme, note}`，日期合法且不重复 |
| `festival_tasks` | array | 每项 `{festival_id, user_id, reason}`，`user_id` 必须在候选集内 |

流程：模型自由多轮读工具 → 调 `submit_monthly_plan` → 工具内校验并落库 → 返回 `{"ok": true, "plan_id": ...}`。
校验失败时工具返回错误字符串（模型可改后重提），不落库。

预算：`planner_max_iterations`（默认 1000，防死循环兜底，正常不会撞上）、`planner_timeout_seconds`（默认 120）。
真正的约束是超时——需要多读几轮就让它读，不要用轮次去卡正常路径。
到预算仍未调用 submit → 本次失败，下个 tick 重试。

## 4. 节日任务

**目标人群不使用白名单**（白名单只属精益求精体系）。候选集合来自两处：

1. 关系图谱里与 Bot 直接相连的用户（部署者、亲人、朋友等，见 [05-关系图谱](./05-关系图谱.md)）；
2. 最近 `festival_target_days`（默认 30）天里与 Bot 有过私聊的用户（来自 `relic_messages`）。

由 `relic_planner` 在生成计划时一并给出「节日 × 用户 × 理由」，relic 侧只做校验与落地：

1. 跳过条件：该用户当天已有未完成任务；该节日今天已过；落在安静时段（默认 23:30–08:00）；该用户本月已有节日任务（每人每月最多 1 次）。
2. 通过则经 `scheduled_task_manager.create_task`（`app/src/neobot_app/runtime/scheduled_tasks.py:213-246`）建一次性任务：
   - `bindings=[ConversationRef(kind="private", id=QQ号)]`
   - `detail` 写「今天是 X 节，用一句话关心他/她，不要提定时任务」
   - `start_at` 默认节日当天 10:00（可配 `festival_send_hour`）
3. 成功后在 `relic_festival_task` 记录 `(year_month, festival_id, user_id)` 唯一键，重跑不重复建。

上限：每月总量 `max_festival_tasks_per_month`（默认 10），每人每月 1 次；超出只记 debug，不追问模型。

## 5. 接口

| 类型 | 名称 | 说明 |
|---|---|---|
| 路由 | `agent_model.relic_planner` | 规划专用模型编号（0–3，默认 1） |
| 工具 | `relic__read_monthly_plan` | 主 agent 读取当前/指定月份日程 |
| 命令 | `/relic plan [YYYY-MM]` | 管理员手动查看或强制重生成（`permission=1`） |
| 表 | `relic_monthly_plan` | 见 [07-数据模型与接口](./07-数据模型与接口.md) |

## 6. 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `monthly_plan` | true | 功能总开关 |
| `monthly_lead_days` | 5 | 提前多少天开始生成下月 |
| `monthly_check_interval_seconds` | 3600 | 检查间隔 |
| `festival_send_hour` | 10 | 节日任务默认发送小时 |
| `max_festival_tasks_per_month` | 10 | 每月节日任务总量上限（每人每月 1 次） |
| `festival_target_days` | 30 | 从多少天内的私聊互动里挑候选用户 |

## 7. 失败与边界

- 工具参数校验失败（日期越月、用户不在候选集、条数超限）→ 工具返回错误让模型重提；重试到 `planner_max_iterations` 仍未通过则本次失败。
- 到超时（或撞到 1000 轮兜底）仍未调用 `submit_monthly_plan` → 视为失败，最多每个目标月重试 3 次后写 warn，等下一个 tick 再试。
- 定时任务管理器不可用（本体 `scheduled_task.enabled=false`）→ 只生成日程，跳过节日任务并记 warn。
- 重复任务配额（`max_repeating_tasks`）不影响本模块：节日任务都是 `once`。
- 时区统一 `time_context.now_local()`（UTC+8，`app/src/neobot_app/time_context.py:62`）。

## 8. 测试与验收

- 单元：tick 判定三分支（补跑/生成下月/跳过）用假时钟；日志级别断言（跳过=debug、生成=info）。
- 单元：非法 JSON、缺字段、日期越月 → 不落库且计数重试。
- 单元：同一节日重复 tick 只建一次任务（唯一键）。
- 手工：把 `monthly_lead_days` 调到月末当天，观察生成与节日任务。
