# 配置参考

> 模块 X-2 · 归属 跨模块 · 状态：设计稿（未实现）

分两块：**relic 插件配置**（在 `plugins_data/relic/config.toml`，`plugin.toml` 只放打包默认值）
与**本体新增配置**（在 `data/config.toml`）。

## 1. relic 插件配置

`plugin.toml` 的 `[config]` 写默认值并逐项加中文注释；面板据此生成表单，首次生成
`plugins_data/relic/config.toml` 时把注释写进文件，保存时保留。

```toml
[config]
# 月度虚拟日程：每月最后几天生成下月计划
monthly_plan = true
# 提前多少天开始生成下月计划
monthly_lead_days = 5
# 规划检查间隔（秒）
monthly_check_interval_seconds = 3600
# 节日任务的默认发送小时
festival_send_hour = 10
# 计划生成的最大工具轮数（兜底，正常不会撞上）
planner_max_iterations = 1000
# 计划生成总超时（秒）
planner_timeout_seconds = 120
# 每月节日任务总量上限（每人每月 1 次）
max_festival_tasks_per_month = 10
# 从多少天内的私聊互动里挑节日候选用户
festival_target_days = 30

# 自动定时任务：对白名单私聊用户分析并安排关心
companion = true
# 检查间隔（分钟）
companion_interval_minutes = 60
# 攒够多少条消息立即分析
companion_message_threshold = 30
# 每用户最多几个待触发的自动任务
max_pending_tasks = 3
# 不排任务的时段（本地时间）
quiet_hours = "23:30-08:00"
# 送入分析模型的消息条数上限
analysis_history_limit = 50
# 陪伴分析的最大工具轮数（兜底）
analysis_max_iterations = 1000
# 陪伴分析总超时（秒）
analysis_timeout_seconds = 120

# 精益求精模式：每天对重点用户做一次深度分析
perfection = true
# 每天几点开始排队
perfection_start_hour = 0
# 每个用户之间的间隔（秒）
perfection_dispatch_interval_seconds = 300
# 单次分析的工具轮数上限（兜底）
max_iterations = 1000
# 单次分析总超时（秒）
timeout_seconds = 180
# 结论字数上限
max_analysis_chars = 800
# 每用户每天最多分析几次
perfection_daily_limit = 1

# 聊天记录：是否记录消息（供日记素材与分析使用）
record_messages = true
# 记录保留天数
retention_days = 30
# 单条消息入库长度上限
max_text_chars = 2000
# 单条日记素材摘要上限
max_summary_chars = 500
# 日记素材总条数上限
diary_material_limit = 500
```

### 热更新

`config_hot_reload = true`。可原地生效的键（由配置消费者声明，`HotReloadRule`）：
`quiet_hours`、`max_pending_tasks`、`analysis_history_limit`、`max_analysis_chars`、`retention_days`、
`max_text_chars`、`max_summary_chars`、`diary_material_limit`、`companion_message_threshold`、
`monthly_lead_days`、`festival_send_hour`、`max_festival_tasks_per_month`、`festival_target_days`。

需要重启（或重载插件）的键：`monthly_plan`、`companion`、`perfection`、`record_messages`、各间隔秒数（循环启动时读取）。

## 3. 敏感字段

relic 不存凭据，本插件没有 secret 字段。本体 `user_relations.note` 可能被 agent 写入，
面板只显示条数，不展示内容；如需展示，按既有「只写不读」规则处理。

## 4. 默认值原则

- 功能开关默认开（需求：自动定时任务默认开启），但**没有白名单用户时不产生模型调用**。
- 所有"高频"路径都有上限键，方便用户按钱包收紧。
- 所有时间相关键用本地时间（UTC+8），与本体一致。

## 5. 失败与边界

- 插件配置里出现未知键：本体加载时忽略并告警（`packages/modloader/src/neobot_modloader/config_validation.py:14-50`），不阻断插件启动。
- 类型错误/越界（如 `quiet_hours` 不是 `HH:MM-HH:MM`）：回落默认值并告警，面板保存时由 pydantic 模型校验拒绝。
- 开关全关时：relic 只保留调度循环，不产生模型调用、不建定时任务、不写消息记录。
- `retention_days = 0` 视为「不保留」，等价于关闭记录；`max_pending_tasks = 0` 视为不建自动任务。

## 6. 测试与验收

- 单元：`RelicConfig` 默认值快照（守住插件升级不悄悄改默认行为）。
- 单元：`plugin.toml [config]` 与模型默认值一致（参考 `app/tests/modules/test_plugin_config_comments.py` 的官方插件守卫）。
- 单元：`quiet_hours` 解析覆盖跨天区间（23:30–08:00）。
- 本体：`AgentModelRouting` 新字段默认值与解析函数单测；`docs/05-配置参考.md` 同步检查。
