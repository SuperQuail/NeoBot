# 聊天记录与日记素材

> 模块 R-D · 归属 **relic 插件**（不是本体） · 状态：设计稿（未实现）

relic 自己记录聊过什么，并从中沉淀「日记素材」：一段带时间区间的聊天摘要。
素材供分析 agent 按需查阅，将来给日记生成用。

**本体 `messages` 表零改动**——记录归属插件，随插件启停，隐私面不会扩大到所有部署。

## 1. 目标与非目标

**目标**

1. 给 R-B/R-C 提供可跨会话、跨群检索的消息来源（重启后仍可查）。
2. 给「日记」提供中间产物：时间区间 + 摘要 + 来源会话。
3. 记录行为可控：开关、保留期、单条长度上限。

**非目标**

- 本轮不做日记生成（用户明确：日记机制尚未设计）。
- 不替代本体记忆/档案，不改写本体数据。

## 2. 消息记录

注册 `@plugin.message()`（空 pattern 匹配全部消息，`packages/modloader/src/neobot_modloader/command_dsl.py:97-98`），
处理函数必须**非阻塞**：只做字段裁剪 + 一次 INSERT，不做模型调用、不 await 网络。

记录条件：`record_messages=true`（默认）、消息类型为文本、非插件自身发出的消息。

写入 `relic_messages`：

| 列 | 说明 |
|---|---|
| `event_id` | 唯一键，重复投递幂等 |
| `conversation_kind` | `private` / `group` |
| `conversation_id` | QQ 号或群号 |
| `sender_id` / `sender_name` | 发送者 |
| `text` | 纯文本，超 `max_text_chars`（默认 2000）截断 |
| `occurred_at` | UTC 时间戳 |

索引：`(sender_id, occurred_at)`、`(conversation_kind, conversation_id, occurred_at)`。

清理：每天一次删除 `occurred_at < now - retention_days`（默认 30 天）的行，写 debug 日志（行数）。

## 3. 日记素材

`relic_diary_material`：

| 列 | 说明 |
|---|---|
| `id` | 自增主键 |
| `conversation_kind` / `conversation_id` | 来源会话 |
| `start_at` / `end_at` | 覆盖的时间区间（UTC） |
| `summary` | 摘要，≤ `max_summary_chars`（默认 500） |
| `keywords` | 逗号分隔，便于检索 |
| `source_count` | 该区间内被概括的消息条数 |
| `created_at` | 记录时间 |

「素材」不是日记正文，只是一条可被检索的观察记录；同一天可以有多条，来源可以不同群。

## 4. 工具

全部是 `@plugin.tool(package="diary")`，默认工具名 `relic__<name>`：

| 工具 | 参数 | 返回 |
|---|---|---|
| `relic__record_diary_material` | conversation、start_at、end_at、summary、keywords | `{id}` |
| `relic__list_diary_materials` | since?、limit(≤20)、keyword? | 只回 summary + 时间区间 + 来源，不回正文长文 |
| `relic__read_diary_material` | id | 完整摘要 + 来源会话 + 可回查消息的区间 |
| `relic__search_messages` | user_id?、conversation?、since?、query?、limit(≤50) | 命中的消息行（截断） |

设计约定：
- 列表只给 summary（需求原文：显示给 agent 的是 summary），要看来源再调 `read_diary_material`。
- `read_diary_material` 返回来源会话后，agent 可用 `search_groups`（[06](./06-群资料检索.md)）看群性质、用 `relation__list_relations` 看关系。

## 5. 「要求」怎么写

需求里的「为记忆 agent 提供新的工具和要求」落在两处：

1. `plugin.tool_package("diary", description="日记素材", instructions=...)`——说明什么值得记：
   - 有情绪转折、有承诺/计划、有明确时间点（「五点吃饭」「下周一面试」）、关系变化；
   - 必须带时间区间，summary 先写「谁在哪段时间发生了什么」；
   - 不确定是否值得记时不记。
2. R-C 分析 agent 的 system prompt 复用同一段文字，保证「记录标准」只有一份。

> 说明：本体记忆 agent 的工具表是装配期快照（`app/src/neobot_app/bootstrap/_services.py:380-403`），
> 插件工具进不去；因此这里的「记忆 agent」实现为「主 agent 可加载的日记工具包 + relic 自己的分析 agent」。

## 6. 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `record_messages` | true | 是否记录消息 |
| `retention_days` | 30 | 记录保留天数 |
| `max_text_chars` | 2000 | 单条消息入库长度上限 |
| `max_summary_chars` | 500 | 单条素材摘要上限 |
| `diary_material_limit` | 500 | 素材总条数上限，超出删最旧 |

## 7. 失败与边界

- 写库失败：只记 warn，丢弃该条，绝不阻塞消息处理（消息管线优先）。
- 并发：`aiosqlite` + WAL（`packages/modloader/src/neobot_modloader/database.py:235-292`），批量插入用单次事务。
- 隐私：只记文本，不记图片/文件；不记 Bot 自己发出的消息之外的敏感字段；保留期到期自动删。
- 容量：超过 `diary_material_limit` 时删最旧素材，避免无限增长。

## 8. 测试与验收

- 单元：幂等（同 `event_id` 重复写入不报错）、截断、保留期清理。
- 单元：`list_diary_materials` 只回 summary；`read_diary_material` 回正文与来源。
- 单元：`search_messages` 的 user_id / conversation / since 组合过滤。
- 手工：开插件聊几句，查 `plugins_data/relic/databases/relic.db`。
