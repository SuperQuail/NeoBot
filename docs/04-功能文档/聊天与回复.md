# 聊天与回复

NeoBot 的核心能力：在群聊与私聊中自然对话。本节说明消息如何进入队列、Bot 如何决定是否回复以及如何组织回复。

## 消息通道

- **群聊通道**与**私聊通道**各自维护独立的消息队列（[`app/src/neobot_app/message/queue.py`](../../app/src/neobot_app/message/queue.py)），队列长度上限为 `chat.max_group_chat_observations` / `chat.max_friend_chat_observations`（默认 200）。
- 启动时可选预热历史消息（`enable_group_startup_history_warmup` / `enable_friend_startup_history_warmup`，配合白名单），让 Bot 启动后即有上下文。
- 事件进入队列时带权重：戳一戳按 `poke_weight`（默认 0.2）计，回应按 `reaction_weight` 计。
- **Bot 自己的发言也会入队**（文本逐段、图片/语音按索引），并按 `self_sent_message_weight`（默认 0.1）计权：这样回复管线因寿命耗尽、挂起恢复或软重启而重新组装提示词时，`role=assistant` 的历史不会凭空消失（否则模型会把同一句话再答一遍）。后台通知同样以 0.1 权重入队，渲染为 `[通知:<source>] <content>`。
- Bot 发出的图片以**索引**入队（`[图片:tmp_xxx file:<路径>]`）：产物登记在 temp 图库，agent 需要时可再用 `image_context__add_image(image_id="tmp_xxx")` 取回查看，队列本身不占用上下文窗口。

## 回复模式

`chat.reply_mode`（在 `EnhancedChat` 中）可选：

- `agent`（默认，推荐）：Agent 模式。主模型在提示词约束下自主判断是否回复，可调用工具、委托子 Agent，回复由 send_reply 工具发出。
- `common`：基础模式。仅触发基础回复功能，通过概率系数决定是否回复，不推荐。

## 回复意愿（Willing）

Bot 并非每条消息都回复，回复与否由意愿服务（`app/src/neobot_app/willing/`）决定：

- `group_chat_chance`：群聊基础回复概率（默认 0.5）
- `willing_global_coefficient`（common 模式）/ `willing_agent_global_coefficient`（agent 模式）：全局回复概率系数
- `group_response_coefficient`：按群号配置的回复系数
- 名单控制：`group_use_black_list` / `friend_use_black_list` 选择黑名单或白名单模式，`group_list` / `friend_list` 为名单
- `reply_blacklist`：回复黑名单（QQ 号），名单内用户 @Bot 时不强制追加回复要求

## @ 与必回

- `at_mention_guaranteed_reply`（默认 true）：@ 时必回。
- `at_mention_reply_delay_seconds`（默认 5.0）：@ 提及时的回复延迟，期间收集后续群消息再生成回复，避免碎片化回复。
- **命中玩法关键词时跳过该等待**：插件可以把自己「意图已经明确」的关键词登记到本体
  （[message/fast_reply_keywords.py](../../app/src/neobot_app/message/fast_reply_keywords.py)），
  被 @ 的正文命中即**直接触发回复事件**，不再等收集窗口。当前登记方是小游戏插件
  （漂流瓶 / 成语接龙 / 签到 / 抽签 等关键词，只登记已启用的玩法；插件停用后随之注销）。
  判定是**最长关键词优先、大小写不敏感**，且只在被 @ 时生效——普通群消息依旧走回复意愿。
  事件入口与回复后的挂起循环两处都遵循这一规则。

## 回复组织与后处理

- **短句切分**：回复会被自动切分为多条短句逐条发送（模拟打字间隔），`reply_sentence_cooldown_seconds` / `private_chat_sentence_cooldown_seconds` 控制逐句冷却（默认 2 秒）。
- **冷却**：`reply_cooldown_seconds` 控制距上次回复结束的最小间隔。
- **长回复保护**：`long_reply_max_length`（默认 300 字符）与 `long_reply_max_sentence_count`（默认 12 条）超限时触发 fallback（`long_reply_fallback_template`）；`enable_ai_reply_regenerate_on_length_limit`（默认 true）时先让 AI 重新生成更简短的版本。
- **AI 回复检查**：`ai_reply_check`（全量）或 `ai_reply_check_lightweight`（仅在过长/过多拦截时）开启后，send_reply 先返回切分结果供主 Agent 确认。
- **Markdown 长回复**：如需发送代码块/表格/公式等，使用 `send_long_reply` 工具，内容会渲染为图片发送（[`app/src/neobot_app/reply/markdown_image.py`](../../app/src/neobot_app/reply/markdown_image.py)）。
- **位置追踪**：`enable_last_reply_tracking` 记录「上次回复到」的位置并在提示词中显示，避免重复回复。
- **同一轮可多次回复**：`send_reply` 允许在同一轮（同一次回复事件）里连续调用多次，
  用于长任务的**开工告知**与**中途进度汇报**——发完不必结束本轮，可以继续调用工具。
  连续多轮只调工具不回复时，由沉默提醒机制（`chat.silent_nudge_*`）注入一条
  `[silent_nudge]` 提醒推模型一把（详见 [提示词系统](./提示词系统.md)）。

## 关键词规则

`chat.key_word` 配置关键词规则列表（`KeyWordRule`）：

```toml
[[chat.key_word]]
enabled = true
keywords = ["妈妈", "妈"]
prompt_list = ["你可以反问对方是不是叫夏亚"]
ignore_case = true
match_mode = "any"   # any / all
min_depth = -1
max_depth = 0
description = ""
```

命中关键词时，将 `prompt_list` 中的提示注入提示词，引导 Bot 做出特定反应（彩蛋/梗）。

## 随机表情包

`random_sticker_probability`（默认 0.1）：回复事件中随机触发聊天互动 Agent 发送表情包的概率。

## 命令

文本以 `/` 开头即视为命令（群聊需先 @bot，私聊直接触发）。命令表由本体命令与插件命令共同组成：

| 命令 | 权限 | 提供方 | 说明 |
|---|---|---|---|
| `/help [命令名] [页码]` | 所有人 | 本体 | 命令菜单**图片卡片**：列表每页 30 条，`/help <命令名>` 看详情，`/help <页码>` 翻页 |
| `/sleep <时长>` | **次级管理员** | 本体 | 进入睡眠（最长 12 小时）；回复由 AI 生成 |
| `/awake` | **次级管理员** | 本体 | 结束睡眠；回复由 AI 生成 |
| `/status [概况 用量 插件 错误]` | **次级管理员** | 网页面板插件（dashboard） | 回一张**状态图片卡片**；不带参数时四块全渲染，带块名时只渲染选中的块，未知块名回明确错误且不出图 |

`/status` 的四个块与字段（**固定白名单，不可配置**）：

| 块 | 字段 |
|---|---|
| 概况 | 在线状态 / 延迟 / 运行时长 / 今日消息 / 累计消息 / 协议端名与版本 |
| 用量 | 近 24 小时与近 7 天的金额（CNY）、输入 / 输出 / 缓存命中 Token、调用次数 |
| 插件 | 名称 / 版本 / 状态 |
| 错误 | 近 24 小时 ERROR 条数 + 最近一次异常的时间与模块名 |

**明确不出现**：QQ 号、昵称、头像、群名与好友名、配置值、`.env`、API Key、提示词、日志正文、
档案与聊天内容、按模型 / 模块 / 会话排行、堆栈、安装路径与 repo 地址。白名单硬编码在
`builtin_plugins/dashboard/status_card.py`，要扩白名单必须改代码并走评审。

卡片按**分块卡片化**呈现：概况是六格指标卡片（在线状态 / 异常值按语义着色），
用量把「近 24 小时 / 近 7 天」并排成两栏，插件表按状态着色（运行中绿、已停用灰），
错误块在近 24 小时有 ERROR 时整体转为**告警配色**（红标题 + 红边面板 + 左侧色条）。

渲染依赖 playwright + chromium（见 [部署说明](../08-部署说明.md)）；缺少浏览器或渲染失败 / 超时时
自动降级为**等价的纯文本卡片**（同样四块、同样字段）+ 一行「安装 playwright 与 chromium 后可发图片」，
命令不会因此报错。

权限由 `CommandService` 统一判定：普通成员发 `/status` 会收到「你没有权限使用 /status(需要权限:次级管理员)」，
handler 不会被执行。命令由面板插件在 `load()` 里注册，插件停用 / 卸载即摘除。

命令重名时插件命令会自动追加来源前缀，并在 `/help` 里带 `[来源: <插件名>]` 标记；
命名规则与 `prefixed=True` 兼容开关见 [07 插件开发](../07-插件开发.md)。

### 帮助菜单（`/help`）

`/help` 渲染一张**自包含 HTML 卡片**并作为图片发送（不再走 markdown→图片 路径）：

- **语法**：`/help [命令名] [页码]`。参数逐个解析，**能当作数字的视为页码**
  （多个数字取最后一个），其余视为命令名。于是 `/help` 与 `/help 2` 都是列表，
  `/help ping` 是单命令详情。
- **列表**：每页最多 **30 条**，按命令名升序。表格分三列 —— **命令**（`/命令 [用法]`）、
  **说明**（一句话描述）、**权限 / 来源**；权限与来源各占一行，所以窄列里也不会折行
  （`[权限: 所有人]` 一行、`[来源: minigame]` 一行）。列表带斑马纹，
  超过一页时表格下方出现**翻页条**（`第 P/M 页` + 页码圆点，当前页高亮），
  页脚显示 `共 N 条 · 用 /help <页码> 翻页`（命令不超过一页时只留总数、不出翻页条）；
  没有可见命令时显示空态文案。
- **详情**：命令名、描述、权限、用法、别名、来源与参数表，不分页；用法用等宽字体，
  权限与来源显示为圆角标签。
- **配色**：卡片跟随主题渲染（默认深夜蓝），标题带强调色装饰线、分区分块卡片化、
  表头与斑马纹、页脚强调短线；主题与字体栈见
  [03 架构设计 · 自包含 HTML 卡片与渲染](../03-架构设计.md)。
- **越界页码**：`/help 0` / `/help 999` 会给出越界提示，并渲染**最接近的合法页**，
  卡片顶部标注「页码 X 超出范围（共 M 页），已显示第 P 页」，不会出现空白图。
- **三级降级**：HTML 卡片 →（既有）markdown→图片 → 纯文本。任一级成功即视为已回复，
  三级全部失败才由命令服务发送纯文本，因此命令**不会**因渲染问题报错。
- **权限**：只列出当前用户有权限的命令；图片里除了命令名 / 描述 / 用法 / 权限 / 别名 /
  参数 / 来源之外不含任何信息（不含 token、配置值与用户标识）。

**预渲染与缓存**：进程启动与软重启后，后台会预渲染**三个权限维度**
（所有人 / 次级管理员 / 超级管理员）的列表卡片并落盘到 `<DATA_DIR>/cache/help/`：

- 缓存**按权限维度分份**并按页存放，读取时按当前用户的维度取，
  低权限用户不可能拿到高权限命令的图；
- 缓存键带**命令集指纹**（命令名 / 用法 / 描述 / 权限的哈希）：插件加载、卸载、
  热重载后指纹变化，旧缓存立即失效并重新渲染；渲染器版本变化同样失效；
- 命中缓存时直接发图；未命中时即时渲染并写回缓存（详情卡片按需渲染后写回）；
- 目录内图片上限 **60 个文件**，超出按生成时间淘汰最旧的；
- 预渲染**后台异步**执行，失败只记 warning，不会影响启动 / 软重启；
  删掉 `<DATA_DIR>/cache/help/` 即回到「每次即时渲染」；
- `/help --refresh`（**次级管理员及以上**）：重算指纹、重渲染列表并清理旧文件。

### 睡眠与唤醒

`/sleep <时长>` 进入睡眠、`/awake` 结束睡眠。**睡眠语义完全不变**：睡眠期间群聊
消息只接收不回复、被 @ 会叫醒、私聊不受影响、单次最长 12 小时。区别在于**回复由 AI
生成**：

- **只要回复管线可用，所有分支都交主 Agent 组织回复**（命令把「事实 + 提示词」
  交给主管线，由 AI 用自己的语气回应）—— 包括缺参数、时长非法、超过 12 小时、
  没有在睡眠时执行 `/awake`、睡眠服务未注入这类**没有状态变更**的分支；
  它们同样走模型，不再回固定提示。
- 回复管线**不可用**时（Bot 处于待机、主模型未注册）才回**固定文案**兜底，
  命令不报错，用户一定有反馈；
- 重复 `/sleep` 保持「按新时长重置」的语义，并明确提示
  「已在睡眠中（剩余 X）；已按新时长重置」。

> **设计原则**：除**语义明确的纯工具命令**（如 `/help`、`/status`、纯查库的 `/mg 积分`）
> 保持确定性输出外，其余命令一律以 **agent 互动为主** —— 命令层只提供「事实」，
> 由模型决定怎么把话说出口。后续新增命令（含小游戏）都遵循这条。

提示词分区为 `[sleep_cmd]` 与 `[awake_cmd]`（可自定义，见
[提示词系统](./提示词系统.md)）；它们与「睡眠中被 @ 唤醒」的 `[wake_up]` 是两回事，
互不覆盖。

## 相关配置

- 提示词模板：全部位于 `data/prompts/`（默认 + 自定义两文件合并），不在 `config.toml` 中。
  分区、占位符、转义与消息结构见 [提示词系统](./提示词系统.md)。
- 群聊/私聊描述：`chat.group_description` / `chat.friend_description`，用于让 Bot 了解群/好友背景。
- 工具输出压缩：`chat.tool_result_full_keep`（默认 10）/ `chat.tool_result_summary_chars`（默认 200）。
