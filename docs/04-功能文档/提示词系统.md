# 提示词系统

NeoBot 的所有模型提示词都来自 **提示词文件**（`data/prompts/`），与 `config.toml` 分离，
按分区维护、按占位符渲染。本节说明消息结构、可用分区、占位符与转义规则，以及自定义方式。

## 目录结构

```
data/prompts/
├── README.md            使用说明（首次运行自动生成）
├── default/prompts.toml 默认提示词（每次启动 / config.reload 由内置模板覆盖同步，勿手改）
└── custom/prompts.toml  自定义提示词（默认为空，写入的分区/键覆盖默认值）
```

合并规则（保证跨版本升级不丢自定义）：

1. 自定义文件中出现的分区/键覆盖默认值；
2. 未出现在自定义文件中的分区/键自动继承默认值；
3. 程序升级后新增的分区自动继承默认值，无需手动处理。

提示词按文件 mtime 自动感知（每次构建 prompt 时校验），改完即生效，无需重启；
需要重新同步默认提示词时执行 `config.reload` 命令。

## 一次模型调用的消息结构

聊天记录**不再内嵌在 system 提示词里**，而是作为真实消息追加在 system 之后：

| 顺序 | 角色 | 内容来源 | 模板分区 |
|---|---|---|---|
| 1 | system | 人设、回复规则、群/好友元信息、编号格式说明 | `[group_chat]` / `[friend_chat]` |
| 2 | user | 本轮上下文：群友信息、对方档案、印象 | `[group_context]` / `[friend_context]` |
| 3 | user / assistant | 按发送者拆分的聊天记录（Bot 自己的发言是 assistant） | 代码构建（`prompt/role_messages.py`） |
| 4 | user | 回复前的当前时间块 | `[current_time]` |

拆分角色的意义：assistant 消息就是模型自己说过的话，因此「不要重复回答」「不要与自己
之前的话矛盾」是模型可直接验证的约束，而不是提示词里的口头要求。

第 4 条（`[current_time]`）在**每次调用模型前**追加一条最新时间块，且始终是本次请求的最后一条
消息；历史时间块**保留在对话中不做清理**，模型因此能看到时间推进。群聊挂起恢复时，新出现的群友档案通过
`[new_member_profiles]` 渲染进 `[group_chat_resume]` 说明块，同样作为 user 块追加，
不插入 system。

## 分区一览

| 分区 | 键 | 用途 |
|---|---|---|
| `group_chat` | `template` | 群聊 system 提示词 |
| `group_context` | `template`、`enabled` | 群聊上下文 user 块（群档案/群友信息/印象） |
| `friend_chat` | `template` | 私聊 system 提示词 |
| `friend_context` | `template`、`enabled` | 私聊上下文 user 块（聊天对象/印象/对方信息） |
| `friend_chat_hint` | `template`、`enabled` | 私聊专属提示（追加在私聊 system 末尾） |
| `long_task_progress` | `template`、`enabled` | **长任务过程可见性**（追加在群聊/私聊 system 末尾）：开工先说、中途报进度、不报流水账 |
| `current_time` | `template`、`enabled` | 回复前的 `<当前时间>` user 块（**每次管线激活**追加一条完整时间） |
| `current_time_short` | `template`、`enabled` | 同一激活内**后续**模型调用追加的短时间戳（`YYYY-MM-DD HH:MM:SS`） |
| `avoid_repeat` | `template`、`enabled` | 防重复提醒：**每次管线激活只追加一次**（紧跟时间块之后） |
| `silent_nudge` | `template`、`enabled` | 长任务沉默提醒文本（模型长时间只调工具不回复时由机制注入的 user 提醒） |
| `group_chat_resume` | `template` | 群聊挂起恢复说明 |
| `new_member_profiles` | `template` | 新出现的群友档案块 |
| `native_vision` | `template`、`enabled` | 原生视觉说明（仅主模型支持原生视觉时追加到 system 末尾） |
| `tool_result_compressed` | `template` | 基础回复类工具压缩后的文案 |
| `tool_result_compressed_detail` | `template` | 其它工具压缩后的文案（含结果摘要） |
| `long_reply_fallback` | `template` | 回复过长时的兜底回复 |
| `wake_up` | `template` | 睡眠中被 @ 唤醒的提示 |
| `problem_solver` | `description`、`system_prompt`、`runtime` | 解题子 Agent（英文提示词） |
| `self_heal` | `description`、`system_prompt` | 自修复子 Agent |
| `maintenance` | `system_prompt` | 沙箱维护子 Agent |

子 Agent 的 `problem_solver.runtime` 是子表，用于运行时动态信息（同级 Agent 描述、
超时时间、最大轮次、当前任务模式），同样可自定义：

```toml
[problem_solver.runtime]
template = \'\'\'
{peer_descriptions}
- 超时时间: {timeout_seconds} 秒
- 最大模型轮次: {max_iterations}
{mode_note}
\'\'\'
```

## 占位符与转义

1. **占位符**写作 `{名字}`，渲染时替换为运行时内容。未提供值的占位符**原样保留**，
   便于发现写错的占位符。
2. **转义**：需要输出字面量花括号时写成双花括号 —— `{{` 渲染为 `{`，`}}` 渲染为 `}`。
   例如 `示例:{{msg_id=123}} 1: 小明: 你好` 渲染为 `示例:{msg_id=123} 1: 小明: 你好`。
3. **空区块自动删除**：只含空白的 XML 风格区块（如群友信息标签之间只有换行）渲染后会被移除，
   因此可以放心把可选区块写在模板里，没有内容时不会留下空壳。
4. **畸形花括号降级**：模板含单个 `{` 或 `}` 时降级为「只替换已知占位符」，
   不会导致整轮回复失败。
5. **不重复渲染**：把 `{member_list}` 之类的占位符写进 system 模板，内容就留在 system 里，
   并且不再重复出现在上下文 user 块中（反之亦然）。

### 常用占位符

| 类别 | 占位符 |
|---|---|
| 身份 | `{bot_name}` `{bot_account}` `{other_name}` `{bot_data}` |
| 群聊 | `{group_name}` `{group_id}` `{group_description}` `{group_admin}` `{bot_group_admin_status}` `{group_info}` `{member_list}` |
| 私聊 | `{friend_name}` `{remark}` `{profile}` `{friend_info}` |
| 记忆/印象 | `{key_word_reaction_list}` `{memory_list}` |
| 消息格式 | `{numbering_guide}` |
| 时间 | `{current_time}`（完整句子） `{current_datetime}` `{current_date}` `{current_weekday}` `{lunar_date}` `{timezone}` |
| 工具压缩 | `{tool_name}` `{summary}` `{original_chars}` |
| 挂起恢复 | `{new_member_profiles}` `{member_profiles}` |
| 解题 Agent | `{timeout_seconds}` `{max_iterations}` `{peer_descriptions}` `{mode_note}` |

各分区的完整占位符清单以 `default/prompts.toml` 内的分区注释为准。

## 关闭某个区块

任意分区都支持 `enabled = false`（也接受 `"false"`、`"否"`、`0` 等写法）：

```toml
[current_time]
enabled = false
```

## 工具输出压缩

长会话中工具返回会不断累积。NeoBot 在**重新构建/续用提示词的新一轮开始前**压缩较早的
工具返回：只保留最近 `chat.tool_result_full_keep` 条（默认 10）完整内容，其余按工具类别压缩。

- 基础回复类工具（`send_reply`、`wait`、`cancel`、`send_emoji` 等，见
  `reply/tools.py` 的 `BASIC_REPLY_TOOLS`）只保留「调用成功」，不再保留具体内容；
- 其它工具保留一段结果摘要，长度由 `chat.tool_result_summary_chars`（默认 200）控制。

压缩只改写工具消息的 content，不改动消息顺序，因此 assistant 的 `tool_calls` 与
`tool` 结果消息始终一一配对；已压缩过的条目按 `tool_call_id` 去重，不会重复处理。
压缩文案由 `[tool_result_compressed]` / `[tool_result_compressed_detail]` 提供。

## 主 Agent 提示词中的历史一致性约束

默认的 `[group_chat]` / `[friend_chat]` 模板包含 `<历史一致性>` 区块，明确三条规则：

1. 对话中 assistant 角色的消息就是 Bot 自己说过的话，**已经回答过的内容在没有新要求时不再回答**；
2. 回答不能忽略自己之前说过的话，新回复必须与之前的表态/结论/承诺一致；
3. 消息行首的 `[msg_id=...]`、消息编号、发送者名字以及 `[被回复消息]` 等标记都是系统为了
   引用而自动生成的标注，**不属于消息正文**；使用 reply 工具引用回复或复述原文时，
   只能使用消息正文本身，禁止把系统标注一起发出。

## 长任务过程可见性（`long_task_progress`）

Agent 执行长任务（后台任务 / 绘图 / 解题 / 批量操作 / 浏览器 / 沙箱等）时容易**长时间一声不吭**，
用户侧体感就是「Bot 卡死了」。这一层用两件事解决：

1. **静态规则**：`[long_task_progress]` 追加型分区（群聊与私聊都追加），要求模型
   「开工前用 `send_reply` 说一句、中途报进度、不报流水账」，并显式声明这条优先于
   「成功就不必再告知」的通用规则（**仅限长任务的开工与进度**，不豁免其它重复回复约束）。
   它在 `prompt/builder.py` 里按 `friend_chat_hint` 的先例追加，因此**即使部署方把整段
   `[group_chat]` 复制进 `custom/prompts.toml`，本分区仍然生效**。
2. **机制兜底（沉默提醒）**：模型仍然不说话时，由 orchestrator 主动注入一条 `[silent_nudge]` 提醒。

另外 `[group_chat]` / `[friend_chat]` 的 `<回复要求>` 里补了一条通用原则：需要时间的事情要适时
回话；同时把「如果成功就不需要再告诉对方你完成了」**限定为任务收尾后**，避免它压制长任务中的进度汇报。

## 沉默提醒（nudge）

与上面的静态规则**互补**：静态规则告诉模型「该说」，nudge 在它仍然不说时推一把。

| 项 | 说明 |
|---|---|
| 触发条件 | **轮次**：自上次回复/上次提醒以来连续工具调用轮数达到阈值；**或时间**：自本轮开始（或上次提醒）起超过 `chat.silent_nudge_seconds` 且期间从未调用过回复工具 |
| 阶梯阈值 | 首次 `silent_nudge_first_rounds`（默认 5）轮；之后每次再累积 `silent_nudge_repeat_rounds`（默认 10）轮 —— 提醒点落在累计第 **5、15、25…** 轮，而不是每 5 轮一次 |
| 刷新 | 每次提醒后轮次归零、时间基准重置、阈值切到 repeat |
| 上限 | 单次回复事件内最多 `silent_nudge_max`（默认 3）次；达到上限后停止提醒，**不做兜底回复** |
| 清零 | 只要调用过 `send_reply`（`reply_sent`）就清零计数与时间基准，不再提醒 |
| 注入形式 | 一条 `role=user` 的消息，文本来自 `[silent_nudge]` 分区（可在 `custom/prompts.toml` 覆盖，`enabled=false` 时完全不注入） |
| 适用范围 | 群聊与私聊共用同一段 Agent 循环，因此两边都生效 |
| 关闭 | `chat.silent_nudge_enabled = false`，或把 first_rounds / seconds 设为 0 |

> **与 120s 静默看门狗的区别**：`chat.group_agent_silent_timeout_seconds` 测的是**两次活动之间的空档**
> （模型/工具每次返回都会重置），超时后果是**强杀管线**；nudge 测的是**对用户可见的回复缺失**，
> 后果只是**注入一条提醒**。10 轮快速工具调用（每轮都 <120s）能躲过看门狗，但躲不过 nudge。
> 两者语义不同、互不干涉。

## 防止重复（`avoid_repeat` 与时间块分级）

- `[avoid_repeat]`：每次**管线激活**时追加一次（不是每次模型调用），位置紧跟时间块之后。
  它贴近决策点重申「不要重复执行已完成的工作、不要反复回答已回答的话；已经开始但没做完的，
  在没人问的情况下不需要再告知已经开始」。软重启导致 assistant 块丢失时，这层是提示词级的缓解。
- **时间块分级**：同一激活内**第一次**模型调用注入完整 `[current_time]`，**之后**只注入
  `[current_time_short]`（`YYYY-MM-DD HH:MM:SS`），长管线（上限 200 轮）下显著降低重复度。
  新一轮激活会重新注入一次完整时间块。两段各有独立开关：关闭 `[current_time]` 即不再有任何时间注入
  （此时也不会单独出现短时间戳）。

## 网页面板编辑

网页面板「提示词模板」页可以直接编辑这些分区：

- 左侧列出合并后的全部可编辑键；右上编辑，右下**实时预览**模拟取值渲染后的内容
- 保存只写 `data/prompts/custom/prompts.toml`（默认文件不动），写前备份 `.bak`；
  「恢复默认」删除覆盖项
- 预览会还原 `{{` / `}}` 转义、删除空区块，并列出没有模拟取值的占位符

「聊天流」页则可以查看每条聊天流最近一次发给模型的 system 提示词、消息列表与后台任务；
该页还提供**完整提示词历史**（按聊天流过滤）：每次模型请求的完整 messages 会落盘保存
（目录 `<DATA_DIR>/chat_flows/prompts/`，全局保留最近 `chat.chat_flow_prompt_history_limit` 份，
默认 100），默认视图仍是内存里的「最近 80 条」快速预览，**展开/切换某一份时才读盘**，
且完整视图不做任何截断。
