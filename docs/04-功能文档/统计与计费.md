# 统计与计费

NeoBot 跟踪 LLM 调用用量与费用，提供余额查询与费用报告，帮助控制运行成本。

## 用量统计（`app/src/neobot_app/statistics/`）

- [tracker.py](../../app/src/neobot_app/statistics/tracker.py)：模型用量记录（输入/输出 Token、缓存命中 Token）
- [reporter.py](../../app/src/neobot_app/statistics/reporter.py)：费用报告生成
- [balance.py](../../app/src/neobot_app/statistics/balance.py)：余额检查（BalanceChecker）

## 模型计费配置（`models.registry[].pricing`）

模型库中的每个模型可配置：

```toml
[[models.registry]]
key = "deepseek-v4-pro"
# … provider / model_name / settings …

[models.registry.pricing]
input_price_per_mtokens = 0.0     # 输入价格（每百万 Token）
output_price_per_mtokens = 0.0    # 输出价格（每百万 Token）
cache_hit_price_per_mtokens = 0.0 # 缓存命中价格（每百万 Token）
billing_metric = ""               # 非 Token 计费模型的平台计费标识（如 TTS 按字符）
```

计费币种为 CNY（数据库迁移 [`0018_rename_cost_usd_to_cny.py`](../../packages/storage/src/neobot_storage/alembic/versions/0018_rename_cost_usd_to_cny.py)）。

## 可脚本化的消耗计费（`[billing]` + `billing_script`）

固定单价（线性三项求和）表达不了峰谷定价、阶梯、按次、汇率、折扣等真实口径，因此
「金额怎么算」可以交给**用户自己写的计价脚本**。脚本**按模型条目绑定**，默认**关闭**。

### 全局段 `[billing]`

```toml
[billing]
enabled = false          # 是否启用按模型绑定的计价脚本；关闭 = 全部模型走既有固定计费公式
timeout_ms = 200         # 单次脚本求值超时（毫秒）；超时即放弃脚本结果、改用固定计费并告警
reload_on_change = true  # 脚本文件修改时间（纳秒）或大小变化时自动重载，无需重启
record_detail = true     # 是否把脚本返回的分项（components / note）写入 cost_detail 列
```

- 关闭时**零额外开销、零风险**：不加载任何脚本、不创建线程池，行为与改造前逐位一致。
- 改 `[billing]` 段**无需重启**（面板「保存并重载」后立即生效）。

### 模型条目：`billing_script` + `billing_config`

```toml
[[models.registry]]
key = "deepseek-v4-pro"
provider = "DeepSeek"
model_name = "deepseek-flash"
billing_script = ""       # 留空 = 该模型走固定计费；填写 = 用 <数据目录>/Billing/<名字>.py
# billing_config = { price_per_call = 0.01 }   # 可选：传给脚本的参数表

[models.registry.pricing]
input_price_per_mtokens = 2.0
output_price_per_mtokens = 8.0
cache_hit_price_per_mtokens = 0.5
```

- 计价脚本**绑定在模型条目上**（一模型一脚本）；多个模型可以引用**同一个名字**，
  脚本只加载一份，用各自的 `billing_config` 定不同的价。
- `billing_script` / `billing_config` 落在 `models` 段，改它们走「面板保存并重载」路径。

### 脚本契约

脚本放在 `<数据目录>/Billing/`，按名解析 `<name>.py` 或 `<name>/__init__.py`，二选一入口：

```python
# 函数式（推荐给简单场景）
def compute_cost(ctx):
    return 0.01            # 返回 float = CNY 金额

# 类式（需要缓存 / 表格时；构造时按签名注入 config / logger）
class BillingPolicy:
    def compute(self, ctx):
        return {"cost_cny": 0.01, "components": {"per_call": 0.01}, "note": "按次计费"}
```

返回值可以是 `float`（CNY 金额），也可以是 dict：`cost_cny`（必填）、`components`（分项）、
`note`（一行说明）、`source`（默认取脚本名）。**负金额合法**（退款 / 抵扣 / 赠币返还），
原样落库；面板对该笔标注「冲抵」，报表 `SUM` 因此可能出现负值。

`ctx` 是**只读纯数据**（`MappingProxyType` + 深拷贝），字段：

| 键 | 内容 |
|---|---|
| `model_key` / `model_name` / `provider` / `model_type` | 注册 key、供应商模型名、供应商名、模型类型（`model_key` 是区分同名模型条目的唯一依据） |
| `module` | 调用模块（`reply_agent` / `reply_common` / `agent:*` …） |
| `usage` | 原始用量：`input_tokens` / `output_tokens` / `cache_hit_tokens` / `cache_miss_tokens` / `completion_tokens_details` |
| `pricing` / `settings` | 该模型条目的价格表与运行参数原文 |
| `billing_config` | 该模型条目的脚本参数 |
| `conversation` | `{"kind": group/private/"", "id": ...}` |
| `occurred_at` / `local_time` / `tzname` | UTC 时间 ISO8601 / 本地时间 ISO8601 / 时区名（峰谷判定必须用本地时间） |

**框架不向脚本注入任何 I/O 能力**（没有 provider、没有数据库会话、没有服务对象）。
脚本如果自己联网属于用户越界，框架不为其负责，也不做沙箱——与 `willing` 自定义脚本同级的信任模型。

**兜底**：脚本缺失 / 加载失败 / 抛异常 / 超时 / 返回值非法（NaN、Inf、None、缺 `cost_cny`）
一律**回落固定计费公式**，绝不中断用量落库，也绝不反噬回复管线：

| `cost_source` | 含义 |
|---|---|
| `builtin` | 模型未绑定脚本，或 `[billing].enabled=false` |
| `script:<name>` | 脚本正常返回 |
| `fallback:missing` | 绑定了名字但文件不存在 |
| `fallback:error` | 脚本抛异常 / 返回值非法 / 加载失败 |
| `fallback:timeout` | 超过 `timeout_ms` 未返回 |

### 内置模板（启动时同步到 `<数据目录>/Billing/`）

| 模板 | 用途 | 需要的参数 |
|---|---|---|
| `deepseek_peak_valley.py` | 峰谷定价：高峰 = 北京时间周一至周五 09:00-12:00、14:00-18:00，其余空闲；空闲价 = 高峰价 × 0.5 | 无 |
| `per_call.py` | **按次计费**基础模板：每次调用固定金额，与 Token 数无关 | `billing_config.price_per_call` |

> ⚠️ 峰谷模板假定 **`pricing` 填的是高峰价**（DeepSeek 默认价目表就是高峰价），空闲时段打 5 折。
> 如果把 `pricing` 填成均价，金额会系统性偏小。

模板只在「文件不存在」或「内容仍是本程序上次写入的版本」时同步；**用户改过的文件不会被覆盖**
（同名旧内容哈希记在 `<数据目录>/Billing/.templates.json`）。

### 面板与报表

- **模型编辑弹窗「计费」区**：脚本下拉（内置模板 + `<数据目录>/Billing/*.py`，含「留空 = 固定计费」）、
  `billing_config` 键值行、只读试算按钮；模型列表行显示「脚本: xxx」或「固定计费」标签。
- **面板「用量统计」页**：新增「最近调用（计费来源）」表，来源列显示
  `固定计费` / `脚本: xxx` / `兜底: 原因`，分项在点「展开」时按需读取；负金额标注「冲抵」。
- **费用报告**（`data/费用统计/费用统计-*.md`）：新增一节「计费来源分布」（脚本 / 内建 / 兜底 计数与金额），
  既有三张统计表的数值不变。

### 接口

| 接口 | 说明 |
|---|---|
| `GET /api/config/billing` | 全局策略、可用脚本清单（内置模板 + 用户脚本）、每个模型条目的绑定情况与加载错误 |
| `POST /api/config/billing/reload` | 显式重载脚本（**需管理权限**），返回每个脚本的加载结果与错误详情 |
| `POST /api/config/billing/preview` | **只读试算**（不写库）：传 `{model_key, usage, occurred_at}`，也可直接传 `billing_script` + `billing_config`；用于保存前验证峰谷边界与按次定价 |

> 历史金额**不重算**：脚本演进不会让旧账单跳变，新增的 `cost_source` / `cost_detail` 列用于区分来源。

## 面板用量图表

网页面板的「用量统计」页读取 `GET /api/series/usage?hours=<小时数>&bucket=hour|day`：

- `points`：按小时/天分桶的金额（CNY）、输入/输出 Token、缓存命中 Token 与调用次数；
- `models` / `modules`：按「供应商 + 模型」与调用模块的金额排行（各取前 12）；
- `totals`：所选窗口内的合计值；数据库不可用时返回 `available = false`，页面显示空状态。

聚合在存储层用 SQL 完成（`SqlAlchemyUsageRepository.series_since` 等），面板不拉取原始记录。

## 数据存储

- 模型用量记录表：数据库迁移 [`0017_add_model_usage_records.py`](../../packages/storage/src/neobot_storage/alembic/versions/0017_add_model_usage_records.py)
- 缓存命中 Token 字段：[`0019_add_cache_hit_tokens_to_usage.py`](../../packages/storage/src/neobot_storage/alembic/versions/0019_add_cache_hit_tokens_to_usage.py)
- 计费来源与分项：[`0025_add_usage_cost_source.py`](../../packages/storage/src/neobot_storage/alembic/versions/0025_add_usage_cost_source.py)
  - `cost_source`（默认 `builtin`，**闭集**见上表）：存量行自动填充为 `builtin`；
  - `cost_detail`（nullable，单行 JSON）：脚本返回的 `components` / `note`，超过 8192 字符即截断并标记 `truncated`；
  - `cost_cny` 的**语义与类型完全不变**（仍是可直接 `SUM` 的标量），因此既有聚合 SQL、报表与面板数值零改动。

## 余额 Skill

- `deepseek_balance` Skill（BalanceSkill，`name = "deepseek_balance"`）：Agent 可查询 DeepSeek 账户余额；仅在 `enable_balance_check` 开启且 DeepSeek 已配置时注册
- 在费用敏感场景（如自修复 Agent 日限额）中用于防止费用失控

## 费用控制相关配置

- 自修复 Agent：`agent.self_healing.daily_limit`（默认每日 5 次）
- 后台绘图：`agent.creator.drawing.max_tasks_per_pipeline` 等任务上限
- 定时任务：`scheduled_task.max_repeating_tasks`（默认 15）
