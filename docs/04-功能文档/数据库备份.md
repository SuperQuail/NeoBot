# 数据库备份

`neobot_storage.backup_sqlite_database(db_path, backup_dir)` 使用 SQLite 在线备份 API 复制数据库，包含已经提交但尚未 checkpoint 的 WAL 数据。调用方显式传入源库和备份目录；成功返回快照路径，源库不存在或复制、发布失败时返回 `None`，失败会记录警告。

## 命名与完成时机

公开快照名为 `<源库名>_<日期时间与毫秒>_<随机后缀>.db`。时间戳用于识别时间，不承担唯一性：即使连续或并发调用发生在同一毫秒，也不会覆盖已有快照。

复制先写入同目录的隐藏暂存文件。SQLite 连接关闭后，独占创建零字节目标占位，再把完整暂存原子替换到本调用持有的占位。已有目标不会被覆盖，命名碰撞会重新分配；复制或发布失败会清理本次暂存和占位。不依赖硬链接能力。

## 保留策略

默认保留同名源库最近 5 份公开快照，`max_backups <= 0` 时不自动清理。排序先比较文件修改时间的纳秒值，时间相同时按文件名形成稳定顺序；旧命名的快照仍参与保留策略。

隐藏暂存和发布前的零字节占位不计入保留数量，另一备份仍在写入或发布时不会被清理。SQLite 在线备份即使源库为空也会生成非空数据库。并发清理已经删除的文件会被跳过，其余快照继续检查。

本功能只生成数据库快照；恢复时应停止使用目标库的进程，并由维护者按实际部署执行恢复。存储与迁移流程见 [存储流程图](../flow/22-storage-migrations.md)。
