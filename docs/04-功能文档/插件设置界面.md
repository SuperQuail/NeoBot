# 插件配置表单与自定义页面

插件界面只有两条路径：**配置表单**由宿主根据配置模型自动渲染固定控件；**插件页面**由作者编写 HTML，在 sandbox iframe 中运行。普通配置不需要 Node，也不需要额外声明一套界面 Schema；选群、预览、订阅等业务流程放在自定义页面，不再由宿主推断业务布局。

顶部使用一组平级模式：「配置表单」「TOML」「插件页面」。没有声明页面时隐藏「插件页面」；进入后直接显示页面，不再提供展开／收起。单页不重复显示分组标题，多页以标题和分隔线区分；首次访问时挂载，切换模式或打开说明书只暂停，不清空原输入。

## 自动配置表单

```python
from pydantic import BaseModel, Field
from typing import Literal
from neobot_modloader import Plugin


class Config(BaseModel):
    """配置模型同时约束存储值和面板输入。"""

    interval: int = Field(default=60, ge=15, le=3600, title="检查间隔（秒）")
    enabled: bool = Field(default=True, title="接收通知")
    delivery: Literal["instant", "digest"] = Field(
        default="instant",
        title="通知方式",
        json_schema_extra={"option_labels": {"instant": "立即发送", "digest": "汇总发送"}},
    )
    endpoint: str = Field(
        default="",
        title="服务地址",
        description="填写插件访问的服务地址。",
        json_schema_extra={"single_line": True, "placeholder": "https://…"},
    )


plugin = Plugin("example", config=Config)
```

| Python 类型 | 固定宿主控件 |
| --- | --- |
| `bool` | 开关 |
| `int`、`float` | 数字输入 |
| `str` | 自适应文本框；`single_line=True` 固定为单行输入 |
| `Literal`、`Enum` | 严格下拉，保留数字、布尔等原始值类型 |
| 嵌套 `BaseModel` | 配置分组 |
| `list[BaseModel]` | 可增删、复制和调整顺序的对象列表 |
| `list[str/int/float/bool]`、`dict` | 列表、键值编辑 |
| `SecretStr`、`SecretBytes` 或显式敏感字段 | 只写密码输入，不回读真实值 |
| 无法无损展开的联合、递归或特殊结构 | 保留原始类型的 JSON 编辑 |

开发者只控制以下声明，不提供自定义控件、任意布局、CSS 或脚本注入入口：

- `Field(title=..., description=...)`：中文标签和简短说明；默认值与模型字段顺序沿用 Pydantic。
- Pydantic 类型、枚举与 `ge/le/min_length/max_length` 等约束：决定固定控件和保存校验。
- `Field(frozen=True)` 或 `json_schema_extra={"readonly": True}`：表单只读提示；这不是服务端授权规则。
- `json_schema_extra={"option_labels": {...}}`：只改变枚举的显示名称，不改变值。
- `json_schema_extra={"single_line": True, "placeholder": "…"}`：仅用于非敏感的普通字符串；不能把数值改成文本，也不能覆盖密钥控件。

表单的恢复默认、未保存草稿、保存、版本冲突、权限和密钥脱敏由宿主处理。配置保存到 `plugins_data/<插件名>/config.toml`，模型和清单只是默认值来源。没有配置模型时仍可从 TOML 值与注释生成表单；无法使用表单的内容可在允许源码编辑时使用 TOML。

## 自定义 iframe 页面

需要业务按钮、动态候选、预览或列表交互时，直接声明页面：

```python
plugin.view(
    "subscriptions",
    title="直播订阅",
    entry="web/subscriptions/index.html",
    anchors=["target", "preview"],
)
```

清单同时列出分发入口，然后重新导出契约：

```toml
[sdk]
version = 1
contract = "plugin.contract.json"
pages = ["web/subscriptions/index.html"]
```

```powershell
uv run --no-sync python -m neobot_modloader.sdk export path/to/plugin
uv run --no-sync python -m neobot_modloader.sdk check path/to/plugin
```

模式 Tab 合并为一组：提供「配置表单」和「TOML」；当插件声明了 `view` 自定义页面时，右侧自动出现「插件页面」，未声明的插件默认隐藏。页面操作即时调用业务接口；底部的配置保存只用于配置表单。切换回配置表单或 TOML 时，已访问页面保留输入并暂停；尚未访问的页面按需加载。

## 优先使用宿主组件样式

在页面入口引用 `_ui.css` 和 `_sdk.js`，不复制宿主文件，也不需要安装前端框架：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>直播订阅</title>
    <link rel="stylesheet" href="_ui.css">
    <script src="_sdk.js"></script>
    <script defer src="app.js"></script>
  </head>
  <body>
    <main class="nb-view nb-stack">
      <div id="target" class="nb-field">
        <label for="url">订阅地址</label>
        <input id="url" name="target" type="url" placeholder="https://…">
        <p class="nb-help">填写要接收更新的页面地址。</p>
      </div>
      <div id="preview" class="nb-actions">
        <button class="nb-primary" type="button" id="load">预览通知</button>
      </div>
    </main>
  </body>
</html>
```

| 组件样式 | 用途 |
| --- | --- |
| `nb-view` | 内容根节点，不额外叠加卡片背景与边框 |
| `nb-stack` / `nb-grid` | 纵向布局 / 窄屏自动单列的双列字段 |
| `nb-field` / `nb-help` | 字段标签、控件与说明 |
| `nb-inline` / `nb-actions` | 同行控件 / 可换行操作组 |
| `nb-section` / `nb-section-heading` | 业务分区与标题 |
| `nb-primary` / `nb-quiet` / `nb-danger` | 主操作 / 次操作 / 危险操作 |
| `nb-empty` / `nb-table-wrap` | 空态 / 必要的表格横向滚动 |

原生输入、选择、按钮、表格及其焦点、禁用状态均有共享样式。**优先使用这些组件约定**，业务 CSS 只补自己的内容结构，不另外维护一套基础控件。

## 主题与宿主桥接

**自定义页面必须响应宿主主题，不能只适配一种明暗配色。** `_sdk.js` 在握手和主题切换时自动将宿主颜色、字体、控件尺寸等 CSS 令牌应用到 iframe 根节点，并同步 `color-scheme`；采用 `_ui.css` 的控件无需手动刷新。业务样式使用 `var(--text)`、`var(--muted)`、`var(--panel)`、`var(--brand)`、`var(--border)`、`var(--surface-field)` 等令牌，主按钮文字使用 `var(--text-on-brand)`，不要写死页面背景、正文或按钮文字颜色。

绘图等非 CSS 内容通过 `NeoBotPlugin.onContext()` 响应 `context.theme`、`colorScheme` 和 `reducedMotion`。同一回调也接收权限、可用性和 `suspended` 更新；页面应在暂停时停止轮询、禁用真实操作，在恢复时继续使用原输入。订阅回调返回取消函数，页面卸载时调用。

配置重载可能在页面隐藏时重建 iframe。首读应延后到可用且未暂停时执行，并在恢复事件补齐初始化；不能把跳过的首读记为成功。群目录等外部连接失败也不应阻止读取或管理本地已有记录。

页面只通过 `NeoBotPlugin` 访问宿主：

- `ready()`：等待握手并获取当前上下文。
- `action(id, values)`：调用本插件已声明动作，仍经过服务端权限和插件操作锁。
- `getConfig()` / `saveConfig(values, revision)`：与自动表单共用配置文档、脱敏和版本冲突规则；冲突时保留草稿，不盲目覆盖。
- `notify({title, message, tone})`：统一显示全局 InfoBar，不在页面重复弹出相同提示。
- `registerAnchor(id, element)`：为 `view.<页面>.<锚点>` 教程目标注册真实元素。

不要访问宿主 DOM、登录凭据或绕过桥接自行请求管理 API。iframe 不授予 `allow-same-origin`，只分发入口同目录的公开静态资源，CSP 禁止页面直接联网调用接口。

页面根节点采用自然内容高度，避免 `100vh`、固定最小屏高或全页内滚动；SDK 自动上报高度，正文只有一条滚动条。局部图片预览、代码和宽表格可以保留必要滚动。打开说明书时真实页面保留并暂停，演示拥有独立会话，只读作者提供的合成数据，不执行真实写动作。

完整业务示例见 `app/src/neobot_app/builtin_plugins/streaming_parser/web/subscriptions/`，页面声明和教程分别位于 `panel.py`、`panel_guide.py`。

## 从零填写表单的说明书

`plugin.guide()` 的步骤可用 `form` 声明完整配置表单的教学阶段：

```python
plugin.guide(
    "config-basics",
    title="从零填写配置",
    steps=[
        {"target": "config", "form": "start", "text": "从公开默认值开始。", "example": {}},
        {"target": "config.interval", "form": "edit", "text": "填写检查间隔。", "example": {"interval": 30}},
        {"target": "config.interval", "form": "validate", "text": "检查样例数值范围。", "example": {"interval": 30}},
        {"target": "config", "form": "save", "text": "找到保存位置。", "example": {"interval": 30}},
        {"target": "config", "form": "saved", "text": "说明真实保存后的生效规则。", "example": {"interval": 30}},
    ],
)
```

`form` 只允许 `start/edit/validate/save/saved`，仅用于有配置模型的 `config` 或 `config.<字段>`，不能与聊天命令混用。宿主复用完整 `SchemaForm`；字段目标仍定位具体控件，根目标定位表单或模拟保存区。未带 `form` 的旧字段说明保持单字段展示。

每一步的 `example` 是独立快照，不继承上一章输入；未声明值只取可公开默认值或空值，递归清除真实配置、列表数据与敏感样例。凭据始终留空。`validate` 仅演示本地数值边界，不替代后端完整校验；保存阶段只显示教学状态，不请求配置保存或真实动作。作者应覆盖初始表单、逐项填写、错误与修正、保存及生效，并检查后退、跳章和重播。

自定义业务页面同样应在 `onGuideStep()` 中重建完整合成快照，包括群选择、链接、设置、预览和列表；不能只更新当前高亮部分而保留后续章节状态。直播示例的配置表单教程位于 `panel_form_guide.py`。


## 从旧业务设置声明迁移

`plugin.settings()`、契约 `settings` 和 `settings.*` 教程目标已移除，不保留兼容层。保留原配置模型和 `action/resource` 声明，将业务界面改为 `plugin.view()` 页面；清单补充 `sdk.pages`，教程目标改为 `view.<页面>.<锚点>`，重新执行 `export`。旧静态契约会被检查器拒绝，不能只删契约字段而保留旧页面逻辑。

## 验收

- 桌面和手机分别检查配置表单、自定义页面、空列表和长列表。
- 切换明暗主题，确认 iframe 内控件和业务样式即时更新。
- 切换页签和开关说明书后输入保留，暂停期间不执行真实动作；插件页面没有折叠入口。
- 增删内容后 iframe 高度随内容变化，不出现额外正文滚动条。
- 验证只读、忙碌、配置冲突和密钥只写边界；业务操作不触发配置保存。
- 重新导出契约并运行插件工程检查、打包；修改宿主前端后重建 `web/` 分发资源。
