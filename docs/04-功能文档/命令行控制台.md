# 命令行控制台与同实例开发

独立的 NeoBot CLI 提供 Textual 操作界面和非交互命令。控制台连接当前实例；
创建插件、开发和日常使用共用一个机器人进程，不另外启动演示 Bot。
已有 `neobot` 命令仍表示运行机器人。

控制台源码与使用说明见 [NeoBot-CLI](https://github.com/SuperQuail/NeoBot-CLI)。

## 实例与环境

实例的数据目录以 `NEOBOT_DATA_DIR` 或现有宿主路径规则为准。插件目录以
`config.toml` 的 `plugins.dir` 为准，相对路径相对于数据目录；插件运行数据仍在
`plugins_data/<name>/`。控制台应读取状态接口中的绝对 `plugin_dir`，不能假定
插件总在当前工作目录的 `plugins/`。

同一个数据目录由操作系统文件锁保护，第二个 `neobot` 进程会拒绝启动。进程崩溃后
锁随句柄释放；锁文件存在不表示实例正在运行，也不能据此杀死某个 PID。
控制台退出只断开客户端，停止宿主必须显式请求。

## 创建插件并开发

控制台从模板创建本地工程，再请求当前宿主加载该工程并开启该插件的源码监听。
该过程不使用插件下载器，也不自动安装 Python 依赖。

- 开发对象必须是当前实例插件目录中的直接子目录，清单名称必须与目录名称一致。
- 首次加载先执行 SDK 静态检查；已停止或停用的插件需要先显式启动或启用。
- 未开启全局 `plugins.watch` 时，只监听已选择开发的插件；关闭开发监听不停止插件。
- 已显式开启全局监听时，复用同一监听器，关闭单个开发选择不会关闭全局监听。
- 保存 Python 源码或清单后，沿用已有候选验证、事务重载与失败保留旧代机制。
  状态接口提供重载次数、最近结果和错误，修正源码后保存即可重试。
- 声明不支持热重载的插件会明确报告需要重启。
- HTML、JS、CSS 产物更新仍由 Dashboard 的页面版本机制处理。首版自定义页面模板
  使用原生 HTML，无需 Node；额外采用前端构建工具时，需自行运行其构建命令。

依赖和 Python 环境变化由实例的 uv 工程统一记录、同步。开发监听不会在运行中
偷偷安装依赖，也不承诺通过插件重载替换已经导入的第三方库。

## 本地控制接口 v1

宿主在 `127.0.0.1` 随机端口启动控制服务，发现文件位于
`<DATA_DIR>/.neobot/control.json`。文件包含 `schema_version`、`url`、`token`、
`pid`、`instance_id` 和规范化后的 `data_dir`。文件在 POSIX 系统使用 `0600` 权限，
控制目录使用 `0700`；Windows 使用目录继承的当前用户权限。客户端不得打印、提交
或转发发现文件中的凭据。

请求必须使用发现文件中的 URL 和 Bearer 凭据。服务仅接受本机连接，拒绝浏览器
Origin 和不匹配的 Host，不提供 CORS。请求 JSON 最大 8 KiB。

| 方法与路径 | 输入 | 行为 |
| --- | --- | --- |
| `GET /v1/status` | 无 | 读取实例身份、版本、实际目录、能力和插件状态 |
| `POST /v1/plugins/dev` | `name` 字符串、`enabled` 布尔值 | 加载新建插件并选择开发监听，或只取消监听 |
| `POST /v1/plugins/reload` | `name` 字符串 | 对已加载插件执行现有事务重载，不自动安装依赖 |
| `POST /v1/stop` | 空 JSON 对象 | 请求当前宿主优雅退出 |

成功响应包含 `schema_version: 1`、`ok: true` 和 `data`；错误响应包含
`schema_version: 1`、`ok: false` 和 `error.code / error.message`。
插件状态包含 `development` 和 `reload`，后者含单调递增的 `sequence` 与
`idle / reloading / succeeded / failed` 状态。

重载请求等待依赖联动期间，若插件已被停止、停用或替换为另一代，请求返回
`409 / reload_failed`，保留新状态，不重新启动插件。需要重载时，应先确认当前状态再发起新请求。
依赖插件在前置重载期间被手动停用时，会撤销自动恢复意图；前置恢复后也不会重新启动该依赖插件。

`instance_id` 是本次宿主启动的随机身份，客户端需同时验证实例身份和数据目录，
避免向已被复用的端口派发操作。发现文件只在自己的宿主退出时清理；异常退出留下的
文件不代表服务仍然可用。

优雅退出期间 `status.data.stopping` 为 true，新写入操作被拒绝，但状态服务和实例锁
一直保留到插件清理结束。控制台不能把停止请求已接收当作宿主已经完成退出。

当前能力为 `plugin.list`、`plugin.dev`、`plugin.reload` 和 `runtime.stop`。
插件市场、搜索、远程下载和安装尚未开放，不在能力列表中，也没有可调用的安装端点。
