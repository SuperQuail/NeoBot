# 网页面板

NeoBot 的网页面板是**官方内置插件 `dashboard`**（基于 aiohttp），随主进程启停。它取代了旧版的管理员控制台（9891）与调试控制台（9981），是当前唯一的网页面板。

- 插件位置：[app/src/neobot_app/builtin_plugins/dashboard/](../../app/src/neobot_app/builtin_plugins/dashboard/)
- 配置来源：插件数据目录 `data/plugins_data/dashboard/config.toml`（与本体 `config.toml` 无关），可在面板「插件 → dashboard → 配置」里编辑
- 是否启用：`data/plugin_state.json` 里的独立记录（默认启用），**不是**配置项
- 前端：源码在插件目录 `frontend/`（React 18 + TypeScript + Vite + Tailwind CSS v4），构建产物 `web/` 随包分发，使用面板**不需要安装 Node.js**
- 前端统一验证：`pnpm run verify`（lint、类型、组件测试、构建）；隔离演示 HTTP 契约另运行 `pnpm run test:preview`。CI 沿用既有检查及 `web/` 产物一致性校验。维护边界见[架构说明](../../app/src/neobot_app/builtin_plugins/dashboard/frontend/ARCHITECTURE.md)，视觉与滚动规范见[DESIGN](../../app/src/neobot_app/builtin_plugins/dashboard/frontend/DESIGN.md)。

## 界面与表单交互

- 界面禁止使用 emoji；导航、操作与状态图标统一使用 Lucide SVG，保持一致的尺寸、描边与颜色语义。
- 面板沿用天蓝与藏蓝色系：浅色使用冷白内容层和淡蓝画布，深色使用藏蓝背景与分层表面，主要操作、选中和焦点统一使用蓝色强调。分组侧栏支持收起、手机抽屉导航，以及浅色 / 深色 / 跟随系统三种主题。主题与侧栏偏好保存在当前浏览器；侧栏可滚动，但不常驻显示滚动轨道。
- 所有业务页使用一致的内容边界、标题基线和操作区，宽屏内容上限为 1600px。页头只保留标题与操作，标题旁不再显示说明小字；手机端也优先保持标题与主要操作同行。卡片、输入框、状态提示沿用同一套间距与圆角。
- 仪表盘、机器人、用量统计、提示词分析和系统状态采用一屏总览，列表按区域分页，手机切换内容视图。消息趋势支持 7 / 30 天、日均、峰值与日期刻度。快捷部署、配置、插件、提示词、聊天流、档案、日志采用固定外层的工作区，只滚动实际列表或正文；宽表格只在表格内横向滚动。
- 全部业务页面自动更新，不再常驻显示刷新按钮；读取失败时在对应区域提供重试。页面隐藏或离线时暂停，恢复后补读；前一次请求未完成时不会重复发起。用量趋势与最近调用每分钟更新，正在查看的计费详情保持打开。
- 配置、快捷部署、插件配置、提示词和档案每 30 秒检查更新：无草稿时同步文件，有未保存内容、待填密钥或正在保存时保留编辑；输入焦点、非法 JSON 或弹窗交互期间不替换文档。请求返回前开始输入也不会覆盖；档案保留开始编辑时的保存版本。自动读取不会保存、清空输入、弹出草稿确认或重复成功提示。
- 业务页面切换、首次挂载的卡片、工作区、弹窗、手机导航与提示消息统一使用 Motion 动效；开启系统「减少动态效果」时直接呈现内容。轮询更新数值不重复触发整页入场，编辑器不会因动效重新挂载或丢失焦点。
- 登录页使用 GSAP 编排三行 NEOBOT 大字的错位、翻转与叠合开场，左侧不再显示图标、辅助说明或标签。登录表单保持可操作，手机使用上下布局；减少动态效果时直接呈现最终构图，离开页面会清理动画。
- 仪表盘系统资源用 CPU 环形仪表、内存容量条和磁盘分段占比展示当前采样，保留主机、系统、Python 与更新时间；加载、缺失、非法读数和刷新失败分别提示，不用缺失值冒充零使用率。
- 业务页面按需加载，西文字体随静态产物本地分发；中文优先使用本机 Noto Sans SC，再回退系统雅黑等字体。使用面板不依赖外部字体服务。
- 路由切换与首次读数使用对应布局的骨架占位，保留标题、列表、编辑区或图表的空间；已有内容刷新时保留内容，不用单行加载文案替换整页。
- 配置、插件、提示词与档案编辑发布统一的未保存 / 忙碌状态；页内切换使用统一确认弹窗，取消后保留草稿。本体配置将文件同步状态、运行操作和保存集中在顶部工具栏，窄屏保留保存按钮并将运行操作收入菜单；插件保留左右对齐的底部保存区。
- 保存、校验、重载等操作反馈统一显示在固定位置的全局 InfoBar，同一时间只展示一条简短摘要，完整结果与恢复操作按需打开，不撑开编辑区或重复插入提示卡。失败、冲突和需重启反馈保持可访问；详细变更缺少前后值时只显示路径与原因，不显示 `undefined → undefined`。初次读取失败等阻塞状态和字段错误仍在对应内容处提供重试或定位入口。
- 配置表单使用清晰的分组标题与字段说明；嵌套分组通过细引导线区分，窄屏自动改为单列。选中分区的名称、数量收成一行，说明与生效方式按需展开，不重复堆叠标题。普通字段不再重复显示热重载标签；「需重启 / 部分需重启」及具体原因仍保留，未声明能力的字段不会推定为可重载。已修改字段标记「未保存」。
- 字符串数组可切换紧凑标签、逐行列表与 JSON；列表除了拖拽，也可用每行的上移 / 下移按钮排序。包含对象或嵌套数组的值使用 JSON，避免可视化编辑破坏结构。
- 字典保留键值表与 JSON 两种视图。切换视图或折叠字段分组不会丢弃已输入的非法 JSON 草稿；非法内容仍保留在编辑器中，并显示错误，不写入配置值。
- 只读字段与无管理权限的表单会禁用写入控件，包括开关、候选输入、数组增删排序、键值编辑、模型参数与恢复默认；仍可切换数组 / 字典的查看视图。
- 长文本支持自动增高与放大编辑，中文输入法组字期间不会提交中间状态。字段和操作按钮提供可见的键盘焦点；开启系统「减少动态效果」后关闭非必要过渡。
- 本体与插件的 TOML 模式共用按需加载的 CodeMirror 编辑器，支持语法高亮、行号、查找替换、定位行、注释、缩进、括号补全与撤销重做。`Ctrl / Cmd + S` 沿用保存并重载流程，保存前继续进行语法与类型校验。`Tab / Shift + Tab` 调整缩进，先按 `Esc` 再按 `Tab` 可离开编辑区；工具栏提供快捷键帮助。编辑器不自动重排全文或删除注释，加载失败时仍能使用普通文本框编辑和保存。
- Agent、系统用量范围与日志模块使用统一的自定义选择器，支持键盘选择与明暗主题；日志级别筛选、选择器和搜索框共享控件高度。
- 模型库将名称与引用名、供应商型号、运行计费状态和操作分别对齐，正常状态使用轻量文字，缺少密钥或地址才强调；使用说明按需查看。模型分配单选复用统一选择器，保留推荐类型分组、跨类型选择、缺失引用和可选用途清空。
- 环境变量按统一网格对齐名称、输入值、说明和操作，密钥设置状态与值放在一起；新增行与供应商表沿用相同边界和操作列，窄屏只在表内横向滚动。
- B站独立扫码页采用同一套蓝色主题与紧凑控件，遵循面板的明暗偏好（自动模式跟随系统）；二维码始终保留浅色背景，登录过程、过期与失败提示继续使用原有状态接口。

布局、颜色、字体、滚动、组件与响应式的开发约定见 [前端设计规范](../../app/src/neobot_app/builtin_plugins/dashboard/frontend/DESIGN.md)。验证界面时应覆盖正常、长内容、空态与只读场景，以及 390px / 1366px / 1920px 三档宽度。演示夹具使用虚构内存数据，不能替代真实实例的登录、权限、保存与运行操作验收；具体预览方式见 [前端 README](../../app/src/neobot_app/builtin_plugins/dashboard/frontend/README.md)。

## 启动与访问

- 默认**开启**（`plugin_state.json` 中没有停用记录即视为启用），监听 `0.0.0.0:9981`，即默认对网络开放
- 本机访问 `http://127.0.0.1:9981/`；跨机访问 `http://<服务器IP>:9981/`
- 端口被占用时，从配置的 `port` 起**最多向后尝试 10 个端口**；改用其它端口后会在启动日志打印告警，提示同步修改插件配置里的 `port`
- 只在本机使用时可把 `host` 改为 `127.0.0.1`，收敛监听范围
- 可用 `base_path` 把面板挂在路径前缀下（如 `/neobot`），便于反向代理

### 来源 IP 白名单（`allowed_ips`）

`host` 决定「在**哪个本机地址**上监听」，`allowed_ips` 决定「**哪些来源**能连进来」。绑到 `192.168.1.5` 仍然全网段可访问，要只放行固定几台机器就配白名单：

```toml
# data/plugins_data/dashboard/config.toml
allowed_ips = ["192.168.1.0/24", "10.8.0.2", "fd00::/8"]   # 留空 = 不限制
```

- 条目接受**裸 IP**（等价 `/32`、`/128`）或 **CIDR 网段**，IPv4 / IPv6 都行
- **回环地址（本机）始终放行**：白名单是能把自己锁在门外的配置，而面板正是修复入口——配错了仍可在本机打开面板改回来
- **`/healthz` 不受白名单限制**，方便反向代理或监控从名单外的机器探活
- 名单外的来源拿到的是 `403` + `{"allowed_ips": false}`，连 SPA 外壳与静态资源都不放行；同一来源每 5 分钟最多记一条拒绝日志
- 条目**解析失败不等于放行**：该条永不匹配，效果是除本机外全拒，并在启动日志告警。这里刻意不让配置校验失败——那会让字段回落到默认值（空列表 = 放开所有）
- 反向代理部署时先开 `trust_proxy_headers`，白名单比对的是**最右一跳**的转发地址；反过来，**前面没有可信代理时别开它** —— 那样客户端可以自带 `X-Forwarded-For` 伪造来源，白名单会被绕过
- 保存后**立即生效**（下一个请求起按新名单判定），无需重启 NeoBot

## 登录（面板密码）

面板使用**登录密码**鉴权，密码不写在 `config.toml` 里，而是以 PBKDF2-HMAC-SHA256 + 随机盐保存在数据目录
`plugins_data/dashboard/auth.json`（权限 0600，不落明文）。

**未设置密码时不允许外网访问**，只能通过下面两种方式之一设置：

1. **本机设置（推荐）**：在本机浏览器打开面板，登录页会自动进入「设置面板密码」表单（密码至少 8 个字符，需二次确认）。只有回环地址（本机）能看到这个表单。
2. **超级管理员命令**：在 QQ 私聊中由超级管理员发送 `/set_password <新密码>`；留空参数则 Bot 自动生成一个随机密码并回复给你。为避免泄露，该命令**只允许私聊**使用。

其他要点：

- 设置密码后，任何来源（含本机）都需要用密码登录
- 登录成功后使用 HttpOnly Cookie 保存会话（内存态，重启即失效）；写操作需要 CSRF 令牌，由前端自动携带
- **修改密码会立即失效所有已登录会话**（会话绑定密码版本号）
- 已登录且有管理权限时，可在「系统状态 → 运行设置 → 面板安全 → 修改密码」输入当前密码和两次新密码。新密码为 8–128 个字符、至少包含一个字母或数字、首尾不能有空白；提交成功后返回登录页，使用新密码重新登录。离开编辑页进入系统状态时保留草稿确认；验证失败不会退出当前会话，取消改密返回运行设置。
- 登录失败按 IP 限速：在 `login_rate_limit_window_seconds` 窗口内失败超过 `login_max_failures` 次后临时锁定
- 忘记密码：由超级管理员再次执行 `/set_password` 重置；也可停止 NeoBot 后删除 `plugins_data/dashboard/auth.json`，再从本机重新设置

## 页面功能

| 页面 | 内容 |
|---|---|
| 仪表盘 | 运行概览（在线状态、运行时长、消息量、插件数量、延迟）、系统资源、消息趋势、最近日志 |
| 快捷部署 | 机器人身份、人设、供应商密钥、管理员与回复意愿的配置引导；查看与复制 OneBot 连接地址、生成令牌 |
| 插件管理 | 官方/第三方分组、启停、热重载、安装/更新/卸载、固定配置表单 + TOML、iframe 插件页面 |
| 配置管理 | 本体 `config.toml` 表单/TOML 在线编辑、`.env` 编辑（密钥只写不读）、一键添加 API 供应商、模型库增删改、模型分配到各调用方 |
| 用量统计 | API 消耗图表：金额与 Token 趋势、总量卡片、按模型/模块排行（近 24 小时 / 7 天 / 30 天），以及「最近调用」的来源列（固定计费 / 脚本 / 兜底）与分项展开；**曲线图支持鼠标悬停查看某一点的详细数据** |
| 系统状态 | 单屏查看进程资源、宿主服务、后台任务和模型用量；「运行设置」按组提供待机、软重启、OneBot 连接、星舰开关与修改密码，底部保留进程操作 |
| 提示词分析 | 单屏按 Agent 切换提示词组成、字符数与估算 Token；组成环图与分页来源列表并排，选择来源后阅读原文，保留截断提示和估算口径说明 |
| 提示词模板 | 在线编辑 `data/prompts/custom/prompts.toml` 覆盖项，右侧实时预览「模拟取值渲染后」的内容 |
| 聊天流 | 每条聊天流的可读名称（群名 / 昵称）、最近一次发给模型的内容（system 提示词、消息列表、后台任务），以及**完整提示词历史**（纯内存 + 逐份 diff、图片只留哈希、按需重建、不截断；默认每 5 秒跟随最新一份） |
| 档案 | 查看 / 编辑 / 删除档案记忆：表清单（含条目数、最大长度、超限数）、按 key/内容筛选的条目列表、单条全文与版本号，以及 **AI 压缩**（单条 / 批量、目标字符数、压缩历史只读快照） |
| 定时任务 | 全部定时任务列表，支持新建 / 编辑 / 启用停用 / 删除，与主 Agent 共用同一套校验；桌面使用表格，手机使用可直接操作的任务卡片；编辑弹窗采用紧凑分区与固定保存栏，手机为全高面板 |
| 机器人详情 | 昵称、QQ 号、在线状态、延迟、今日与累计消息量 |
| 日志 | 实时日志缓冲（保留 `log_buffer_size` 条） |

机器人昵称、版本和头像按 `bot_info_cache_ttl` 缓存；反向 WebSocket 建立或断开后缓存立即失效，不会继续沿用离线／在线旧结果。页面可见时，首页、机器人列表与详情按现有约 10 秒周期自动读取，无需手动刷新，也不必把缓存 TTL 改成 0。

### 插件管理

插件详情将名称、运行状态与主要操作集中在一条身份栏。顶部提供合并的平级模式 Tab：自动生成的「配置表单」及「TOML」，以及在插件声明了自定义页面时出现的「插件页面」（无自定义页面时默认隐藏）。切换 Tab 保留原输入，隐藏页面暂停业务操作，配置未保存时可返回配置表单处理草稿；底部保存区只作用于配置，不与即时业务操作混排。版本、作者、依赖与热重载能力在「插件信息」查看。左右底栏保持边框齐平；TOML 编辑区占满剩余高度，长内容在编辑器内滚动。

「插件页面」直接展示，不提供折叠；单页不重复标题，多页用标题区分。直播订阅页覆盖选群、链接识别、图文预览、群级设置、按群筛选、逐项推送开关和监听健康；说明书可从空表单开始演示订阅，以及完整配置的填写、错误与修正、模拟保存。教程重播或后退重建样例，不修改真实配置和订阅。

插件工作区的列表读取失败、运行错误、依赖／配置告警与页面暂停提示统一进入全局 InfoBar，不在侧栏或配置正文插入通知卡片。列表读取失败保留现有插件与输入；重试、重新读取及返回配置在 InfoBar 的详情中操作，重新读取未保存的配置前仍需确认。错误与告警不得挤动既有桌面布局。

- **官方插件**：随本体分发（`app/src/neobot_app/builtin_plugins/`），可启停、可重载，**不能**安装/更新/卸载
- **第三方插件**：位于数据目录 `plugins/`，可安装/更新/卸载/启停/重载
- 同名时官方插件优先，第三方副本被忽略
- 启停状态持久化在数据目录 `plugin_state.json`，是**独立记录**：既不写进插件配置，也不受插件更新影响；`plugin.toml` 的顶层 `enabled` 只是打包默认值
- **启停入口**：插件详情顶部提供「启用插件 / 停用插件」。停用会二次确认；依赖它的插件会被联动停用，前置插件恢复后自动重新加载。停用后配置仍可正常查看与编辑
- **星舰默认关闭**：未保存过显式启停状态时，星舰不加载，侧栏不显示入口。可在「系统状态 → 运行设置 → 启用星舰」切换；关闭会卸载插件并移除入口，游戏数据保留，已有显式启停选择继续生效
- **面板自身不能在面板内停用或重载**（会中断当前连接）：请把 `data/plugin_state.json` 里 `dashboard` 的 `enabled` 改为 `false` 后重启 NeoBot
- 插件配置项 `manage_plugins = false` 会关闭面板内的全部写操作（保存配置、模型库/分配、添加供应商、管理插件、重启），只保留查看

插件开发与 `PluginControlFacade` 接口见 [07-插件开发](../07-插件开发.md)。

  QQ 号、人设、群描述），`{{` / `}}` 按转义规则还原成字面量花括号，没有模拟取值的占位符会
  单独列出来提示

### 聊天流

- 会话身份和视图切换集中在紧凑工具栏，消息正文优先显示。记录与保留方式在页头「隐私与记录」中查看；system 提示词、后台任务和调用元信息按需展开或打开详情，完整内容与截断提示保留。
- 会话与档案列表统一名称、类型图标、时间和摘要的层次，选中项使用轻量底色与侧边强调，长标识可查看完整值。后台任务按名称、状态、等待数量或真实进度展示；无法识别的结构保留在「原始数据」中，不将其冒充已完成或零任务。
- 会话名称与运行状态分行；提示词历史按日期分组，每条以编号、时刻、当前/最新标记及消息数/迭代两行呈现，筛选与跟随控制集中在顶部。存储大小、驻留补丁、模型与图片等详情独立展开，不切换当前正文；完整性提示集中在正文顶部，原始 JSON 按需展开。
- 按 `group:<群号>` / `private:<QQ号>` 列出每条聊天流的最近一次运行快照，显示**可读名称**
  （群聊显示群名、私聊显示对方昵称；缺失时回落 `群聊{id}` / `QQ:{id}`，`pipeline_key` 作为副标题常驻）、
  是否运行中、模型、迭代次数、消息条数与更新时间
- 详情包含：本轮 **system 提示词原文**、**最近一次模型请求的消息列表**（system/user/assistant/tool，
  工具调用单独列出，图片只计数，超长内容标注「已截断」）、以及该聊天流的**后台任务**状态
  （绘图 / 定时任务 / 解题 / 通知中心，与回复工具 `check_background_tasks` 同源）
- 快照是**内存态、有界、只读**的，重启后清空；不落盘、不影响回复决策
- **完整提示词历史**：每次模型请求的完整 messages 会留在**内存**里
  （由 `chat.chat_flow_prompt_history_enabled` 控制，**默认开启**），全局保留最近
  `chat.chat_flow_prompt_history_limit` 份（默认 100）。该页提供历史列表（可按当前聊天流过滤）
  与「清空历史」入口；**切换某一份时按需重建**，完整视图**不做任何截断**
  （默认视图仍是内存里的「最近 80 条」快速预览）
- 完整提示词**每 5 秒自动跟随最新一份**：一轮对话跑完（回复已发出或被取消）后，面板上就是
  该轮最后一次模型调用的完整提示词，不再是上一次调用留下的旧那份；手动翻到更早的某一份后会
  停在那里（列表该项标「最新」的那条旁边给出「回到最新一份」按钮），点一下就恢复跟随
- 历史**不落盘**：逐份只存相对上一份的 JSON diff（类似 git），面板顶部显示当前常驻体积；
  图片部件在写入侧把 `data:...;base64,...` 换成 sha256 哈希（与图库去重同口径），
  审查提示词时不再搬运数 MB 的 base64。旧版本落盘目录 `<DATA_DIR>/chat_flows/prompts/`
  **不再读取**，「清空历史」会顺带删除它
- 名称解析只走 `profile_service` 的**纯 DB** 路径（群名 / 昵称），并按 60 秒 TTL 缓存：
  **不会**因为面板轮询而产生任何 OneBot API 调用；解析异常时回落 `pipeline_key` 且接口仍返回 200
- **注意：**完整提示词含**完整聊天内容（包括私聊）**，属高敏数据（仅在内存，重启即清空）；关闭
  `chat.chat_flow_prompt_history_enabled` 后不再记录

### 档案

- **左栏表清单**：来自 `SELECT DISTINCT table_name`（真实反映库内现状，不依赖静态清单），
  每张表显示条目数、最大 value 长度与**超限条目数**（对应 `agent.memory.archive.max_total_chars`）
- **中栏条目列表**：key、更新时间、字符数、内容预览；支持 `key_query` / `value_query` 筛选与分页。
  列表**不返回完整 value**，避免把大档案一次性塞进浏览器
- 表说明集中在当前表的条目区顶部；条目以 key、两行摘要、字数和更新时间分层展示，悬停时间可查看完整时间戳，选中后在右栏阅读全文。
- **右栏单条详情**：全文 + `tags` + `version` + 时间戳，提供「编辑 / 删除」
- 条目身份、版本与档案信息入口保持一行；完整 key、表名、时间、标签和删除保护按需展开。编辑/删除与目标字数/AI 压缩分组排列，手机整组换行，全文标题旁仅保留实际字数。
- **编辑**：带 `version` 提交（乐观锁）。版本不一致返回 **409 + 当前内容**，前端提示「已被他人修改」
  并让用户重新读取，**不会**自动覆盖。内部表（`memory_counter`）**禁止手工编辑**
- **删除**：硬删除（无回收站），要求**独立开关** `dashboard.allow_archive_delete`（默认 false）
  + 二次确认；被删内容会以 INFO 级别写进 `neobot.log`（含操作者 IP、表、key、字符数、预览前 500 字）
  以便追溯。此开关与模型侧的 `agent.memory.archive.allow_delete` **完全独立**
  （一个管运维、一个管模型；关掉模型删除不会连带失去面板清理能力）
- 表清单、筛选后的条目与非编辑详情每 30 秒自动读取，查询仍按当前筛选和分页执行；编辑、保存与压缩期间保护详情快照和草稿版本，不使用 5 秒级数据库轮询
- **注意：**档案含隐私数据（用户画像里有昵称/生日/城市/好感度等）。面板默认监听 `0.0.0.0`，
  写操作全部走 `_require_manage`；如需更强隔离请改 `host = "127.0.0.1"` 或加反向代理鉴权

#### AI 压缩

由总结 Agent 读全文后**整条重写**一条档案（保留事实、合并重复、只丢冗余），**不是**尾部截断。
压到目标的判定、失败保留原文与快照留痕等机制见 [记忆系统](./记忆系统.md)。

- **单条入口**：右栏详情区「AI 压缩」按钮 + **目标字符数**输入框
  - 默认值 = `GET /api/archives` 返回的 `max_total_chars`；输入用 `localStorage` 记住上次值，
    **不会**写回 `agent.memory.archive.max_total_chars`
  - 下限 `200`、上限 `max_total_chars`（`max_total_chars = 0` 时兜底 `100000`）；越界由后端返回 400
  - 目标 ≥ 当前字数 → **不调用模型**（零 token），面板提示「当前字数已不大于目标，无需压缩」
  - 内部表（`memory_counter`）**禁止触发压缩**（与禁止编辑同口径，后端也会拒绝）
- **进度与前后字数**：压缩是**后台任务**（HTTP 202 + `task_id`），前端每 2 秒轮询一次。
  进行中显示「N 字 → 目标 M 字」；完成后提示「N → M 字（目标 M，快照 id X）」；
  失败显示**失败原因**并说明「已保留原文」（模型异常 / 超时 / 没压到目标都不会留下半成品）
- **压缩期间禁止编辑 / 删除**：同一 `(表, key)` 在 `running` 期间禁用编辑与删除按钮
  （避免人工写入与模型写入互相覆盖）；后端并发写仍由既有乐观锁返回 409
- **批量入口**：页面顶部「AI 压缩（超限档案）」卡片可对当前全部超限档案批量触发，
  统一使用卡片上的目标字符数，**逐条串行**、一次最多 **20** 条（其余条目数在返回体 `truncated` 里说明）。
  面板逐条显示状态（等待中 / 压缩中 / 已完成 / 失败（已保留原文）/ 已跳过）与前后字数
- **压缩历史（只读快照）**：详情区下方列出该档案最近 **10** 份**压缩前**快照
  （时间 / 压缩前 / 压缩后 / 来源「手动压缩 / 自动压缩」/ 操作者），可「查看全文」。
  快照表只存**压缩前**字数，「压缩后」由后一份（更晚的）快照字数或该档案当前字数推得——
  中间若有人工编辑，这个推算只是近似值，仅供展示；界面上**没有**「恢复到此快照」入口，
  需要恢复时人工读取全文后走编辑接口写回

相关接口（**均走 `_require_manage`，与「编辑档案」同一判据**）：

| 接口 | 权限 | 说明 |
|---|---|---|
| `POST /api/archives/summarize` | 需管理权限 | 单条压缩；body `{table, key, target_chars}`；已开始或该档案已在压缩中 → **202** + `task_id`；目标已不大于当前字数（no-op）或预检后恰好被自动压缩抢先 → 200，不含 `task_id` |
| `GET /api/archives/summarize?task_id=` | 需管理权限 | 轮询任务状态：`running` / `done` / `failed`，含 `chars_before` / `chars_after` / `target_chars` / `error` / `snapshot_id`；缺少参数 400，未知 `task_id` 404（进程重启后状态清空） |
| `POST /api/archives/summarize/over-limit` | 需管理权限 | 批量压缩超限档案；body `{target_chars, table?}`；返回 **202** + `task_id` + `items[]` / `skipped[]` / `truncated` |
| `GET /api/archives/snapshots?table=&key=` | 需管理权限 | 只读快照列表（含 `keep_per_key`、`current_chars`、`restore_supported: false`） |
| `GET /api/archives/snapshot?id=` | 需管理权限 | 读取某份快照全文；`id` 非整数 400，不存在 404 |

> `GET /api/archives` 还会返回 `summarize_available` / `min_target_chars` / `max_target_chars`，
> 前端据此显示或隐藏压缩入口、并约束输入框范围；档案总结服务未装配时压缩入口不可用。

### 配置管理

- **本体配置**：`data/config.toml` 提供表单与 TOML 双视图在线编辑，保存前校验并备份到 `config_backup/`
- **表单层级**：嵌套对象与对象数组使用分组标题、缩进和路径表达层级；分组标题随内容滚动，避免多层标题吸附到同一位置。模型参数添加区独立横向排布，窄屏自然换行
- **热重载标记**：每个配置项/分组标注「热重载」或「需重启」（鼠标悬停可看原因）；「重载运行时配置」按钮与超级管理员 `/reload` 命令等价，重载后直接列出「已生效 / 需重启」明细；原本标注「需重启」的项改完点「软重启运行」即可生效（见下文「待机与软重启运行」）
- **撤销/重做/历史**：编辑支持 Ctrl+Z / Ctrl+Y（按钮同步显示可撤销步数），每项可查看历史数值并一键恢复
- **恢复默认值**：单项「恢复默认」与「全部恢复默认」（可撤销）
- **分组折叠**：点击分组标题左侧箭头即可折叠/展开，便于在长表单中定位
- **环境变量**：`.env`（源码安装为 `app/.env`，打包部署为可执行文件同目录）在线编辑；密钥类变量**只显示是否已设置**，输入框留空表示不修改，保存后也读不回明文
- **一键添加 API 供应商**：填平台名 + API 地址 + API Key，自动写入 `<平台名>_URL` / `<平台名>_APIKey`（Key 只写不读）；已有平台可在此覆盖更新 Key
- **模型库**：新增/编辑/删除 `[[models.registry]]` 条目（类型、描述、供应商、模型名、顶层推理强度、采样参数、价格、原生视觉、系统代理、余额查询提示）；编辑弹窗为宽布局
  - **顶层推理强度**：模型名下方的「推理强度」下拉（留空 = 沿用供应商默认）。预置主流 OpenAI 档位（`none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`，下发 `reasoning_effort`），并额外提供 **Claude 系**档位（`claude:low` … `claude:max`，下发 `output_config.effort`）；Claude 系选项在分组标题与选项文案里都标注「Claude 系」。Anthropic 供应商会自动使用 Claude 系参数名。模型库列表行与模型分配页的模型信息都会显示当前档位，并在不会真正生效时带上原因（归并后的实际值 / 思考已关闭 / 该类型不生效 / DeepSeek 不支持 Claude 系）；留空时 OpenAI / Anthropic 不下发，DeepSeek 仍走旧思考强度的兼容路径
  - **引用名（key）不用手填**：新建时按模型名自动生成（小写、非字母数字转连字符，重名自动加序号），弹窗顶部只做只读提示；调用方（主对话/Agent/视觉/TTS/生图）通过它引用模型
  - **模型类型**：对话 / 推理、生图、图像识别、语音（TTS）、其它；列表显示类型标签，模型分配按角色期望类型排序并标注
  - **供应商**：下拉选择 + 自定义，候选来自内置平台、`.env` 中已配置的平台与模型库
  - **模型名**：候选只跟随当前供应商——未拉取时列出「该供应商在模型库中已用过」的模型名；拉取成功后清空旧列表、改为该供应商 `/models` 返回的模型；两者都为空时自动切换为自定义输入框，任何情况下都可手填
  - 打开编辑器或切换供应商会自动拉取该供应商的模型列表（静默失败不打扰），也可点「拉取供应商模型」手动刷新
  - **API Key 不在模型里**：模型条目只保存「供应商名」，密钥始终来自 `.env` 的 `<供应商>_APIKey`；列表状态显示的是**供应商**凭据是否就绪
  - 保存提供「仅保存」与「保存并重载」；保存后列表立即更新，刷新页面同样可见
  - **计费区（计价脚本按模型绑定）**：编辑弹窗下方新增「计费」区
    - **计价脚本**下拉：**内置脚本** `deepseek_peak_valley`（峰谷，随代码分发、不需要文件；同名用户脚本优先）+ 模板 `per_call`（按次）+ `<数据目录>/Billing/*.py`，含「（留空 = 固定计费）」；脚本文件缺失时选项标注「文件缺失」并给出错误
    - **脚本参数**键值行：即 `billing_config`（如按次计费的 `price_per_call`），同一脚本可被多个模型复用、各自定价
    - **试算**按钮：填输入/输出 Token 与可选发生时间（本地时区，留空 = 现在），调 `POST /api/config/billing/preview` **只读**试算（不写库），显示金额、来源、分项、耗时与「固定计费对照」，可用来验证峰谷边界（12:00 整点归属）与按次定价
    - 「重载脚本」按钮调 `POST /api/config/billing/reload`（需管理权限），立即重载并回显加载失败详情
    - 脚本清单与每个模型的绑定情况来自 `GET /api/config/billing`（全局 `enabled` / `timeout_ms`、可用脚本、加载错误）
    - **注意：**计价脚本需 `[billing].enabled = true` 才生效（在该页或「本体配置」里改，属热重载）
  - 模型列表行显示「**脚本: xxx**」或「**固定计费**」标签
  - **参数区（模型参数目录）**：`settings` 只常显基础四参数
    （`temperature` / `max_output_tokens` / `timeout_seconds` / `top_p`），其余参数改为三段式按需添加
    - **基础参数**：常显、不可移除，仍在 `settings` 组里直接编辑
    - **已添加参数**：`enabled_params` 里的每一项一行（中文名 + 分组标签 + 值编辑器），可改值、可移除；
      **移除只从 `enabled_params` 删名，不删配置里的值**（提示「值已保留，重新添加即恢复」）
    - **+ 添加参数**：下拉候选按当前模型的 `model_type` / `provider` **过滤**（provider 归一化后比较：
      `DeepSeek` / `deepseek-offical` / `deepseek_official` 同一条规则），已添加的不再出现
    - **+ 添加自定义参数**：键值行（写入 `settings.extra_body`），值按 **JSON** 解析（字符串需带引号），
      解析失败即报错且不提交；键名不得以 `__` 开头（内部命名空间，保存会被拒绝）
    - **警告行**：`enabled_params` 里「不在参数目录」或「当前模型不适用」的名字会渲染成警告行
      （「已配置，但当前模型不适用」），不会静默隐藏
    - 该参数目录由后端 schema 内嵌（`kind=model_params` 伪字段），**本体配置页的模型条目同步生效**：
      两处渲染路径共用同一个后处理器，在「本体配置」里编辑 `models.registry` 也能看到同一套参数区
    - **旧配置提示**：旧 `config.toml`（没有 `enabled_params`）首次加载会按「值 ≠ 默认值」推断一次并写回，
      面板在对应模型的编辑弹窗顶部提示「已按旧配置推断，请复核」
- **模型连通性测试**：每条模型可点「测试」，检测网络可达性、鉴权与模型名是否存在，并显示请求地址、是否走系统代理、HTTP 状态与耗时（供应商不支持 `/models` 时自动改用一次最小对话请求探测）
- **模型分配**：把主对话 / Agent 编号 1-3 / 视觉 / TTS / 生图改绑到模型库中的 key；生图可多选。仍被引用的模型不允许删除
  - 按用途分组展示选择器、供应商、实际模型与必需 / 可选状态；缺失引用保留并提示修正。
  - 「已保存」表示写入文件；「运行时已注册」仅说明模型已加载。修改分配后仍需重载配置生效。

### 插件管理（面板）

- **热重载能力标注**：每个插件显示「可热重载 / 本体需重启」与「配置可热重载 / 配置需重启」；声明不可热重载的插件，重载按钮会禁用并提示重启
- **插件配置统一存放**：官方与第三方插件的配置都在 `data/plugins_data/<插件名>/config.toml`，面板渲染表单（声明了配置模型的插件用模型生成表单与校验）或直接编辑 TOML；保存后按插件的配置热重载能力决定是否需要重启
- **插件配置保存校验**：插件声明配置模型时，表单与 TOML 原文均须在写盘前通过模型校验，包括字段范围及跨字段约束；TOML 按「打包默认值 + 新原文」校验，不保留原文中已删除的旧值。校验失败返回字段位置，配置文件、备份、revision 与内存配置保持不变，也不触发重载。有效原文保留注释与格式；未声明模型的插件仍只检查 TOML 语法，含密钥的配置继续禁用源码编辑
- **停用插件的源码编辑边界**：配置模型尚不可用时，TOML 页签禁用并提示先启用、加载插件后再校验；接口也会拒绝原文写入，不会为校验自动执行停用插件入口。静态契约明确声明 `config: null`，或运行中已确认没有配置模型的插件，仍可按纯 TOML 语法编辑。没有静态契约的旧插件在停用、从未加载及重启后无法确认是否声明模型，因此暂时只保留表单编辑；模型 schema 本身不能替代 Python 跨字段校验器。过期 revision 仍优先返回 HTTP 409
- **配置与代码/状态分离**：插件目录（`plugins/`）在安装或更新时会被整体替换，配置放在插件数据目录不会丢；是否启用是 `plugin_state.json` 的独立记录，不出现在配置表单里
- **配置与本体配置解耦**：官方插件与第三方插件的配置**都**在 `data/plugins_data/<插件名>/config.toml`，不会写回本体 `config.toml` 的任何分区（面板会显示真实文件路径）
- **字段说明（注释）**：插件作者在自带 `plugin.toml` 的 `[config]` 里给每个默认值写一行注释，面板表单会把注释渲染成字段说明，并写进首次生成的 `config.toml`；保存时保留文件里已有的注释与顺序，用户自己写的说明优先
- **下载代理**：侧栏「代理设置」可切换「跟随系统 / 直连 / 自定义 HTTP 代理（地址 + 端口）」，保存写入 `config.toml` 的 `[plugins]`，下一次下载立即生效
- **安装/更新**：输入 GitHub 仓库地址即可自动下载安装（`https://github.com/owner/repo` 或 `owner/repo`），受代理设置影响
- **安装冲突：三选一，不允许静默覆盖**（spec(4) R27）：安装前先做一次**只探测不写盘**的 dry run（`POST /api/plugins/install {dry_run: true}`）。目标 ID 已存在时弹窗进入冲突态，展示**两侧来源与版本**（待安装：名称 / 版本 / 仓库；已存在：名称 / 版本 / 仓库），并提供三个选择：
  - **保留现有**：关闭弹窗，磁盘零变化（不删、不覆盖、不产生备份）
  - **替换现有插件**：只有点了这个按钮才会带 `replace: true` 再次提交；替换走既有备份路径，结果里回显 `backup_path`（旧版本被完整复制到 `plugins` 同级的 `.plugin-backups/`）
  - **取消**：同「保留现有」
  未确认替换时后端返回 **HTTP 409 + 结构化 `conflict`**（`requested` / `existing` / `message`），文案说明「只能二选一」。
- **官方插件 ID 是保留字**：manifest 的 `name` 命中 `builtin_plugins/` 下的官方插件时直接拒绝（`conflict.kind = "official"`），提示「官方插件随本体更新，不能在面板内更新」；同名第三方插件需改名。只读探测接口：`GET /api/plugins/probe?name=<插件ID>`。
- **命令重名可见**：插件因命令重名被自动改名时，插件详情页展示「原 `/status` → 实际 `/dashboard__status`（重名）」（见 [07 插件开发](../07-插件开发.md)）。
- **重载运行时配置**：等价于 `config.reload` 管理命令，也可由超级管理员在 QQ 私聊发送 `/reload`。运行时按需读取的配置立即生效；`[adapter]` 监听设置与 `[models]` / 平台密钥会**按新配置重建**（监听服务原地重启、provider 原地替换），因此补 token、换模型、改端口都不必重启进程；仅面板自身监听地址/端口、插件目录等核心构建期项仍需进程重启，TTS 等 bot 侧「需重启」项可改后点「软重启运行」生效。重载后界面会列出本次改动中「已生效 / 需重启」的明细
- **启动韧性**：缺 API Key、OneBot 尚未连上、甚至 `config.toml` 缺失必需项或格式损坏都**不会让进程退出** —— 面板始终可用；配置本身有问题时会直接进入待机（运行状态卡片写明失败详情），在面板里修好后点「软重启运行」即可
- **重启 NeoBot（进程重启）**：优雅关闭并执行进程级重启，重新加载代码与配置，磁盘历史数据保留；会短暂中断面板与平台连接（等价 `POST /api/admin/restart`）。只改配置请用「软重启运行」，改代码才需进程重启

### 待机与软重启运行

待机 = 停掉 bot 运行时（回复、记忆、后台任务、定时任务、浏览器、沙箱维护等全部停止）并释放引用，只保留核心服务：日志、配置（含热重载）、宿主服务注册表、插件运行时与网页面板、命令服务、数据库引擎（面板历史/用量仍可看）；适配器是否保持连接由 `[standby].connect_onebot` 决定。面板与命令在待机期可用，面板自身不掉线（插件运行时归核心所有，不会被停）。

「系统状态」采用单屏资源概览，宿主服务、后台任务和定时任务可切换、分页，单条完整信息可点开阅读。模型用量可切换时间范围，小屏切换「服务与任务 / 模型用量」。主机信息保留操作系统、Python、PID 和负载详情。

页头「运行设置」提供：

- 状态标签（运行中 / 待机中）与待机原因输入；待机期间页面顶部显示全局横幅（原因、操作者、已待机时长），任意页面都能一键「启动运行」
- 「进入待机」按钮；待机时该位置变为「启动运行」，执行软重启以恢复运行
- 运行中显示「软重启运行」：按当前配置在进程内**重建全部 bot 侧对象**后启动，不重启进程、面板不掉线。因此原本标注「需重启」的配置项，改完点「软重启运行」即可生效；运行期按需读取的配置项仍旧即时生效。按钮与接口**立即返回**（重建在后台进行，需要几秒到几十秒），状态由面板轮询自动刷新
- **优雅关闭慢不会让软重启失败**：关闭时要跑记忆总结（`flush_all`，单次总结预算默认 300 秒），所以软重启可能等上几分钟。窗口（`[standby].shutdown_timeout_seconds` / `resume_timeout_seconds`，默认 300 / 600 秒）到点只是记日志并继续等，**不会**中途判定失败；只有进程真的要退出、或关闭真的卡住时才会停在待机并给出原因
- 「重启进程」按钮等价 `POST /api/admin/restart`：加载代码改动，会短暂断线（面板与平台连接中断几秒到十几秒）；只想按当前配置重建运行时用「软重启运行」
- 「待机时保持 OneBot 连接」开关对应 `[standby].connect_onebot`（默认 true，见 [05-配置参考](../05-配置参考.md)）；待机期可随时切换并立即生效，运行中不可切换
- 启动即待机：`[standby].start_in_standby`（默认 false）让进程启动后直接进入待机；待机状态不跨进程恢复（避免静默哑火），但 OneBot 连接开关会持久化到 `data/standby.json`
- QQ 侧命令：超级管理员 `/standby [原因]` 进入待机、`/reboot [原因]` 软重启运行（待机中执行即恢复运行），次级管理员 `/standby_status` 查看状态
- 面板接口：`GET /api/admin/power`（状态）、`POST /api/admin/standby`、`POST /api/admin/resume`、`POST /api/admin/reboot`、`POST /api/admin/standby/onebot {enabled}`；`/api/overview` 的状态字段由 `frozen` 改为 `standby`
- 与 `/sleep` 的区别：睡眠只影响群聊且会被 @ 唤醒；待机是整机级状态，bot 运行时不存在

### 远程管理

- 插件配置里的 `allow_remote_manage = false` 时，非本机来源只能查看，不能改配置、编辑 `.env`、管理插件或重启
- 面板默认对网络开放，公网使用建议经 HTTPS 反向代理访问，并在确认 HTTPS 生效后把插件配置里的 `secure_cookies` 设为 `true`
- 仅当可信反向代理正确覆盖客户端地址头时才开启 `trust_proxy_headers`
- 经反向代理访问时请让代理同时透传 Host 与客户端地址头：
  `proxy_set_header Host $host;`、`proxy_set_header X-Forwarded-Host $host;`、
  `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`，并开启
  `trust_proxy_headers = true`。登录/首次设置密码会校验 Origin 与 Host 同源，
  代理不改写 Host 也不透传 `X-Forwarded-Host` 时会返回 403（这是防 CSRF 的
  必要约束，不是 bug）；来源判定取 `X-Forwarded-For` 的**最右**一项，
  因此不要在代理上丢弃客户端地址头

## 配置（`plugins_data/dashboard/config.toml`）

配置不在本体 `config.toml` 里，而是插件自己的配置文件；面板「插件 → dashboard → 配置」可表单/TOML 编辑，
也可以直接改文件后重载插件（改监听地址/端口需要重启 NeoBot）。文件不存在时显示的是下面这些默认值：

```toml
host = "0.0.0.0"                      # 监听地址；127.0.0.1 仅本机
port = 9981                           # 监听端口；占用时最多向后尝试 10 个
base_path = ""                        # 访问路径前缀，如 "/neobot"；留空为根路径
manage_plugins = true                 # 是否允许在面板内管理插件
allow_remote_manage = true            # 是否允许非本机来源执行管理操作
session_timeout_minutes = 720         # 会话过期时间（分钟）
log_buffer_size = 500                 # 日志缓冲条数（保存即生效）
bot_info_cache_ttl = 300              # 机器人信息缓存秒数（保存即生效）
allow_archive_delete = false          # 是否允许在「档案」页删除档案（保存即生效）
history_max_days = 30                 # 消息统计历史保留天数（保存即生效）
login_max_failures = 5                # 限速窗口内允许的登录失败次数
login_rate_limit_window_seconds = 600 # 登录限速窗口（秒）
secure_cookies = false                # 仅通过 HTTPS 发送登录 Cookie
trust_proxy_headers = false           # 是否信任反向代理提供的客户端地址头

# ── 延迟探针（保存即生效）────────────────────────────────────────
latency_probe_interval_seconds = 60     # 有人看面板时的探测间隔；0 = 彻底关闭探针
latency_probe_idle_seconds = 0          # 无人在线时的间隔；0（默认）= 完全停止探测
latency_probe_active_window_seconds = 120  # 会话视为「有人在线」的活跃窗口（秒）
latency_probe_gate_check_seconds = 30   # 空闲期复检门控的间隔（不产生 API 调用）
```

**延迟探针的门控语义**：只有「最近 `latency_probe_active_window_seconds` 秒内活动过的面板会话」
存在时才探测；否则按 `latency_probe_idle_seconds` 处理（默认 0 = **完全不探测**）。
这使得「8 小时没人开面板」与「每 10 秒刷一次面板」的调用量彻底分开。

> 修复前探针是**无条件常驻**的：无论有没有人看面板，进程生命周期内每 15 秒发一次 `get_status`，
> 实测 5760 次/天、占报文日志行数 70.8%、约占 `neobot.log` 字节 39%，并且因为面板自己统计日志文本，
> 让「API 调用排行第一」变成探针自己（自证回路）。默认值下无人看面板时调用量为 **0**。
>
> 空闲期探针**不会退出循环**（只做廉价的门控复检）：任务只在 `load()` 创建一次，而面板
> 声明 `hot_reload=False`、`load()` 不会重跑，一旦退出就永久停摆、再也无法恢复。

**插件配置的「保存即生效」**：面板插件可声明自己哪些配置项属于运行期安全
（`PluginControlFacade.register_config_consumer`，见 [07-插件开发](../07-插件开发.md)）。
面板保存时只把这类字段原地喂给插件——**不重载插件本体**（整插件重载会关闭 HTTP 服务、
切断当前保存请求、并丢掉全部内存指标）。dashboard 自己声明的运行期安全字段：
`latency_probe_*`、`bot_info_cache_ttl`、`log_buffer_size`、`history_max_days`、`allow_archive_delete`；
`host` / `port` / `base_path` 与安全类字段仍提示「需要重启 NeoBot」。未声明消费者的插件行为完全不变。

> 旧版本把面板配置写在本体 `config.toml` 的 `[dashboard]` 分区（更早是 `[console]`）：
> 升级后首次启动会自动搬到 `plugins_data/dashboard/config.toml`，
> `enabled = false` 会转成 `plugin_state.json` 的停用记录。
> 是否启用不在这里配置：默认启用，只由 `plugin_state.json` 的独立记录决定。

## 安全

- **密码认证**：密码经 PBKDF2-HMAC-SHA256 + 随机盐保存（`plugins_data/dashboard/auth.json`，0600），未设置密码时禁止外网访问
- **会话**：内存态，绑定密码版本号；重启或改密码即失效
- **CSRF**：写操作必须携带与会话绑定的 CSRF 令牌（前端自动带）
- **登录限速**：[security.py](../../app/src/neobot_app/builtin_plugins/dashboard/security.py) 的 `LoginLimiter` 按 IP 统计失败次数并临时锁定
- **密钥只写不读**：面板**不返回**任何明文或掩码片段；`.env` 与插件配置文件的敏感字段只暴露「已设置 / 未设置」，保存时留空或提交占位符即视为不修改（只能覆盖更新）。含密钥的插件配置同时禁用源码模式，避免绕过脱敏。接口与日志输出另经 `redact` 兜底
- **防火墙**：`neobot firewall-open` 为面板端口添加 Windows 防火墙入站放行规则（需管理员权限，默认同时放行 9981）；外部无法连接时还要放行操作系统与云平台防火墙中的实际端口

### 禁止抓取与搜索收录

面板默认向所有爬虫声明禁止抓取和索引。后端所有 HTTP 响应（含登录页、API、静态文件、错误响应与插件 HTTP 扩展）统一携带：

```http
X-Robots-Tag: noindex, nofollow, nosnippet, noimageindex
```

前端入口的 robots meta 使用相同指令，静态构建也会携带 `robots.txt`；独立部署静态文件时仍需由对应 Web 服务器保留这些声明。

根路径 `/robots.txt` 和配置的 `base_path` 下同名路径（如 `/neobot/robots.txt`）均支持未登录的 GET / HEAD 请求，返回：

```text
User-agent: *
Disallow: /
```

反向代理部署时，应确保域名根路径 `/robots.txt` 仍能访问这份规则；仅开放 `/neobot/robots.txt` 不足以让标准爬虫发现它。根规则会禁止抓取同一域名下的全部路径；若该域名还承载需要被收录的公开网站，应为面板使用独立域名。

这些声明约束遵守规则的爬虫，**不能阻止忽略规则的程序，也不替代密码、会话和 CSRF 保护**；面板不会仅凭 User-Agent 拦截请求。禁止抓取后，搜索引擎也可能无法读取页面上的 `noindex` 声明，因此不保证已收录 URL 立即移除。依据：[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)、[Google 的 robots 与 X-Robots-Tag 说明](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag#combining-robots.txt-rules-with-indexing-and-serving-rules)。

## 快捷部署（`/deploy`）

页面按身份、人设、供应商、管理员、连接五步组织，可直接点步骤或使用上一步 / 下一步。每次只显示当前步骤，切步保留未保存内容；顶部显示配置进度，底部统一「保存并应用」。选填项不影响必填配置完成状态。

**必填**（4 项）：

1. **机器人身份**：机器人 QQ 号与昵称。出厂配置里 `bot.account = 0`、昵称是示例值 ——
   这些**占位值不算配好**（后端拿 schema 默认值现算比对，不写死字面量），字段里会提示「出厂占位」。
   别名选填（多个用「、」分隔）。
2. **人设**：写进 `bot.bot_data`，插进系统提示词（占位符 `{bot_data}`）。
   出厂那段只是示例文案，请替换成自己的；想改提示词模板去「提示词」页。
3. **平台密钥**：填 `DeepSeek_APIKey`（默认模型库全部走 DeepSeek，所以只填这一个就能对话）。
   走 `POST /api/config/env`，保存后立即重建 provider。
4. **OneBot 连接（给 NapCat 用）**：NeoBot 作为**反向 WebSocket 服务端**监听，由 NapCat 主动连过来，
   所以这里给出可直接抄走的两样（详见 [08-部署说明 §4.2](../08-部署说明.md)）：
   - **地址**：同机 `ws://127.0.0.1:<port>`、局域网 `ws://<本机局域网地址>:<port>`
     （监听 `0.0.0.0` 时两者分开给——`0.0.0.0` 是连不上的）
   - **Access Token**：一键生成（`POST /api/deploy/onebot-token`），与 NapCat 反向 WS 里填同一个值
   - 路径由 NapCat 侧自己配，服务端不限制（本仓库文档用 `/onebot`）
   - 未配 token 却对外监听时，页面会显示安全告警（同网段任何主机都能注入伪造事件）
   - 「自动连接」是**预留接口**：装了 NapCat Desktop 后由它直接创建连接，当前显示不可用 + 原因

**保存行为（避免草稿丢失）**：

- 「保存密钥」/「生成 token」只刷新页面状态，**不会覆盖**身份、人设、超管、回复意愿等还没点「保存并重载」的输入。
- 身份/人设/超管/回复意愿由第 4 张卡片底部「保存并重载」统一写入 `bot` / `chat`，成功后按服务端值回填。
- API Key 是只写不读：保存后输入框会清空、页面步骤打勾，属预期行为；需要更换时重新输入即可。
- **切页面/刷新不丢未保存输入**：身份、人设、别名、超管、回复意愿会按标签页存在 `sessionStorage`；切到配置编辑页再回来会自动恢复并提示，可点「放弃草稿」丢弃。保存并重载成功后清除草稿。API Key 不写入浏览器存储。

**选填**：

- **超级管理员 QQ**：用于接收余额不足等系统通知；留空也能正常跑，只是收不到通知。
- **群聊回复意愿系数**：约等于回复概率，具体概率受聊天流场景浮动（有人 @ 你、话题相关时更高）。
  默认 0.3；填 0 表示不主动回复。

**保存策略**：身份 / 别名 / 人设 / 超管 / 意愿走 `POST /api/config`，先读当前配置，再只把实际修改的字段合并进完整文档，保留其它字段与未改动的管理员列表。密钥单独写入环境配置，成功后清空输入框；若配置成功但密钥失败，保留密钥供重试，不重复提交已保存配置。刷新进度、切换步骤和生成 OneBot token 均不会覆盖表单草稿。

**默认范围**：所有聊天流（群聊 / 私聊）都可回复；要限定范围去「配置管理 → chat」。

端口与监听地址仍在「配置管理 → adapter」里改（`reverse_ws_port` / `reverse_ws_host` /
`reverse_ws_access_token`，也可用环境变量 `NEO_BOT_ADAPTER_PORT` / `NEO_BOT_ADAPTER_HOST` /
`NEO_BOT_ADAPTER_TOKEN`）。生成 token 后会尝试热重载 adapter（AdapterSupervisor 的路径）；
重载入口不可用时如实提示需重启进程。
