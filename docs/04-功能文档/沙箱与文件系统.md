# 沙箱与文件系统

NeoBot 为 Agent 的文件操作提供**沙箱**：Agent 只能在其工作目录内读写文件，配合容量限制、临时文件清理与 SSRF 防护，控制 Agent 行为的风险面。

## 沙箱（`agent.sandbox` 配置）

```toml
[agent.sandbox]
enabled = true
max_total_size_bytes = 2147483648   # 沙箱总容量上限（默认 2GB），写入前检查，超出拒绝
temp_max_age_seconds = 1800         # 临时文件最大存活秒数（30 分钟）
temp_hold_max_minutes = 120         # 临时文件保活最大分钟数（2 小时）
scan_interval_seconds = 300         # 临时文件清理扫描间隔（5 分钟）
allowed_read_dirs = ["./data/emoji/", "./data/creator/gallery/"]  # 文件操作 Agent 可只读访问的目录
```

### 持久化文件定时维护（`agent.sandbox.maintenance`）

- `enabled`（默认 true）+ `interval_seconds`（默认 10800，3 小时）：定期维护沙箱持久化文件
- **调度以数据库记录为准**：每次维护（含跳过）都写入 `maintenance_runs` 表
  （`started_at / finished_at / status / trigger / tool_calls / summary / error / skipped_reason`）。
  进程启动时按「距上次成功维护是否已到 `interval_seconds`」判断：
  - 未到期 → 跳过并记录一条 `skipped`（含原因），不调用模型；
  - 上次状态是 `failed` 或 `running`（进程被中断）→ 立即补跑一次；
  - 到期 → 正常执行。
  这样重启进程不再无条件触发一次沙箱维护（此前每次重启都会在 60 秒后跑一整轮，
  生产实测两次重启各触发一次无意义维护）。
- **工具按需加载**：维护 Agent 只常驻 `archive` / `file_storage` / `sandbox_maintenance` /
  `sandbox_manager` 四个技能（27 个工具 / 约 1.2 万字符），其余技能用
  `skills__load_tools` 按需加载。此前每次都内联全部 173 个工具 / 7.1 万字符，
  而一次维护要发 16~23 次模型调用（见 `app/src/neobot_app/skills/agent_toolset.py`）。

### 相关 Skill

- `sandbox_manager`：沙箱管理（查看/删除等）
- `sandbox_maintenance`：沙箱持久化维护
- `file_storage`：文件存储读写

### 运行时组件（`app/src/neobot_app/runtime/`）

- [sandbox_service.py](../../app/src/neobot_app/runtime/sandbox_service.py)：沙箱核心服务（路径校验、容量检查）
- [sandbox_lock.py](../../app/src/neobot_app/runtime/sandbox_lock.py)：沙箱并发锁
- [sandbox_maintenance.py](../../app/src/neobot_app/runtime/sandbox_maintenance.py)：持久化文件定时维护

## 文件操作 Agent（`agent.file_operation`）

- `enabled`（默认 true）：是否启用文件操作 Agent
- `agent.system.allowed_work_dirs`（默认 `["./Data/"]`）：System Agent 允许操作的工作目录

文件操作 Agent 负责按主 Agent 的指示在沙箱内读写文件、处理文档（依赖 pypdf、python-docx、openpyxl、xlsxwriter、pikepdf 等）。

## 图片引用加载器的信任边界（设计特性）

`image_parse` 的引用加载器 [`skills/image_parse_skill.py`](../../app/src/neobot_app/skills/image_parse_skill.py)
（`_read_image_ref`，模块内第 34-69 行）**有意同时支持**四类来源：`base64://`、`data:` URL、
**本地路径（含 `file://` 与裸绝对路径）**、以及 `http(s)://` URL。本地路径与 URL 是刻意保留的能力，
不算沙箱越权：

| 输入形态 | 行为 | 说明 |
|---|---|---|
| `base64://…` | 直接解码 | 无外部访问 |
| `data:image/…;base64,…` | 直接解码 | 无外部访问 |
| `file://<绝对路径>` | 直读该文件字节 | POSIX 下 `file:///etc/passwd` 即 `/etc/passwd` |
| 裸绝对/相对路径 | 若存在且是文件则直读 | 不做沙箱解析 |
| `http(s)://…` | 交给 `image_http_client` 抓取 | 跟随重定向；无 host 白名单、无响应体大小上限 |

```text
信任边界（必须按部署环境理解）：
- 该加载器读的是 **bot 进程可读的任意本地文件**，以及 **bot 能访问的任意 URL**，
  不经过 sandbox_service 的路径白名单与容量检查（sandbox 约束的是文件操作 Agent 的读写路径）。
- 调用参数由模型生成，而模型受群聊等不可信文本影响，因此实际链路是
  「不可信文本 → 提示注入 → 工具调用 → 本地文件读取 / 出网请求」。
- 读到的字节会作为图片送入视觉模型服务（可能外泄），并可能出现在工具返回或日志里。
```

**部署方需要承担的选择**：画像/图库/表情包等本地图片、以及公网图片 URL 是这套加载器的正常用例，
删掉本地路径分支会让这些功能失效；因此当前把它作为**能力**保留，由部署方决定是否：
① 把 bot 进程的可读面限制到运行账号应有的最小集合（专用账号/容器挂载/文件权限）；
② 在反向代理或出口防火墙上限制 bot 的出网目标，阻断私网/环回地址；
③ 需要更强隔离时，改为只允许"沙箱内文件 + 显式白名单只读目录"，并为此调整相关 Skill 的取图路径。

> 与 §SSRF 防护的分工：`utils/ssrf.py` 的 `validate_public_url` 用于浏览器/网页类工具；
> 上述图片加载器当前**未接入**该校验，属已知边界而非缺陷（见 `bugfixes/fix(12)-release-scan-unfixed-findings` 的范围说明）。

## SSRF 防护

[`app/src/neobot_app/utils/ssrf.py`](../../app/src/neobot_app/utils/ssrf.py) 提供 SSRF（服务端请求伪造）防护，用于浏览器/网络请求相关功能，防止 Agent 请求内网地址。

## 安全设计要点

1. **路径限制**：所有文件操作必须落在沙箱根目录内
2. **容量上限**：写入前检查总容量，超出拒绝（默认 2GB）
3. **临时文件自清理**：过期自动删除（30 分钟/2 小时）
4. **只读目录白名单**：`allowed_read_dirs` 控制 Agent 可读取的系统目录
5. **并发锁**：沙箱操作串行化，避免竞态
6. **边界例外**：沙箱约束的是**文件操作 Agent** 的读写路径；`image_parse` 的图片引用加载器按设计可读任意本地路径与 URL，见上文「图片引用加载器的信任边界」
