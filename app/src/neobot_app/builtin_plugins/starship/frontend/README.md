# 亚顿之矛 / Spear of Adun

## 运行

启用 NeoBot 的 dashboard 与 starship 插件，在面板同一端口打开 `/game/`（也支持配置的自定义前缀）。真实会话检查通过后直接渲染三维舰桥，不经过二维登舰页。首次点击舰桥接管鼠标；M 打开场景内实体操作仪。未打开插件页面不创建渲染器或轮询。

```sh
pnpm install
pnpm typecheck
pnpm test
pnpm build
```

构建输出 `../web/`，随插件分发；更新后刷新游戏页面。无需另起前端服务。

## 尺度与造型

以实际原作图为参考：舰首矛头 → 长型镂空中殿 → 宽厚带孔装甲翼与桥接冠架，中央保留真实负空间和椭圆灵能核心。独立外壳按实际米制缩放到 **74,400 × 17,204 × 9,139 m**，而舰桥、人物和机械仍是米制原尺寸，绝非只修改尺寸文字。

长度采用《StarCraft Field Manual》经 [StarCraft Wiki](https://starcraft.fandom.com/wiki/Spear_of_Adun) 引用的74.4公里；宽高是同来源对比图推算值，不当作同精度官方参数。原始资料/玩家资料存在约74–74.5公里的不同表述，本工程以74.4公里为明确标尺。模型是程序化风格重建，不包含游戏原版模型或贴图，不声称一比一资产复刻。

舰外总览和「舰桥外侧尺度」提供远近两种观察位置，另有动态凤凰编队与虚空辉光舰作尺度参照（展示长度约58–70m／310–355m，不冒称官方舰型尺寸）。外壳真实尺寸、通道连接与碰撞写入自动测试。渲染使用对数深度与200万米远裁面；太空天体位于数百公里外。

## 本次开放范围

- **星穹舰桥**：玻璃/灵能护盾、雕刻式拱骨、装甲地砖、星图仪和指挥装置。
- **战争机械装配车间**：不朽者与追猎者工位，按原作双炮重甲／紫色高壳四刃足区分，配套机械臂与分段加工台。
- **机器人装配车间**：龙骑士与巨像装配工位；低宽穹甲四足底盘与高悬长腿机体形成明确尺度差。巨像有独立的大型装配台。

- **太阳核心室**：按暴雪实际舱内画面重建的分瓣金属约束壳、三蓝色能量口、叉状支座和厚弧肋；太阳核心是亚顿之矛的供能中枢，不是裸蓝球或普通反应堆。
- **记忆资料室**：配置与日志设备、水晶档案、阅读岛、雕刻壁框和拱撑。

五个主要舱室以真实地板、通道与8组感应滑门连通。其余舰体仍不可进入，最终后界在z118；远征机库等仅预留。战斗单位是展示模型，不是生产模拟系统。

## 全三维交互

所有正常游戏中的可见菜单、命名、确认和状态仪表均由 Three.js 网格渲染；DOM 仅承担不可见中文IME输入及加载/鉴权失败时的必要提示。

六类已适配实体业务设备：

| 设备 | 实体操作 |
| --- | --- |
| 星图仪 | 航点选择、快捷航点、跃迁启动 |
| 指挥核心 | 监控切换、刷新、待机/恢复与重启确认 |
| 机器人中枢 | 机器人选择、连接/消息/平台/延迟状态 |
| 插件装配矩阵 | 模块选择、启停、重载、依赖状态 |
| 系统仪表 | CPU、内存、磁盘、任务与服务切换 |
| 能源仪表 | 真实调用、Token、费用与模块选择 |

终端按用途区分星图盆、指挥冠架、动力棱柱、通讯双翼、模块槽和遥测圆仪。按钮参照原作命令格，使用小切角矩形、深蓝凹槽、多层金属框与选中金边，不再是叶形或大六角。整个可见标签属于同一真实射线点击面；聚焦时标题、按钮和读数不被装饰遮挡。复杂配置、日志、分析与演练使用展开的世界空间投影屏，按真实平面/FOV/视口计算焦点。离线设备可只读观察，但不启动轮询或API操作。危险写操作继续保留权限、确认及防重复提交。

WASD移动，鼠标看方向，空格跳跃，Shift潜行，Ctrl疾跑；E使用/离开设备，M操作仪，1/2/3前往开放区域，V舰外总览。舰外鼠标拖动环绕、滚轮缩放。实体操作仪支持鼠标射线点击与Tab/Enter/Esc。

默认舰名为“亚顿之矛”。操作仪「命名战舰」可修改1–24个Unicode字符的舰名，与舰长名独立；仅持久化到当前浏览器。禁用存储时在本次页面内保留。

## 原作美术对照

参考记录见 `ART_DIRECTION.md`、`VISUAL_AUDIT_V3.md` 与最新 `RECONSTRUCTION_V4.md`。舰桥改为单一连续椭球弧罩，前窗/侧窗/顶面没有方盒接角；保留蓝色边缘光、能量网格和波纹。外壳在真实人居空间处局部开腔，周围有闭合航线的动态黄金舰队，四推进口有持续渐隐尾焰。原作参考图片只用于查阅，未打包为游戏资产。

## 架构 / 未来舰型

- `world/registry.ts`：舰型注册表及建造器接口；未来泰伦战列巡航舰须提供自己的外壳、房间、碰撞与交互锚点。当前仅注册灵能方舟，未实现舰型不会显示假切换按钮。
- `world/style.ts`：材质配色、实体仪表视觉主题。
- `world/scale.ts`：真实尺度常量。
- `world/hull.ts`：归一化外壳与米制内舱安装点。
- `world/ship.ts`、`deckplan.ts`：开放空间、碰撞与能力锚点。
- `world/foundry.ts`：四类装配工位与碰撞；`protoss-walkers.ts`、`protoss-heavy.ts`：按原作图重建的四单位模型；`foundry-architecture.ts`：多层铸造圣殿。静态几何按材质合批。
- `terminals/physical.ts`：真实业务实体控制设备，其他终端保持兼容。
- `core/hud.ts`：三维操作仪、铭文输入和确认；`ui/textinput.ts`只负责隐藏输入捕获。
- `core/rendering.ts`：PBR反射环境、材质渲染、抗锯齿与受控辉光。

新舰型不得直接把现有方舟换色冒充不同舰体。新增可进入区域必须同时声明几何、碰撞、通路和安全站位；保持玩家与物理装置的真实比例。

## 精确碰撞

控制台按实际实体网格注册，投影和文字不当实体；圆台、斜支架、四足机体使用解析圆柱/OBB或静态三角BVH，不再用整物体大方盒。门叶碰撞随动画实时移动，终端交互检查可见正面和视线遮挡。站立、蹲伏、落地、腿间空隙与闭合网格内部占据均有回归。静态索引只在注册时构建；场景释放同时清除缓存。

## 验证

`pnpm test`额外检查四类单位的接地、展示比例、平台适配与合批预算；同时覆盖真实外壳三轴尺寸、连续步行/封存边界、控制台前方净空、舰型注册、Unicode舰名与存储异常、IME提交、危险确认默认取消、实际Three.js射线按钮和无可见DOM面板。后端契约另运行仓库测试 `app/tests/modules/test_starship_plugin.py`。真实服务的重启/停用等破坏性操作不在浏览器验收中自动执行。
