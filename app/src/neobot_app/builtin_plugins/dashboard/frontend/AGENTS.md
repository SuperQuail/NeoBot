# Dashboard frontend

本文件只补充前端维护约定；仓库根 AGENTS.md 的提交、验证与数据规则继续适用。

## 修改前

- 先读 README.md、ARCHITECTURE.md、DESIGN.md；确认所属领域、状态归属和样式 owner。
- 保留当前已确认的 UI、接口语义、草稿、权限与恢复路径。重构按职责拆分，不按行数切碎文件。

## 代码边界

- 业务页面目录只登记在 `src/app/routes.ts`；不要另建导航、名称、滚动或骨架映射。
- 鉴权使用 `auth/AuthContext`，通知使用 `notifications/infoBar`；不得反向导入 `App` 或恢复旧 Toast 入口。
- 运行时实现直接导入，纯类型通过 `api/types.ts` 导出；契约领域之间使用 `import type`，不得引入页面依赖。
- 服务端状态使用 query 层和共享 key；写操作复用 client 的会话/CSRF/401 处理。
- 纯展示子组件不自行发请求。异步编排保留过期请求保护、busy、防重复写入、部分成功和冲突恢复。
- 控件、通知、编辑器和动效优先复用已有能力。只读、快捷键、恢复默认和菜单操作遵守相同权限判定。

## UI 与样式

- 使用 Lucide SVG，不添加 emoji、外部字体请求或页面专属主题。
- 全局 CSS 只在 main.tsx 引入；新增业务规则归到对应 owner，同步 DESIGN 的职责表。
- 不用隐藏溢出来掩盖布局问题；保持单屏总览、工作区与普通页的滚动契约。
- 结果用 InfoBar，阻塞读取或字段错误才原位显示；不要为通知新增提示卡或改变编辑区高度。
- 动效遵守减少动态效果偏好，卸载时清理，不重挂编辑器或动画旧的可写页面。

## 验证与交付

- 聚焦测试验证真实行为和恢复分支，不削弱断言、跳过失败或放宽门禁。
- 整理完成后运行 `pnpm run verify`，并保留重建的 `web/`。
- 不手工编辑产物，不格式化仓库内无关 Python 文件，不修改版本号或 Python 锁文件。
- 页面交互验证用隔离夹具覆盖正常、长内容、空态、只读与明暗/手机布局。记录数据来源，不能用演示结果代替真实实例验收。
- 功能和配置变化同步仓库文档；开发边界变化同步 ARCHITECTURE，视觉或滚动变化同步 DESIGN。
